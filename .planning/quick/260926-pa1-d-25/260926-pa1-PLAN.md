Purpose: 제품 목표 "방해되면 즉시 끌 수 있다"(SAFE-04)가 설정 손상이라는 경계 상태에서도 참이 되게 한다. 01-VERIFICATION.md의 deferred 항목(D-25)을 닫는다.
Output: 꺼짐 표시 키·스키마, 저장자 분기, 콘텐츠 스크립트·팝업 반영, 단위 시험 파일 1개(새로 만듦), lifecycle e2e 새 시험 2개와 기존 시험 2개 기대 변경.

**켜기 동작 결정과 근거 (planning_context 요구 사항):** 설정이 여전히 깨져 있을 때 '도우미 켜기'는 원본 보호로 거절하지 않는다. 꺼짐 표시만 지우고 `{ ok: true }`로 답한다. 새 사용자 결정은 필요 없다. 근거는 셋이다.
1. 잠긴 결정 D-25에 이미 "다시 켜면 표시만 지운다"가 들어 있다.
2. 설정이 깨진 상태에서도 콘텐츠 스크립트는 원래 기본 설정(enabled true)으로 돌고 있었다. 이 동작은 content.ts의 'settings' safeParse 실패 경로이고, 알림 문구도 "기본 설정으로 동작해요"다. 그래서 켜기는 끄기 전 상태로 돌아가는 것일 뿐이고, sync에는 쓰지 않으므로 지킬 원본이 위협받지 않는다.
3. 거절하면 두 결과 중 하나가 된다. 표시를 지운 채 거절하면 팝업은 '꺼짐'으로 되돌아가는데 실제 도우미는 켜진다(화면과 실제 불일치). 표시를 남긴 채 거절하면 그 PC에서는 다시 켤 방법이 없다.

**꺼짐 표시 수명 (Claude 재량, D-25 "우선 적용"에서 도출):** 다른 기기 동기화 등으로 sync 설정이 다시 멀쩡해져도 꺼짐 표시를 자동으로 지우지 않는다. 자동으로 지우면 이용자가 끈 도우미가 말없이 다시 켜진다. 표시는 이용자가 '도우미 켜기'를 누를 때만 사라진다. 설정이 멀쩡한 상태의 켜기는 sync enabled true를 쓴 다음 표시를 지운다.

**키 이름 (기존 컨벤션):** 기존 키는 'settings', 'site:<origin>', 'presses:<origin>', 'notice:migration-failed'처럼 '종류:이름' 꼴이고, 값은 D-30에 따라 `{ schemaVersion, data }`로 싼다. 이를 따라 `HELPER_OFF_KEY = 'override:helper-off'`, 값 `HelperOffV1 = { schemaVersion: 1, data: { at: number } }`로 한다. `at` 필드는 MigrationNoticeV1과 같은 모양이다.
