## Phase Boundary

설계 10-1 "만드는 순서" 5번: **작업판, 뒤에서 실행, 반복 패턴 알림**을 Phase 1·3·4 위에 더한다. 이용자가 틀을 뒤쪽 탭에서 돌리는 동안 다른 탭에서 계속 일하고, 열린 탭·자주 가는 곳·뒤에서 도는 틀의 진행·확인 대기를 **작업판 한 곳에서 번호로** 처리하며, 틀로 만들 만한 반복 입력을 도우미가 한 번 알려 준다.

요구사항: BORD-01~04, BG-01~03, PATN-01 (ROADMAP Phase 5, Mode: mvp).

설계 검토(CEO·디자인·엔지니어링)는 모두 끝났고, 설계의 모든 결정은 잠긴 결정이다(GSTACK REVIEW REPORT, "NO UNRESOLVED DECISIONS"). 다시 열지 않는다.

### 앞선 단계 의존 (이 계획은 미리 썼다)
이 계획은 Phase 1 실행 중(16개 중 12개 완료, 커밋 `f468b6e` 기준)에, Phase 3·4 계획을 다른 스레드가 **동시에** 쓰는 동안 미리 썼다. 실행 전에 아래가 끝났는지와 결과가 이 계획의 가정과 맞는지 확인하고, 다르면 이 계획을 먼저 맞춘다.
- **Phase 1 계획 13~16(실행 중):** 사이트별 끄기·"도울 수 없음" 아이콘 표시(배지 "없음"), 형식 버전 변환 실패 보호·동기화 항목 8KB·쓰기 합치기·분당 한도, 브라우저 확대와 상관없는 오버레이 크기, 서체·50ms·독립 DOM 감사. Phase 5의 배지·저장·오버레이는 이 결과 위에 쌓는다.
- **Phase 3(계획 미리 쓰는 중):** 명령판(0, 고정 카드 자리 — 첫 장 2번 "작업판"), 키 배치 설정(PERS-03), 모드 표시 문구, 한 곳의 민감칸 판별 함수(PRIV-01), 확인 화면 보호. Phase 5는 명령판 "작업판" 카드를 실제로 동작하게 하고, 민감칸 판별을 반복 패턴 세기에 그대로 쓴다.
- **Phase 4(계획 동시에 쓰는 중 — 가장 큰 의존):** 틀 저장소, 틀 실행기(단계 진행·속도·Esc 멈춤), `chrome.storage.session`의 실행 상태, 실행 잠금(같은 틀 두 번 실행 막기), 값 고르기 카드(TMPL-06), 제출 확인 화면(TMPL-09)과 제출 직전 `storage.local` "누름" 기록, "확인 필요"(TMPL-10·13), 알림 창 가로채기(TMPL-11), 막힘·"이 단계만 다시 기록"(TMPL-12), 틀 기록기(TMPL-01), 활동 기록(LOG-01). Phase 5가 가정하는 Phase 4의 모양은 D-24~D-27에 적었다. Phase 4 계획이 다르게 나오면 Phase 5 계획의 해당 부분을 먼저 고친다.

## Implementation Decisions

### 구조 (Phase 1·3 결정 이어받기)
- **D-01:** Phase 1의 구조를 그대로 쓴다: 모든 프레임에 content script, **작업판·확인 화면·모드 표시·"확인 대기" 칩은 맨 위 프레임이 모아서** 띄운다. 프레임끼리·탭끼리의 메시지는 service worker를 거친다(설계 4장, 엔지니어링 검토 1번). **탭·작업판 상태와 뒤에서 도는 틀의 조정은 service worker가 맡는다**(설계 4장 구조도 "탭·작업판 상태", "틀 저장소·실행기 조정").
- **D-02:** 도우미는 `isTrusted` 입력에만 반응하고, 입력 필터(떨림 걸러내기)가 가장 먼저 받는다. 작업판·확인 대기 처리 화면의 키 입력도 같은 필터를 거친다. 확인 대기 처리(제출 확인)에는 확인 화면 보호(뜬 뒤 1초 모든 입력 무시, Enter 또는 스페이스바 1초로 확인, Esc 취소)를 그대로 적용한다(설계 5장·8장, 엔지니어링 검토 4번).
- **D-03:** 모든 저장은 service worker 하나가 순서대로 한다(단일 저장자). 새로 저장하는 데이터에도 형식 버전을 붙이고, 형식 변환이 실패하면 원래 데이터를 그대로 두고 알린다. 동기화 항목은 한 항목 8KB·분당 쓰기 제한을 지킨다(설계 7장, 엔지니어링 검토 6번).
- **D-04:** 저장 위치(설계 7장 표): **자주 가는 곳 = `chrome.storage.sync`**(다른 PC에서도 같은 조작). 틀 실행 상태·확인 대기 = `chrome.storage.session`(service worker가 잠들었다 깨어나도 이어 감). 반복 패턴 세기·거절한 패턴 = `chrome.storage.local`(이 PC만, 값 없이). 서버로 보내는 것은 없다 — Phase 5에는 밖으로 나가는 요청이 없다(설계 8장).

### 작업판 (BORD-01~04)
- **D-05:** 작업판은 명령판 카드(첫 장 2번 "작업판" — 고정 자리, 디자인 검토 1번) 또는 단축키로 연다. 큰 번호 카드로 ① 열린 탭 ② 자주 가는 곳(이용자가 고정한 사이트) ③ 뒤에서 도는 틀의 진행 상황 ④ 확인 대기 목록을 보여 준다. 1~9로 고르고, 9개를 넘으면 다음 장으로 넘기며, Esc로 이전 장 또는 닫기(설계 6.9, SYSTEM.md 명령판·작업판 템플릿).
- **D-06:** 열린 탭은 번호로 **바로 이동**하고, **닫기**도 할 수 있다(BORD-01).
- **D-07:** 이용자가 자주 가는 사이트를 고정하고 작업판에서 번호로 이동한다(BORD-02). 고정 목록은 계정 동기화로 다른 PC에도 적용된다(D-04).
- **D-08:** 뒤에서 도는 틀마다 진행 상황을 보여 준다(BORD-03). 표시 형식은 SYSTEM.md 상태 표 "틀 실행 | 불러오는 중" 칸의 **단계 진행 막대 + "3/8 단계"**를 따른다.
- **D-09:** 확인 대기 목록의 항목을 번호로 불러와 처리한다: **값 고르기**(TMPL-06의 바뀌는 값 카드), **제출 확인**(TMPL-09의 큰 글씨 요약 + Enter/Esc)(BORD-04, 설계 6.8 "뒤에서 실행"). 제출은 이 확인 뒤에만, 한 번만 일어나고 절대 다시 시도하지 않는다(설계 8장).
- **D-10:** 확인 대기가 생기면 **확인 창을 바로 띄우지 않는다**(하던 입력을 끊지 않으려고). 대신 모드 표시 오른쪽에 "확인 대기 1" 칩(남색 테두리, 숫자 굵게)을 붙이고, 확장 아이콘에도 같은 숫자 배지를 단다(설계 6.9, SYSTEM.md 모드 표시, 디자인 검토 6번).
- **D-11:** 상태(SYSTEM.md 상태 표 "작업판·확인 대기" 줄): 비어 있음 = "기다리는 일이 없어요", 실패 = 뒤 탭이 닫힘·로그아웃: 카드에 이유, 성공 = 카드 목록. 불러오는 중 표시는 없다(—). 그 밖의 상태는 상태 표 원칙(한 문장 + 다음 행동 카드, 0.3초 안에 끝나면 표시 안 함)을 따른다.

### 뒤에서 실행 (BG-01~03)
- **D-12:** 이용자가 틀을 뒤쪽 탭에서 돌리는 동안 다른 탭에서 계속 일할 수 있다. 이용자가 해야 할 일(값 고르기, 제출 확인)이 생기면 작업판의 "확인 대기"에 쌓인다(BG-01, 설계 6.8).
- **D-13:** **숨은 탭에서의 실행 속도를 측정하고 결과를 기록한다**(설계 11장 ③, ROADMAP 성공 기준 2). 브라우저는 뒤쪽 탭의 타이머를 늦추므로(숨은 탭 타이머 최소 1초, 오래 숨으면 더 느려짐), 뒤에서 도는 실행은 content script의 `setTimeout` 사슬에 기대지 않고 **service worker 조정 + DOM 이벤트(MutationObserver)** 로 진행한다(연구 STACK.md·PITFALLS.md).
- **D-14:** 뒤에서 도는 탭이 **닫히거나 로그아웃되면** 그 틀을 멈추고 작업판에 이유를 표시한다(BG-02, 설계 9장). 멈출 때 제출 단계에 "누름" 기록만 있고 결과가 없으면 다시 누르지 않고 "확인 필요"로 둔다(설계 4장·9장, Phase 4 TMPL-13과 같은 규칙).
- **D-15:** 틀마다 이미지·광고 차단을 켜고 끌 수 있다. 켜면 **그 틀을 실행하는 탭에서만** 이미지·광고 요청을 막는다(BG-03, 설계 6.8). 방식은 `declarativeNetRequest` **세션 규칙 + `tabIds` 조건**(전역 규칙 금지)이다(연구 ARCHITECTURE.md·PITFALLS.md). 틀이 끝나거나 멈추거나 탭이 닫히면 규칙을 걷어 낸다.
- **D-16:** `declarativeNetRequest` 계열 권한은 Phase 1 권한(storage·scripting·tabs, host `<all_urls>`)에 없는 **새 권한**이다. 저장소 규칙(새 권한·새 의존성은 이유 한 줄 + 승인)과 설계 11장 ⑤의 선례("새 권한이라 만들 때 승인받는다")대로, **만들 때 이용자 승인을 받은 뒤에만** manifest에 넣는다. `debugger`·`webNavigation`·`contentSettings`는 이 단계에서도 넣지 않는다(Phase 1 D-13). 이용자가 2026-09-24 프로젝트 대화에서 "declarativeNetRequestWithHostAccess 허용"이라고 답해 `declarativeNetRequestWithHostAccess`를 승인했고(일반 `declarativeNetRequest`는 승인하지 않음), 05-08의 manifest 변경은 더 이상 질문을 기다리지 않는다.

### 반복 패턴 알림 (PATN-01)
- **D-17:** 같은 사이트의 같은 입력칸 묶음에 **틀 없이 3번 이상** 입력하면 "이걸 틀로 저장할까요?"를 **한 번** 묻고, 거절하면 그 패턴은 **다시 묻지 않는다**(설계 6.8, AI 없음).
- **D-18:** 세기는 입력칸의 **정체(사이트 + 칸 묶음의 식별)만** 쓰고 **입력한 값은 쓰지도 저장하지도 않는다**. 민감칸은 Phase 3의 한 곳 판별 함수로 걸러 묶음 식별에서 뺀다(설계 6.13·8장, PRIV-01). 틀 실행 중 입력과 틀 기록 중 입력은 세지 않는다("틀 없이").
- **D-19:** 묻는 방식도 하던 입력을 끊지 않는다(D-10과 같은 원칙). 질문 문구는 카피 규칙대로 "이걸 틀로 저장할까요?"(SYSTEM.md 카피 규칙 "…할까요?").

### 화면(오버레이)
- **D-20:** 모든 오버레이는 `docs/design/SYSTEM.md`(안 A 등대)와 `docs/design/tokens.css`만 따른다: Shadow DOM 안, 가운데 큰 카드 격자(3열, 카드 사이 16px), 카드 radius 12·선택 시 남색 3px, 누르는 대상 높이 56px 이상, 번호 카드 = 큰 숫자(22px, 700) + 이름, 모든 버튼에 누를 키 칩, 막힘·확인 필요 = `--warning` 테두리 카드 + 이유 + 번호 선택지, 새 색·서체·radius·그림자 금지(디자인 검토, DESIGN.md §4).
- **D-21:** SYSTEM.md에는 작업판이 "명령판·작업판 (가운데 큰 카드 격자)"로만 있고 네 구획(탭·자주 가는 곳·진행·확인 대기)의 배치는 없다. DESIGN.md §4-1대로 **먼저 SYSTEM.md에 작업판 템플릿을 더한 뒤** 만든다. 기존 토큰만 쓴다.
- **D-22:** 카피 규칙(SYSTEM.md): 질문 "…할까요?", 알림 "…했어요", 오류 "원인. 다음 행동.", 버튼은 실제 동작 단어(사이트 버튼 이름 그대로 — "상신"), 같은 행동은 어디서나 같은 단어, 키 이름은 영어(`Enter`, `Esc`)·스페이스바만 한글.
- **D-23:** 크기는 브라우저 확대와 상관없이 고정(디자인 검토 5번, Phase 1 계획 15)이고 컨디션 모드의 "표시 크기"로만 바뀐다. `prefers-reduced-motion`이면 나타남은 즉시(SYSTEM.md 모션).

### Phase 4에 대한 가정 (동시에 계획 중 — 다르면 이 계획을 고친다)
- **D-24:** 틀 실행 한 건의 상태(어느 틀, 실행 탭, 몇 번째 단계/전체 단계, 받은 값, 상태: 도는 중·값 기다림·제출 확인 기다림·막힘·확인 필요·끝남·멈춤)가 **단계마다 `chrome.storage.session`에** 적힌다(설계 4장). Phase 5의 진행 표시·확인 대기는 이 기록을 읽어 만들고, 따로 복사본을 두지 않는다.
- **D-25:** 틀 실행기는 값 고르기·제출 확인이 필요할 때 **멈춰서 service worker의 답을 기다리는 모양**이고, 답(고른 값, 확인·취소)은 확장 내부 통로(service worker)로 받는다. Phase 4가 이 화면들을 실행 탭 안의 화면으로만 만들면, Phase 5가 "다른 탭에서 처리한 답을 실행 탭에 넘기는" 길을 더한다.
- **D-26:** 실행 잠금(같은 틀 두 번 실행 막기)과 "이미 도는 틀을 다시 고르면 작업판의 진행 상황으로 안내"(설계 6.8)에서, Phase 4는 안내만 하고 **작업판으로 여는 부분은 Phase 5가 잇는다**.
- **D-27:** 활동 기록(LOG-01)에 쓰는 한 곳의 함수가 있다. Phase 5의 멈춤 이유(탭 닫힘·로그아웃), 확인 대기 처리, 반복 패턴 질문·거절도 입력한 값 없이 여기에 남긴다(설계 6.13).

### 시험
- **D-28:** 모든 기능은 로컬 연습 사이트에서 먼저 시험한다. Phase 5용으로 연습 사이트에 **로그인·로그아웃을 흉내 내는 페이지**, **이미지와 "광고" 요청이 섞인 페이지**, **틀 없이 여러 번 채울 양식**을 더한다(설계 10장).
- **D-29:** 단위 시험(설계 10장이 이름으로 든 것): **반복 패턴 세기**. 확장을 띄운 브라우저 시험(Chromium, `CI=true`): 작업판 열기·탭 이동·닫기·자주 가는 곳, 뒤쪽 탭 실행 중 진행 표시와 확인 대기 처리(값 고르기·제출 확인), 뒤 탭 닫힘·로그아웃 → 멈춤 + 이유, 차단은 실행 탭에서만, 확인 대기 칩·배지, 반복 패턴 한 번 묻기·거절 뒤 다시 안 묻기, **숨은 탭 실행 속도 측정 기록**. 엣지·웨일은 수동 확인 목록(Phase 1 D-29).
- **D-30:** UI 완료 판정은 저장소 규칙대로: 싼 게이트(lint·typecheck·build) → 별도 에이전트의 독립 DOM 감사(`CI=true`, 스크린샷 육안 금지) → 수정 → 전체 게이트 한 번(CLAUDE.md).

### Claude's Discretion
- 작업판 단축키의 기본 키(키 배치는 모두 바꿀 수 있다 — Phase 3 PERS-03)와, 명령판 없이도 열리게 할지(`chrome.commands` 같은 브라우저 단축키는 권한이 필요 없다). 단, 입력칸 안에서 글자 입력을 가로채지 않는다.
- 도우미가 뜰 수 없는 페이지(새 탭 `chrome://newtab`, 설정 화면, 웹스토어)에서 작업판을 어떻게 열지(확장 아이콘 메뉴나 확장 자체 페이지 등). 상태 표의 "도울 수 없음" 원칙을 지킨다.
- 네 구획을 한 장에 나눌지 구획마다 장을 둘지, 번호를 어떻게 매길지(1~9 + 다음 장 원칙 안에서) — D-21의 SYSTEM.md 템플릿으로 정한다.
- 탭 **닫기**를 떨림으로 잘못 누르지 않게 하는 방법(예: 카드를 고른 뒤 "닫기"를 한 번 더 고르기). 틀이 도는 탭을 닫으려 하면 먼저 묻는다.
- 열린 탭을 지금 창만 보일지 모든 창을 보일지, 순서(최근 쓴 순서 등).
- 자주 가는 곳을 고정·풀기하는 방법과 개수 한도, 동기화 항목 나누기(8KB 안에서).
- 확인 대기 항목을 "불러와 처리"할 때 **지금 탭 위에서 처리할지, 그 틀의 탭으로 옮겨 가서 처리할지**. 기본 방향: 이용자가 하던 탭을 떠나지 않게 **지금 탭 위에서 처리**하고, 실제 누르기는 실행 탭에서 한다(BG-01의 목적). 어느 쪽이든 확인 화면 보호·한 번만 제출은 같다.
- 뒤에서 실행을 시작하는 방법(틀 실행 때 "뒤에서 실행"을 고르면 새 탭을 뒤에 열기, 또는 실행 중 다른 탭으로 옮기면 그대로 뒤에서 계속 등).
- 뒤쪽 탭이 브라우저에 의해 버려지지(discard) 않게 막을지와 방법(`tabs` 권한 안에서).
- "로그아웃됨" 판정 규칙(예: 틀 시작 주소와 다른 로그인 화면으로 넘어감, 비밀번호 칸이 새로 나타남) — 단위 시험으로 고정한다. 판정이 애매하면 "막힘"으로 멈추고 이유를 보여 준다(다시 제출하지 않는다).
- 광고 요청을 무엇으로 가릴지(작은 내장 도메인 목록 등). 외부 광고 목록을 새 의존성으로 들이려면 이유 한 줄 + 승인 후.
- 배지 숫자와 Phase 1의 "도울 수 없음" 배지("없음")가 겹칠 때의 우선순위.
- 반복 패턴의 "같은 입력칸 묶음" 식별 규칙(Phase 1 요소 식별 묶음을 쓰되 순서·일부 차이 허용 범위), "한 번 입력"의 경계(제출·페이지 벗어남·일정 시간), 몇 번째에서 언제 물을지, "예"를 고르면 무엇을 할지(예: 그 양식의 시작 페이지에서 Phase 4 "틀 기록" 시작), 세기 기록의 보관 기간.
- 메시지 타입 이름, 파일 배치, 설정 형식 버전 올리는 방법.
