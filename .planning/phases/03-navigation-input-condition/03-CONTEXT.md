## Phase Boundary

설계 10-1 "만드는 순서" 3번: **키 스크롤·명령판·되돌리기, 입력 줄이기, 양식 한 장 보기, 컨디션 모드, 맞춤 설정**을 Phase 1의 MV3 확장 위에 더한다. 이용자가 마우스 없이 명령판과 키로 이동·되돌리기를 하고, 긴 입력 양식을 큰 칸 화면과 최근 값·문구 카드로 빠르게 채우며, 그날 손 상태에 맞는 설정 묶음을 한 번에 고를 수 있어야 한다.

요구사항: CLICK-05, SAFE-06, STOR-03, STOR-04, NAV-01~06, INPT-01~03, PRIV-01~03, PERS-01~03 (ROADMAP Phase 3).

설계 검토(CEO·디자인·엔지니어링)는 모두 끝났고, 설계의 모든 결정은 잠긴 결정이다(GSTACK REVIEW REPORT, "NO UNRESOLVED DECISIONS"). 다시 열지 않는다.

## Implementation Decisions

### 구조 (Phase 1 결정 이어받기)
- **D-01:** Phase 1의 구조를 그대로 쓴다: 모든 프레임에 content script, 자주 일어나는 일(스크롤 영역 찾기, 입력칸 안/밖 판정)은 그 프레임에서 바로, **명령판·확인 화면·모드 표시는 맨 위 프레임이 모아서** 띄운다. 프레임끼리의 메시지는 service worker를 거친다(설계 4장, 엔지니어링 검토 1번).
- **D-02:** 도우미는 `isTrusted` 입력에만 반응하고, 입력 필터(떨림 걸러내기)가 가장 먼저 받는다. 명령판·카드·맞춤 설정 화면의 키 입력도 같은 필터를 거친다(설계 5장·8장, 엔지니어링 검토 4번).
- **D-03:** 모든 저장은 service worker 하나가 순서대로 한다(단일 저장자). 동기화 항목은 사이트별로 나눠 한 항목 8KB·분당 쓰기 제한을 지킨다. 새로 저장하는 데이터에도 형식 버전을 붙이고, 형식 변환이 실패하면 원래 데이터를 그대로 두고 알린다(설계 7장, 엔지니어링 검토 6번).
- **D-04:** 저장 위치(설계 7장): 조작 설정·컨디션 모드·고정 번호·자주 쓰는 문구·민감칸 설정·위험 단어·키 배치·명령판 카드 자리 = `chrome.storage.sync`. 최근 입력 값 = `chrome.storage.local`. 서버로 보내는 것은 없다(Phase 3에는 밖으로 나가는 요청이 없다).

### 명령판·이동 (NAV-01~06)
- **D-05:** 0 = 명령판 열기(도우미 모드일 때만. 입력칸 안에서는 0이 글자로 들어간다). 명령판은 큰 번호 카드 격자(3열, 카드 사이 16px)로, 1~9로 고르고 Esc로 이전 장 또는 닫기(설계 6.5, SYSTEM.md 명령판 템플릿).
- **D-06:** 카드 자리는 **고정**이다(디자인 검토 1번, 사용자 결정). 첫 장: 1 뒤로 · 2 작업판 · 3 틀 실행 · 4 조작 방식 바꾸기 · 5 입력 되돌리기 · 6 컨디션 모드 · 7 새로고침 · 8 도우미 끄기 · 9 다음 장. 둘째 장: 1 앞으로 · 2 탭 닫기 · 3 새 탭 · 4 틀 기록 · 5 번호 고정 · 6 양식 한 장 보기 · 7 화면 정리(AI) · 8 더블클릭. 셋째 장: 1 끌어서 놓기 · 2 민감칸 설정 · 3 기록 내보내기 · 4 맞춤 설정 다시 하기. 이용자는 설정에서 카드 자리를 바꿀 수 있고, 바꾼 자리도 고정이다(쓰는 횟수로 저절로 움직이지 않는다).
- **D-07:** 명령판 첫 화면에 키 안내 카드: 스페이스바·1~9·0·↑↓·Esc, 그리고 "브라우저 알림 창은 Enter=확인, Esc=취소"(설계 6.5, CEO 검토).
- **D-08:** ↑↓ = 한 화면의 80%씩 부드럽게 스크롤. 페이지 안에 스크롤 영역이 여러 개면 자석 커서가 있는 영역을 움직인다(설계 6.5).
- **D-09:** 되돌리기: 번호·자석 커서로 링크를 눌러 페이지가 바뀐 **직후** Esc를 누르면 뒤로 간다. 입력칸에 방금 넣은 값은 명령판 "입력 되돌리기"로 되돌린다(설계 6.5).
- **D-10:** 번호 고정: 명령판 "번호 고정"으로 이 사이트의 특정 요소에 번호(1~9)를 고정한다. 요소 식별은 Phase 1의 식별 묶음(id·name·라벨 글자·버튼 글자·aria·페이지 안 위치 경로·프레임 경로)을 쓰고, 고정 번호는 번호표 순서의 1순위다(설계 6.2, Phase 1 D-11).
- **D-11:** 번호표는 한 번에 1~9만 보여 주고, 9개를 넘으면 0 → "다음 번호"로 넘긴다(설계 6.2, SYSTEM.md 상태 표 "9개 넘으면 '0 → 다음 번호' 카드").
- **D-12:** 떨림 걸러내기가 의도치 않은 더블클릭을 한 번으로 줄이므로, 더블클릭이 필요한 곳은 명령판 "더블클릭"으로 한다(설계 5장).
- **D-13:** 명령판 "도우미 끄기"는 도우미 전체 또는 지금 사이트만 끈다 — 확장 아이콘의 끄기(Phase 1)와 같은 설정을 쓴다(설계 8장, Phase 1 D-20).

### 자동 순서 강조·위험 단어 (CLICK-05, SAFE-06)
- **D-14:** 자동 순서 강조: 번호표가 붙은 요소를 하나씩 차례로 강조하고, 아무 키나(기본 스페이스바) 누르면 강조된 요소가 선택된다. 강조 간격은 조절할 수 있다(컨디션 모드의 "강조 속도"). 손이 특히 힘든 날을 위한 예비 방식이다(설계 6.3).
- **D-15:** 자동 순서 강조로 위험한 버튼을 고르면 번호표와 똑같이 빨간 테두리와 함께 "정말 누를까요? Enter = 예"를 묻는다(확인 화면 보호: 1초 입력 무시, Enter 또는 스페이스바 1초)(설계 8장·5장).
- **D-16:** 위험한 버튼 단어 목록은 사이트마다 고칠 수 있다(더하기·빼기). 기본 목록에 결재·상신은 넣지 않는다(외부 검토 제안을 이용자가 거절). 이용자가 직접 더하는 것은 막지 않는다(설계 8장).

### 입력 줄이기 (INPT-01, INPT-02)
- **D-17:** 입력칸을 누르면 그 칸의 **최근 입력 값**과 이용자가 저장한 **자주 쓰는 문구**를 번호 카드로 보여 준다. 입력칸 안에서는 숫자가 글자로 들어가므로 카드는 **Alt+1~9**로 고른다. 칸은 **사이트 + 칸 이름**으로 구분한다(설계 6.6, CEO 검토).
- **D-18:** 최근 값이 없으면 카드 대신 "자주 쓰는 문구 추가" 카드 1개. 민감칸이면 카드 없이 "민감칸이라 기록하지 않아요"(SYSTEM.md 상태 표).
- **D-19:** 이용자는 자주 쓰는 문구를 저장하고 고칠 수 있다(INPT-02). 문구는 동기화(sync)에 둔다(설계 7장).
- **D-20:** 카드로 고른 값은 원래 칸에 넣고 입력 이벤트를 함께 발생시켜 사이트가 알아채게 한다(설계 6.7과 같은 방식).

### 양식 한 장 보기 (INPT-03)
- **D-21:** 명령판 "양식 한 장 보기"를 켜면 지금 페이지의 입력칸들을 큰 칸이 위아래로 한 줄씩 늘어선 화면으로 모은다. 각 칸에는 원래 칸의 제목(라벨)을 크게 붙이고, 선택 목록은 번호 카드로 바꾼다(설계 6.7).
- **D-22:** 여기서 입력한 값은 원래 칸에 바로 채워지고, 입력 이벤트를 함께 발생시켜 사이트가 알아채게 한다. **제출 버튼은 이 화면에 두지 않는다.** "원래 화면으로"(Esc)를 누르면 닫히고 제출은 원래 화면에서 한다(설계 6.7).
- **D-23:** 상태(SYSTEM.md 상태 표): 칸 모으는 중 "불러오는 중"(0.3초 안에 끝나면 표시 안 함), 입력칸 없음 "이 페이지에는 입력칸이 없어요" + [Esc 닫기], 못 옮긴 칸은 목록 끝에 "원래 화면에서 입력하세요: 칸 이름".
- **D-24:** 회사 시스템은 iframe 안에 본문이 있는 경우가 많으므로(설계 4장, CEO 검토 "iframe 지원") 양식 한 장 보기는 iframe 안의 입력칸도 모은다. 프레임 사이 값 전달은 service worker를 거친다(D-01).

### 민감칸 (PRIV-01~03)
- **D-25:** 판별(설계 8장): `type=password` 칸, 이름·라벨에 비밀번호·비번·PW·인증번호·OTP·보안카드가 들어간 칸은 기본으로 민감하다. 이름·라벨에 주민·계좌·카드가 들어간 칸은 **입력된 값이 주민번호·계좌번호·카드번호 모양일 때만** 민감하다("법인카드 구분", "지급계좌 선택" 같은 업무 칸이 막히지 않게).
- **D-26:** 민감칸의 값은 최근 입력에 남기지 않고 입력 줄이기 카드도 보여 주지 않는다. 같은 판별을 틀 저장(Phase 4)·활동 기록(Phase 4)·AI 전송(Phase 6)이 그대로 쓰도록 **한 곳의 판별 함수**로 만든다(설계 8장, PRIV-01).
- **D-27:** 이용자가 직접 정하기: 명령판 "민감칸 설정"에서 칸을 골라 "이 칸은 민감함 / 민감하지 않음"으로 사이트마다 정한다. 비밀번호 칸을 포함한 **모든 민감칸을 풀 수 있고**, 풀 때는 한 번 더 확인한다(확인 화면 보호 적용). 비밀번호 칸을 풀 때의 확인 화면에는 "이 칸의 값이 이 PC와 틀 파일에 암호화 없이 저장됩니다"라고 적는다. 이 설정은 계정 동기화로 다른 PC에도 적용된다(설계 8장, 이용자 결정).
- **D-28:** 판별 단어 목록(기본 민감 단어, 값 모양을 보는 단어)은 설정에서 더하고 뺄 수 있다(PRIV-03).

### 컨디션 모드·맞춤 설정·키 배치 (PERS-01~03)
- **D-29:** 컨디션 모드 = "좋은 날 / 힘든 날" 두 설정 묶음. 각 묶음에 조작 방식(자석 커서 / 번호표 / 자동 순서 강조), 떨림 간격, 머무르기 시간, 강조 속도, 번호표·테두리 크기를 저장하고, 명령판에서 한 번에 바꾼다. 번호표·테두리 크기는 브라우저 확대와 상관없이 고정되고 이 설정("표시 크기")으로만 바뀐다(설계 6.11, SYSTEM.md 크기, 디자인 검토 5번).
- **D-30:** 처음 설치할 때의 맞춤 설정은 세 단계다(디자인 검토 3번): ① 키 안내(스페이스바·1~9·0·↑↓·Esc, "브라우저 알림 창은 Enter=확인, Esc=취소"를 큰 카드로) ② 떨림 간격 재기(큰 버튼을 몇 번 누르게 해 같은 키가 의도치 않게 다시 눌리는 간격을 잰다) ③ 머무르기 시간 재기(큰 버튼 위에 커서를 올려 두게 해 편한 머무르기 시간을 잰다). 단계마다 "Esc 건너뛰기"가 있고 건너뛴 단계는 기본값을 쓴다. 나중에 명령판 "맞춤 설정 다시 하기"로 다시 한다(설계 6.12).
- **D-31:** 잰 값으로 두 컨디션 모드의 기본값을 정한다(설계 6.12). ROADMAP 성공 기준 4대로 묶음에는 자동 순서 강조를 포함한 조작 방식이 들어간다.
- **D-32:** 도우미 키 배치(스페이스바·Enter·1~9·Alt+1~9·0·↑↓·←→·Esc 등)는 모두 바꿀 수 있다(설계 5장 "모두 바꿀 수 있음", PERS-03). Phase 1은 키 배치를 설정 구조로 두었다(Phase 1 D-15). Phase 3이 바꾸는 화면을 만든다.

### 동기화 용량·설정 파일 (STOR-03, STOR-04)
- **D-33:** 동기화 용량(약 100KB)을 넘을 것 같으면 **넘기 전에** 알리고, 자주 쓰는 문구부터 파일 내보내기를 안내한다(설계 7장, SYSTEM.md 상태 표 "용량 초과: 알림 + '파일로 내보내기' 카드").
- **D-34:** 동기화는 같은 브라우저끼리만 된다. 다른 브라우저(크롬↔엣지↔웨일)로 옮길 때는 **설정 파일 내보내기·가져오기**를 쓴다. 파일에도 형식 버전을 붙이고, 가져오기가 실패하면 지금 설정을 그대로 두고 알린다(설계 7장).
- **D-35:** AI 사용 키와 최근 입력 값은 동기화하지 않는다(이 PC만). 설정 파일 내보내기는 동기화 설정만 담는다(설계 7장).

### 화면(오버레이)
- **D-36:** 모든 오버레이는 `docs/design/SYSTEM.md`(안 A 등대)와 `docs/design/tokens.css`만 따른다: Shadow DOM 안, 카드 radius 12·선택 시 남색 3px, 누르는 대상 높이 56px 이상, 번호 카드 = 큰 숫자(22px, 700) + 이름, 모든 버튼에 누를 키 칩, 새 색·서체·radius·그림자 금지(디자인 검토, DESIGN.md §4).

### 시험
- **D-39:** 모든 기능은 로컬 연습 사이트에서 먼저 시험한다. Phase 3용으로 연습 사이트에 스크롤 영역이 여러 개인 페이지, 긴 양식(선택 목록 포함, iframe 안 양식 포함), 민감칸 이름·라벨이 붙은 칸(비밀번호·인증번호·주민·계좌·카드, "법인카드 구분"처럼 막히면 안 되는 업무 칸), 더블클릭이 필요한 요소, 다른 페이지로 가는 링크를 더한다(설계 10장).
- **D-40:** 단위 시험(Phase 3 해당분): 민감한 칸 판별(설계 10장 명시), 저장 형식 변환. 확장을 띄운 브라우저 시험(Chromium, `CI=true`): 명령판·스크롤·뒤로·입력 되돌리기·번호 고정·더블클릭·입력 줄이기·양식 한 장 보기(iframe 포함)·민감칸·컨디션 전환·맞춤 설정·설정 파일 내보내기/가져오기. 엣지·웨일과 다른 브라우저 사이 설정 옮기기는 수동 확인 목록(설계 10장, Phase 1 D-29).
- **D-41:** UI 완료 판정은 저장소 규칙대로: 싼 게이트(lint·typecheck·build) → 별도 에이전트의 독립 DOM 감사(`CI=true`, 스크린샷 육안 금지) → 수정 → 전체 게이트 한 번(CLAUDE.md).

### Claude's Discretion
- 명령판 카드 중 이 단계에서 아직 동작하지 않는 것(작업판·틀 실행·틀 기록·화면 정리·기록 내보내기 — Phase 4~6)의 표시 방법. 단, **고정된 카드 자리는 비우거나 옮기지 않는다**(D-06).
- "다음 번호" 카드를 명령판 어디에 둘지 — 고정 자리(D-06)를 옮기지 않는 방법으로.
- Esc가 여러 뜻(취소·입력칸 빠져나오기·방금 이동한 페이지에서 뒤로)을 가질 때의 우선순위와 "직후"의 기준. 단, 명령판·확인 화면이 열려 있거나 입력 중일 때 Esc가 뒤로 가기가 되어서는 안 된다.
- "입력 되돌리기"가 몇 단계까지 되돌리는지, 최근 입력 값을 몇 개·언제(바뀜·벗어남·제출) 기록하는지.
- 주민번호·계좌번호·카드번호 "모양"의 정확한 규칙 — 단위 시험으로 고정한다.
- 입력 줄이기 카드와 양식 한 장 보기를 어느 프레임에서 그릴지(D-01 테두리 안에서).
- 설정 화면을 둘 자리(확장 옵션 페이지 또는 팝업 확장)와 처음 설치 맞춤 설정을 띄울 자리 — D-38 절차를 따른다.
- 맞춤 설정에서 잰 값으로 "좋은 날 / 힘든 날" 기본값을 만드는 규칙과 "힘든 날"의 기본 조작 방식.
- 키 배치를 바꿀 때 막을 조합(같은 키를 두 동작에 주기 등)과 검사 방식(zod).
- 동기화 용량 알림을 띄울 기준값, 설정 파일 형식·파일 이름, 가져오기가 덮어쓰기인지 합치기인지.
- 파일 내보내기에 새 권한(`downloads` 등)이 필요하면 새 권한이므로 만들 때 승인받는다. 새 의존성도 이유 한 줄 + 승인 후(저장소 규칙).
- 메시지 타입 이름, 파일 배치, 설정 형식 버전 올리는 방법.
