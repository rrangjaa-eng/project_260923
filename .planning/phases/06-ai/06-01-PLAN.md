## Phase Goal

**As a** 이용자, **I want to** 처음 보는 복잡한 화면에서 명령판의 "화면 정리"를 누르면 중요한 요소 9개에 번호가 붙기를, **so that** AI가 없거나 실패해도 나머지 기능은 그대로이고, 개인정보와 입력 값은 밖으로 나가지 않는다.

(ROADMAP Phase 6 **Goal** 문장을 그대로 세 칸에 옮긴 것이다. 새 내용은 더하지 않았다. Goal 문장이 user story 형식이 아니라 so that 칸에 이득 대신 제약이 들어갔다 — `/gsd-mvp-phase 6`으로 다듬을 수 있다.)

## 실행 규칙 (모든 작업 공통)

- 패키지 매니저는 pnpm만. TypeScript strict, `any` 금지, 시크릿을 코드·커밋에 넣지 않는다(CLAUDE.md).
- 구현 전에 Superpowers `test-driven-development` 스킬을, 시험 실패·버그를 쫓기 전에 `systematic-debugging`을, "완료"라고 말하기 전에 `verification-before-completion`을 **호출**한다. 서브에이전트에 맡기면 그 프롬프트에 세 스킬과 `model`을 적는다(점검·판단은 Opus 5).
- `tdd="true"`/`type="tracer"` 작업은 실패하는 시험을 먼저 쓰고 실패를 확인한 뒤(RED 커밋 `test(06-01): …`) 최소 구현으로 통과시킨다(GREEN 커밋 `feat(06-01): …`). 커밋 제목은 영어 접두어, 본문은 한국어.
- 완료 판정은 `CI=true`로 돌린 e2e(프로덕션 빌드)다. 로컬 dev 통과는 완료 신호가 아니다.
- 이 계획은 패키지를 설치하지 않는다(`package.json`·`pnpm-lock.yaml`을 바꾸지 않는다). Task 1의 선택은 06-04 Task 1이 그대로 따른다. `host_permissions: ['<all_urls>']`가 이미 API 주소를 덮으므로 새 권한은 없다(D-26). 필요해지면 멈추고 이유 한 줄과 함께 승인을 요청한다.
- **자동 시험은 진짜 Anthropic API를 부르지 않는다.** 시험 키는 `FAKE_AI_KEY`(진짜 키 모양이 아닌 문자열) 하나뿐이다. 진짜 키를 저장소·CI·환경변수 파일에 두지 않는다(D-28).
- 실제 회사 시스템에 접속하거나 시험하지 않는다(D-29).
