## Phase Boundary

설계 10-1 "만드는 순서" 1번: **요소 수집기 + 떨림 걸러내기 + 클릭 도우미(자석 커서·번호표·머무르기) + 안전장치(위험한 버튼·확인 화면 보호) + 도우미 끄기**를 크롬(Chromium) MV3 확장으로 만든다. 로컬 연습 사이트에서 이용자가 요소를 "대충 가져가서" 또는 숫자 키 하나로 누를 수 있고, 떨림 재입력·위험한 버튼 오조작이 막히며, 방해되면 확장 아이콘에서 바로 끌 수 있어야 한다.

요구사항: ELEM-01~04, FILT-01~04, CLICK-01~04, KEY-01~02, SAFE-01~05, STOR-01~02 (ROADMAP Phase 1).

설계 검토(CEO·디자인·엔지니어링)는 모두 끝났고, 설계의 모든 결정은 잠긴 결정이다(GSTACK REVIEW REPORT, "NO UNRESOLVED DECISIONS").

**ROADMAP 성공 기준 4 정정(엔지니어링 검토 7번 = B, 사용자 결정):** "확장이 만든 클릭을 사이트가 받는지 확인한 스파이크(11장 ①)"는 Phase 1에서 **로컬 연습 사이트에서만** 한다. 회사 시스템 확인은 회사 시스템이 완성된 뒤(아직 만드는 중 — PLANT8 ERP 아님, 2026-09-23 사용자 결정·설계 11장 ①)에 한다(Phase 2 중간 이용자 시험도 연습 사이트로만). Phase 1은 회사 시스템을 건드리지 않는다.

## Implementation Decisions

### 구조·스택
- **D-01:** Manifest V3 확장 하나(크롬·엣지·웨일, 윈도우 PC). TypeScript strict, `any` 금지, pnpm만 쓴다. 빌드 도구는 구현 계획에서 정한다(설계 4장, 저장소 규칙).
- **D-02:** content script는 모든 프레임에 들어간다(`all_frames`). 자석 커서 계산·강조 테두리·머무르기 클릭·입력칸 안/밖 판정은 **그 프레임에서 바로** 한다 — 50ms 목표 때문에 다른 프레임을 거치지 않는다(엔지니어링 검토 1번).
- **D-03:** **맨 위 프레임이 모아서** 번호표 번호 매기기(모든 프레임의 요소 목록), 모드 표시, 확인 화면을 맡는다. 프레임끼리의 메시지는 service worker를 거친다. 부모 프레임은 `chrome.runtime.getFrameId(iframe 요소)`로 자식 프레임과 iframe 요소를 짝짓는다(엔지니어링 검토 1번).
- **D-04:** 요소 수집기는 누를 수 있는 요소(버튼, 링크, 입력칸, 클릭 이벤트가 걸린 이미지 등)를 위치·이름·종류 목록으로 만들고, 화면이 바뀌면(MutationObserver) 모아서 한 번에 갱신한다. 화면에 보이는 요소만 다루고, 위치는 격자(공간 색인)로 나눠 찾는다. 마우스 움직임 계산은 1초에 60번까지만 한다(설계 4장).
- **D-05:** 성능 목표: 요소 5,000개짜리 연습 페이지에서 커서를 옮긴 뒤 강조가 50ms 안에 따라온다. 이 반응 시간은 확장을 띄운 브라우저 자동 시험으로 잰다(설계 4장·10장).

### 떨림 걸러내기
- **D-06:** 입력 필터가 키보드·마우스 입력을 가장 먼저 받아 떨림을 거른 뒤 다른 기능에 넘긴다. 각 부분은 요소 목록과 필터링된 입력만 주고받는다(설계 4장).
- **D-07:** 같은 키·같은 자리 클릭이 설정한 간격 안에 다시 들어오면 무시한다(기본값은 맞춤 설정에서 정함 — Phase 1은 설정 가능한 기본값을 둔다). 키를 오래 눌러도 한 번만 입력한다(자동 반복 끔). 의도치 않은 더블클릭은 한 번으로 줄인다(설계 5장).
- **D-08:** 끌어서 놓기는 "끌기 시작 → 놓을 곳 누르기"의 두 번 누르기로 바꿀 수 있다(버튼을 계속 누르고 있을 필요 없음)(설계 5장).
- **D-09:** 도우미는 브라우저가 "사람이 누름"(`isTrusted`)으로 표시한 키·마우스 입력에만 반응한다. 사이트가 만든 가짜 Enter로 확인 화면이 넘어가지 않는다. 도우미 부분끼리의 메시지(프레임 사이 포함)는 사이트가 닿지 않는 확장 내부 통로(service worker)로만 주고받는다(엔지니어링 검토 4번).

### 클릭 도우미
- **D-10:** 자석 커서(기본 방식): 커서에 가장 가까운 요소를 잡아 굵은 테두리로 크게 강조한다. 잡는 범위는 요소 크기보다 넓다. 다른 요소 쪽으로 충분히 옮겨 가기 전까지는 잡은 요소를 바꾸지 않는다(히스테리시스). 클릭하거나 스페이스바를 누르면 커서의 실제 위치와 상관없이 잡은 요소가 눌린다. 잡은 요소가 없을 때의 클릭은 원래 클릭 그대로 둔다(설계 6.1).
- **D-11:** 번호표: 단축키로 켠다. 번호 순서는 ① 이 사이트에서 직접 고정한 번호 ② 이 사이트에서 누른 횟수가 많은 순서 ③ 나머지는 지금 커서 주변 요소. 한 번에 1~9만 보여 준다. 요소 식별(고정 번호·누른 횟수를 어느 요소에 붙일지)은 6.8의 "요소 찾기"와 같은 방식 — id, name, 라벨 글자, 버튼 글자, aria 속성, 페이지 안 위치 경로, 프레임 경로를 함께 기억하고, 여러 방식이 같은 요소를 가리킬수록 확실하다고 본다(설계 6.2·6.8).
- **D-12:** 머무르기 클릭: 켜 두면 자석 커서가 잡은 요소 위에 커서가 설정 시간(예: 0.8초) 머물 때 클릭한다. 진행 중에는 요소 둘레에 원이 차오르듯 표시하고, 그 전에 커서를 치우면 취소된다. 한 번 누른 요소는 커서가 떠났다 돌아오기 전까지 다시 누르지 않는다(설계 6.4).
- **D-13:** 대신 누르기 방식: 마우스 누름·뗌·클릭과 포커스를 차례로 보낸다. 선택 목록은 이용자의 실제 키 입력에서 연다. 개발자 도구(`debugger`) 방식은 쓰지 않는다. 새 창(결재 팝업)·선택 목록·파일 선택 창이 막히는지를 1단계 첫 시험(연습 사이트)에 넣는다. 새 창 허용용 팝업 권한 `contentSettings`는 새 권한이라 만들 때 승인받는다(설계 11장 ⑤, 엔지니어링 검토 5번).
- **D-14:** 설계 11장 ① "대신 누른 클릭을 받지 않는 사이트" 확인은 **Phase 1에서는 로컬 연습 사이트에서만** 하고, 회사 시스템 확인은 회사 시스템이 완성된 뒤(아직 만드는 중 — PLANT8 ERP 아님, 2026-09-23 사용자 결정·설계 11장 ①)에 한다. 그 전에는 회사 시스템을 건드리지 않고, 중간 이용자 시험(Phase 2)도 연습 사이트로만 한다(엔지니어링 검토 7번 = B).

### 키와 입력 모드
- **D-15:** 키 배치(모두 바꿀 수 있음): 스페이스바 = 잡은 요소 누르기, Enter = 확인 화면에서 "예"(스페이스바 1초 누르기도 됨), 1~9 = 번호표 요소 누르기, Esc = 취소·입력칸 빠져나오기. 키 배치는 설정 구조로 두어 바꿀 수 있게 한다(설계 5장).
- **D-16:** 커서가 입력칸 안에 있을 때는 숫자·스페이스바가 원래대로 글자를 입력한다. 글쓰기 편집기(`contenteditable`)도 입력칸으로 본다. Esc로 입력칸을 빠져나오면 도우미 키로 돌아간다. 화면 구석에 지금 "입력 중"인지 "도우미"인지 크게 표시한다(설계 5장).
- **D-17:** 숫자·스페이스바를 자체 단축키로 쓰는 사이트에서도 도우미 모드일 때는 도우미 키가 우선하도록 가로챈다 — 가능한지 연습 사이트에서 확인한다(설계 11장 ④).

### 안전장치
- **D-18:** 위험한 버튼: 글자에 삭제·취소·반려·로그아웃·결재 취소 같은 말이 들어간 버튼(목록은 사이트마다 고칠 수 있음 — 목록 자체는 설정 구조로 둔다). 자석 커서가 끌어당기지 않고 커서가 버튼 위에 정확히 있을 때만 잡힌다. 머무르기 클릭이 동작하지 않는다. 번호표로 고르면 빨간 테두리와 함께 "정말 누를까요? Enter = 예"를 한 번 더 묻는다. 결재·상신은 위험 단어에 넣지 않는다(외부 검토 제안을 이용자가 거절)(설계 8장).
- **D-19:** 확인 화면 보호: 확인 화면이 뜬 뒤 1초 동안은 모든 입력을 무시한다. 확인은 방금 누른 스페이스바가 아닌 Enter(또는 스페이스바 1초 누르기)로 하고, 취소는 Esc(설계 5장).
- **D-20:** 도우미 끄기: 확장 프로그램 아이콘에서 도우미 전체, 또는 지금 사이트에서만 끌 수 있다. 어떤 사이트에서 도우미가 방해되면 바로 끄고 일을 계속할 수 있어야 한다(설계 8장). (명령판에서 끄기는 명령판이 생기는 Phase 3.)
- **D-21:** 확장 프로그램이 동작하지 않는 페이지(브라우저 설정 화면, 웹스토어 등)에서는 확장 프로그램 아이콘에 "도울 수 없음"을 표시한다(설계 9장).
- **D-22:** 업데이트·재시작으로 연결이 끊긴 옛 도우미는 스스로 모든 키 감시와 화면 표시를 걷어 내서 키를 가로채지 않는다. 업데이트 직후 열린 탭에 새 도우미를 넣는다(`onInstalled`)(엔지니어링 검토 3번).

### 저장과 동기화
- **D-23:** 조작 설정·사이트별 끄기·고정 번호는 `chrome.storage.sync`(같은 브라우저 계정의 다른 PC에 적용), 자주 누른 기록은 `chrome.storage.local`(설계 7장).
- **D-24:** 저장은 한 곳에서만: 모든 저장은 service worker 하나가 순서대로 한다. 탭·프레임은 저장을 부탁만 한다. 동기화 항목은 사이트별로 나눠 한 항목 8KB·분당 쓰기 횟수 제한을 넘지 않게 한다(엔지니어링 검토 6번).
- **D-25:** 저장하는 모든 데이터에는 형식 버전을 붙인다. 새 버전으로 바꾸다 실패하면 원래 데이터를 그대로 두고 알린다(설계 7장).

### 화면(오버레이)
- **D-26:** 모든 오버레이는 `docs/design/SYSTEM.md`(안 A 등대)와 `docs/design/tokens.css`만 따른다: Shadow DOM 안, 흰 후광 2px, 강조 테두리 남색 5px(요소보다 8px 바깥), 번호표 28×28 이상, 위험 = 빨강 + 점선 + "! 위험" 글자, 모드 표시 왼쪽 아래(커서 80px 안이면 반대편으로 비킴), 확인 카드 600px·버튼 64px, 브라우저 확대와 상관없이 크기 고정, 새 색·서체·radius 금지(디자인 검토 1~6번).
- **D-27:** 상태 표(SYSTEM.md): 번호표 비어 있음 = 모드 표시에 "누를 곳이 없어요" 2초, 자석 커서 잡힌 것 없음 = 테두리 없음·클릭은 원래대로, 잡힘 바뀜 = 테두리 이동 80ms(디자인 검토 2번).

### 시험
- **D-28:** 연습용 가짜 사이트(로컬)를 만든다: 아주 작은 버튼과 이미지 링크, 긴 입력 양식, 늦게 나타나는 입력칸, iframe 안의 양식(중첩·다른 출처), 위험한 버튼, 요소 5,000개짜리 큰 페이지 등. 모든 기능은 이 사이트에서 먼저 시험하고, 실제 회사 시스템에서는 시험하지 않는다(설계 10장).
- **D-29:** CI는 크롬(Chromium)으로만 돈다. 엣지·웨일은 출시마다 짧은 수동 확인 목록으로, 웹스토어 설치·계정 동기화·다른 PC는 수동으로 확인한다(설계 10장, 엔지니어링 검토).
- **D-30:** 단위 시험(Phase 1 해당분): 떨림 필터(간격 안의 재입력 무시), 자석 커서 히스테리시스, 번호표 우선순위, 위험한 버튼 판별, 저장 형식 변환. 확장을 띄운 브라우저 시험: iframe 안 양식, 큰 페이지의 강조 반응 시간(50ms)(설계 10장).
- **D-31:** 데이터는 서버로 보내지 않는다. Phase 1에는 밖으로 나가는 요청이 없다(설계 8장).

### Claude's Discretion
- 빌드 도구·UI 라이브러리·시험 도구 선택(D-01이 "구현 계획에서 정한다"고 열어 둠) — 연구(STACK.md) 추천을 따르되 저장소 규칙대로 의존성 승인 체크포인트 뒤에만 설치한다.
- 번호표를 켜는 단축키의 기본값(설계 5장 키 표에 없음) — 설정 구조 안의 바꿀 수 있는 기본값으로 둔다.
- Phase 1에서 끌어서 놓기 두 번 누르기(D-08)를 켜는 자리 — 명령판이 아직 없으므로 확장 아이콘 메뉴의 설정 스위치로 둔다.
- 떨림 간격·잡는 범위·머무르기 시간의 초기 기본값 — Phase 2 이용자 시험에서 맞추므로 설정 가능한 값으로만 둔다.
- 격자 칸 크기, 메시지 타입 이름, 파일 배치.
