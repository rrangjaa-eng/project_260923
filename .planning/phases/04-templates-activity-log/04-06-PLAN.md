## Phase Goal

**As a** 손 떨림이 있는 이용자, **I want to** 반복 업무를 한 번 해 보여 틀로 저장하고 이후 "틀 고르기 1번 + 바뀌는 값 2~3번 + 제출 확인 1번"으로 끝내기를, **so that** 되돌릴 수 없는 제출은 항상 확인 뒤에 한 번만 일어나고 문제가 생기면 활동 기록으로 추적할 수 있다.

<objective>
화면이 기록 때와 달라 요소를 확실히 찾지 못하면 누르지 않고 멈춘 뒤 이유와 [1 이 단계만 다시 기록] [Esc 멈춤]을 보여 주는 세로 조각. 확신 판정의 최종 규칙(빈 후보·동점·사라진 프레임·글자 정규화·단서 하나)을 단위 시험으로 고정하고, 한 단계만 다시 기록해 확인 뒤 틀에 반영한다.

Purpose: TMPL-05(D-15 확정), TMPL-12(D-28). ROADMAP 성공 기준 2 "화면이 예상과 다르면 멈추고 그 단계만 다시 기록".
Output: 상태 카드 템플릿·오버레이, 막힘 흐름, `template-match.ts` 최종 규칙 + 단위 시험, 한 단계 다시 기록, `workflow-drift.html`, e2e.
</objective>

## 가정 (spec-less edge probe)

- TMPL-05 `empty`(edge probe "What is the result for empty, single-element, or null input?") — 명시 truth로 작성: 빈 후보 → 막힘(none), 후보 하나 → 필요 점수 이상일 때만 match(두 번째가 없으면 차이 조건은 통과), 기록 fingerprint가 없거나 단서 1개 이하 → too-few-clues. 플래그: 필요 점수를 단서 수로 낮추는 규칙(단서 2개 → 2점)은 이 계획의 판단이다.
- TMPL-05 `encoding`(edge probe "Whose definition of length/equality applies?") — 명시 truth로 작성: 글자 비교는 NFC 정규화 + 공백 접기 + trim 뒤 코드 포인트 같음. 대소문자는 구분한다(한글에는 해당 없음, 영문 버튼 "OK"/"ok"는 다른 글자로 본다 — 플래그).
- TMPL-05 나머지 경계(플래그): 동점은 늘 막힘(어느 쪽도 누르지 않음). framePath가 다르면 후보가 아니다(Phase 1 matchScore 그대로).
- TMPL-12: edge probe `unclassified — review manually`. 가정한 경계(플래그):
  - 다시 기록은 이용자의 다음 동작 하나만 받는다(칸 입력이면 칸을 벗어날 때). 다른 단계를 여러 개 한 경우는 첫 하나만 쓴다.
  - 제출 단계는 제자리 다시 기록을 하지 않는다 — 이용자가 직접 누른 제출은 도우미의 누름 기록·결과 판정 밖이라 한 번만 원칙을 지킬 수 없다. 틀을 새로 기록하게 안내한다.
  - 다시 기록 확인 뒤에는 이용자가 이미 그 단계를 했으므로 다음 단계부터 이어 간다.
  - 식별 단서가 하나뿐인 요소는 다시 기록해도 늘 막힌다 — 카드 문구로 그 사실을 알린다.
