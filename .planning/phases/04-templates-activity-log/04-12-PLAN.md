## Phase Goal

**As a** 손 떨림이 있는 이용자, **I want to** 반복 업무를 한 번 해 보여 틀로 저장하고 이후 "틀 고르기 1번 + 바뀌는 값 2~3번 + 제출 확인 1번"으로 끝내기를, **so that** 되돌릴 수 없는 제출은 항상 확인 뒤에 한 번만 일어나고 문제가 생기면 활동 기록으로 추적할 수 있다.

<objective>
민감한 칸에서는 멈추고 이용자가 직접 입력하게 하고(값은 어디에도 남지 않음), 보안 키패드·자동입력 방지 문자·결제 화면에서는 도우미가 누르지도 채우지도 않고 멈춘다.

Purpose: TMPL-14(D-29, D-10, D-21, D-22), TMPL-15(D-30, D-39, D-40). 설계 8장 "대신 누르지 않는다"의 마지막 안전 장치.
Output: 직접 하기 카드(SYSTEM.md 템플릿 먼저), 'awaiting-manual' 흐름, `detectBlockedContext` + 단위 시험, 기록 때 변환·묶기, 실행 때 판별·"채워지지 않음" 폴백, 연습 페이지 4개, e2e 두 파일.
</objective>

- TMPL-14: edge probe `unclassified — review manually`. 가정한 경계(플래그):

  - 기록 뒤에 이용자가 사이트별 민감칸으로 지정한 칸은 실행 때 다시 판별해 멈추고, 그때 틀에 남아 있던 값을 지운다(확인 없이 — 값을 없애는 쪽이라 되돌릴 이유가 없다).

- TMPL-15: edge probe `unclassified — review manually`. 가정한 경계(플래그):
  - 주소 힌트(키패드·결제·CAPTCHA 서비스)는 **프레임 단위**다 — 그 프레임의 모든 동작이 직접 하기가 되고, 기록 때 이어진 동작은 하나로 묶인다. 보이지 않는 reCAPTCHA를 쓰는 사이트도 그 프레임 전체가 멈춘다(안전 쪽 선택, RESEARCH A2 목록은 nicepay 외 미검증).
  - CAPTCHA 글자 힌트는 **칸 단위**다(대상 칸의 label·부모 요소 글만 본다) — 같은 양식의 다른 칸은 그대로 채운다.
  - 제출 버튼이 막힌 화면에 있으면 확인 뒤에도 누르지 않고, 이용자가 직접 누른 뒤 Enter면 틀을 끝낸다. 결과는 알 수 없으므로 성공 토스트를 띄우지 않는다.
  - 결제 화면은 제출 성격 단어와 상관없이 어떤 누름도 하지 않는다. 기록 때 결제 화면에서 한 동작도 모두 직접 하기 단계가 되어 제출 단계로 고를 수 없다(04-03 finalSubmitIndex null 허용).
