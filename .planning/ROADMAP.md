# Roadmap: 손 떨림 브라우저 도우미 (이름 미정)

## Overview

설계 10-1 "만드는 순서"(승인된 결정)를 그대로 따른다. 먼저 핵심 가치인 클릭 도우미(요소 수집기 + 떨림 걸러내기 + 자석 커서·번호표 + 도우미 끄기)를 만들고, **나머지를 만들기 전에 실제 이용자 시험으로 기본값을 맞추는 체크포인트**를 둔다. 그 뒤 이동·입력(명령판이 이후 기능의 입구), 틀 자동화와 활동 기록, 작업판과 뒤에서 실행, 마지막으로 선택 기능인 화면 정리(AI)를 쌓는다. 설정의 granularity는 Coarse(3-5 phases)지만, 승인된 순서가 6단계이고 중간 이용자 시험을 별도 체크포인트로 두라는 결정이 있어 6개 phase로 둔다.

## Phases

**Phase Numbering:**

- Integer phases (1, 2, 3): Planned milestone work
- Decimal phases (2.1, 2.2): Urgent insertions (marked with INSERTED)

Decimal phases appear between their surrounding integers in numeric order.

- [ ] **Phase 1: 클릭 도우미 기반** - 요소 수집기·떨림 걸러내기·자석 커서·번호표·머무르기·안전장치·도우미 끄기로 어느 사이트에서든 대충 가져가서 누른다
- [ ] **Phase 2: 중간 이용자 시험 (체크포인트)** - 실제 이용자가 연습 사이트에서 써 보고 기본값을 맞춘 뒤 이후 순서를 확정한다
- [ ] **Phase 3: 이동·입력·컨디션** - 명령판·키 스크롤·되돌리기, 입력 줄이기, 양식 한 장 보기, 민감칸, 컨디션 모드, 맞춤 설정
- [ ] **Phase 4: 틀 자동화 + 활동 기록** - 반복 업무를 "틀 1 + 값 2~3 + 확인 1"로, 제출 안전장치·알림 창·막힘 복구·활동 기록
- [ ] **Phase 5: 작업판·뒤에서 실행·반복 패턴 알림** - 틀을 뒤에서 돌리며 다른 일을 하고, 확인 대기를 작업판에서 처리
- [ ] **Phase 6: 화면 정리 (AI)** - 처음 보는 복잡한 화면에서 키를 누를 때만 AI가 중요한 9개에 번호를 붙인다

## Phase Details

### Phase 1: 클릭 도우미 기반

**Goal**: 이용자가 어느 사이트에서든(iframe 본문 포함) 원하는 요소를 마우스를 대충 가져가거나 숫자 키 하나로 누를 수 있고, 떨림으로 인한 잘못 누름과 위험한 버튼 오조작이 막히며, 방해되면 즉시 끌 수 있다
**Mode:** mvp
**Depends on**: Nothing (first phase)
**Requirements**: ELEM-01, ELEM-02, ELEM-03, ELEM-04, FILT-01, FILT-02, FILT-03, FILT-04, CLICK-01, CLICK-02, CLICK-03, CLICK-04, KEY-01, KEY-02, SAFE-01, SAFE-02, SAFE-03, SAFE-04, SAFE-05, STOR-01, STOR-02
**Success Criteria** (what must be TRUE):

  1. 로컬 연습 사이트(작은 버튼·이미지 링크·늦게 뜨는 칸·중첩 iframe 양식)에서 이용자가 커서를 요소 근처로 대충 가져가 클릭·스페이스바로 누르거나, 번호표를 켜 숫자 키로 누를 수 있고, 커서가 떨려도 잡힌 요소가 바뀌지 않으며 번호가 프레임 사이에서 겹치지 않는다
  2. 떨림으로 인한 같은 키·같은 자리 재입력, 키 자동 반복, 의도치 않은 더블클릭이 한 번으로 처리되고, 머무르기 클릭은 원이 차오른 뒤에만 눌리며, 입력칸·편집기 안에서는 글자가 정상 입력되고 "입력 중 / 도우미" 표시가 크게 보인다
  3. 위험한 버튼은 끌어당겨지지 않고 머무르기로 눌리지 않으며, 번호로 고르면 빨간 확인 화면이 뜨고 그 뒤 1초 안의 입력은 무시되며 Enter(또는 스페이스바 1초)로만 확인된다
  4. 요소 5,000개 연습 페이지에서 커서 이동 후 강조가 50ms 안에 따라오는 것이 자동 시험으로 측정되고, 확장이 만든 클릭을 사이트가 받는지 확인한 스파이크 결과(설계 11장 ①·④)가 로컬 연습 사이트에서 기록된다(회사 시스템 확인은 Phase 2 중간 이용자 시험 때 한다 — 엔지니어링 검토 7번)

### Phase 2: 중간 이용자 시험 (체크포인트)

**Goal**: 나머지를 만들기 전에 실제 이용자가 자기 PC에서 클릭 도우미를 써 보고, 그 결과로 떨림 간격·잡는 범위·머무르기 시간 기본값을 맞추고 이후 만드는 순서를 확정한다
**Mode:** mvp
**Depends on**: Phase 1
**Requirements**: TEST-01, TEST-02, TEST-03, DIST-01, DIST-02
**Success Criteria** (what must be TRUE):

  1. 이용자가 크롬 웹스토어 비공개 링크로 자기 PC에 확장을 설치했고(회사 PC 설치 정책 확인 포함, 설계 11장 ②), 설치 화면에서 모든 사이트 권한이 필요한 이유를 안내받았다
  2. 이용자가 연습 사이트 과제(작은 버튼 10개 누르기, 양식 하나 채우기)를 확장 없이 할 때와 있을 때의 시간과 잘못 누른 횟수가 기록되어 있다
  3. 시험 결과로 조정한 기본값이 반영된 새 버전이 연습 사이트 시험을 모두 통과한 뒤 지연 게시로 공개되었고, 웹스토어 롤백으로 되돌리는 절차가 확인되었다
  4. 이후 순서(Phase 3~6)를 그대로 갈지 조정할지 결정과 그 이유가 기록되어 있다

### Phase 3: 이동·입력·컨디션

**Goal**: 이용자가 마우스 없이 명령판과 키로 이동·되돌리기를 하고, 긴 입력 양식을 큰 칸 화면과 최근 값·문구 카드로 빠르게 채우며, 그날 손 상태에 맞는 설정 묶음을 한 번에 고를 수 있다
**Mode:** mvp
**Depends on**: Phase 2
**Requirements**: CLICK-05, SAFE-06, STOR-03, STOR-04, NAV-01, NAV-02, NAV-03, NAV-04, NAV-05, NAV-06, INPT-01, INPT-02, INPT-03, PRIV-01, PRIV-02, PRIV-03, PERS-01, PERS-02, PERS-03
**Success Criteria** (what must be TRUE):

  1. 이용자가 0으로 명령판을 열어 큰 번호 카드와 키 안내 카드를 보고, ↑↓ 스크롤·링크 이동 직후 Esc로 뒤로 가기·입력 되돌리기·번호 고정과 "다음 번호"·더블클릭을 키만으로 할 수 있다
  2. 입력칸을 누르면 그 칸의 최근 값과 자주 쓰는 문구가 번호 카드로 떠 Alt+1~9로 고를 수 있고, 비밀번호·인증번호 칸과 번호 모양 값이 든 주민·계좌·카드 칸에서는 카드가 뜨지 않고 값이 기록되지 않으며, 이용자가 사이트별로 민감칸을 경고 확인 후 풀 수 있다
  3. 연습 사이트의 긴 양식을 "양식 한 장 보기"의 큰 칸에서 채우면 값이 원래 칸에 들어가 사이트가 알아채고, "원래 화면으로"로 돌아와 원래 화면에서 제출한다
  4. 처음 설치 맞춤 설정으로 떨림 간격·머무르기 시간이 재어져 "좋은 날 / 힘든 날" 묶음(자동 순서 강조 포함 조작 방식)이 정해지고, 명령판에서 한 번에 전환되며, 키 배치와 사이트별 위험 버튼 단어를 바꿀 수 있다
  5. 이용자가 설정을 파일로 내보내 다른 브라우저(크롬↔엣지↔웨일)에서 가져올 수 있고, 동기화 용량을 넘기 전에 알림과 문구 내보내기 안내가 뜬다

### Phase 4: 틀 자동화 + 활동 기록

**Goal**: 이용자가 반복 업무를 한 번 해 보여 틀로 저장하고, 이후 "틀 고르기 1번 + 바뀌는 값 2~3번 + 제출 확인 1번"으로 끝내며, 되돌릴 수 없는 제출은 항상 확인 뒤에만 한 번만 일어나고, 문제가 생기면 활동 기록으로 추적할 수 있다
**Mode:** mvp
**Depends on**: Phase 3
**Requirements**: TMPL-01, TMPL-02, TMPL-03, TMPL-04, TMPL-05, TMPL-06, TMPL-07, TMPL-08, TMPL-09, TMPL-10, TMPL-11, TMPL-12, TMPL-13, TMPL-14, TMPL-15, TMPL-16, LOG-01, LOG-02, LOG-03
**Success Criteria** (what must be TRUE):

  1. 이용자가 연습 사이트의 양식(iframe 안 양식 포함)을 한 번 입력해 틀로 저장하면(바뀌는 값 후보·제출 단계 자동 표시), 이후 0 → 틀 실행 → 번호 → 값 2~3개 → 제출 확인 1번으로 같은 업무가 끝나고, 속도 3단계를 ←→로 바꾸고 Esc로 멈출 수 있다
  2. 제출 직전에 항상 멈춰 큰 글씨 요약이 뜨고 Enter로만 제출되며, 결과가 불분명한 제출과 실행 중 백그라운드를 강제로 재운 뒤 이어 가기 모두에서 재제출 없이 "확인 필요"가 표시된다
  3. 틀 실행 중 제출 직후 첫 확인 창만 자동 "확인"되고 이어지는 예상 밖 확인 창은 "취소" 후 멈춰 창의 글을 보여 주며, 틀 밖 평소 사용에서는 알림 창을 가로채지 않는다
  4. 모양이 바뀐 페이지에서 틀이 멈추고 "이 단계만 다시 기록"으로 고칠 수 있으며, 민감칸·보안 키패드·자동입력 방지 문자에서는 멈춰 이용자가 직접 하고, 같은 틀 두 번 실행은 막히며, 틀을 고정 값 경고와 함께 파일로 내보내고 가져올 수 있다
  5. 최근 2주 동작이 입력 값 없이 이 PC에만 기록되고, 이용자가 내보낼 내용을 먼저 보고 확인한 뒤 파일로 저장하며, 되돌리기 횟수·틀 한 번에 누른 횟수 주간 통계를 볼 수 있다

### Phase 5: 작업판·뒤에서 실행·반복 패턴 알림

**Goal**: 이용자가 틀을 뒤쪽 탭에서 돌리는 동안 다른 탭에서 계속 일하고, 탭·자주 가는 곳·진행 상황·확인 대기를 작업판 한 곳에서 번호로 처리하며, 틀로 만들 만한 반복을 도우미가 알려 준다
**Mode:** mvp
**Depends on**: Phase 4
**Requirements**: BORD-01, BORD-02, BORD-03, BORD-04, BG-01, BG-02, BG-03, PATN-01
**Success Criteria** (what must be TRUE):

  1. 이용자가 명령판이나 단축키로 작업판을 열어 열린 탭과 고정한 자주 가는 곳을 큰 번호 카드로 보고 번호로 이동·닫기를 할 수 있다
  2. 이용자가 틀을 뒤쪽 탭에서 돌리며 다른 탭에서 일하는 동안 작업판에 진행 상황이 보이고, 값 고르기·제출 확인이 필요하면 확인 대기에 쌓여 번호로 불러와 처리할 수 있으며, 숨은 탭에서의 실행 속도 측정 결과(설계 11장 ③)가 기록된다
  3. 뒤에서 도는 탭이 닫히거나 로그아웃되면 그 틀이 멈추고 작업판에 이유가 표시되며, 틀에 이미지·광고 차단을 켜면 그 탭에서만 요청이 막힌다
  4. 같은 사이트 같은 입력칸 묶음에 틀 없이 3번 입력하면 "이걸 틀로 저장할까요?"를 한 번 묻고, 거절한 패턴은 다시 묻지 않는다

### Phase 6: 화면 정리 (AI)

**Goal**: 이용자가 처음 보는 복잡한 화면에서 명령판의 "화면 정리"를 누르면 중요한 요소 9개에 번호가 붙고, AI가 없거나 실패해도 나머지 기능은 그대로이며, 개인정보와 입력 값은 밖으로 나가지 않는다
**Mode:** mvp
**Depends on**: Phase 5
**Requirements**: AI-01, AI-02, AI-03, AI-04, AI-05, AI-06
**Success Criteria** (what must be TRUE):

  1. 이용자가 명령판에서 "화면 정리"를 누르면 중요한 요소 9개에 1~9 번호표가 붙고, 같은 사이트·같은 페이지 주소를 다시 열면 AI를 다시 부르지 않고 저장된 번호를 쓴다
  2. AI로 보내는 요청에 입력칸 값이 없고 이메일·전화번호·긴 숫자 모양이 가려져 있는 것이 시험으로 확인된다
