# 휴대형 손 실행기와 민감 정보 저장 결정

**상태:** 승인됨  
**승인일:** 2026-09-28  
**범위:** 브라우저 확장과 함께 쓰는 휴대형 Windows 실행기, USB 기준 저장소, 민감 정보 정책

## 결정

### 1. 휴대형 Windows 실행기

- 정식 실행기는 C# 단일 실행 파일로 만들고 USB 메모리나 외장 SSD에서 실행한다.
- 대상 PC에 .NET이나 AutoHotkey를 따로 설치하지 않고, 관리자 권한도 기본으로 요구하지 않는다.
- 실행기는 브라우저 확장이 고른 대상을 실제로 조작하는 **손**이다. 웹 요소의 이름·위험 여부·최신 위치를 판단하는 **눈과 판단**은 확장이 계속 담당한다.
- 실행기가 없거나 실행이 차단되어도 확장의 기존 기능은 계속 동작한다.

### 2. 실행 중에만 임시 연결

- `시작하기.exe`가 현재 USB 경로와 파일 무결성을 확인하고, 현재 사용자 범위에 확장 연결을 임시 등록한 뒤 실행기를 시작한다.
- USB 드라이브 문자가 PC마다 달라도 매번 현재 위치로 등록한다.
- 안전 종료는 반복·드래그·키 입력을 멈추고, 눌린 입력을 해제하고, 연결 등록을 제거하고, USB 쓰기가 끝났음을 확인한 뒤 제거 가능 상태를 알린다.
- 임의 명령·파일·프로그램 실행은 받지 않는다. 허용된 동작, 일회용 요청 번호, 짧은 유효시간만 받으며 같은 요청은 두 번 실행하지 않는다.

### 3. 첫 실행 범위

- canvas 내부 비율 좌표의 클릭·더블클릭, 마우스 이동, 누르기·놓기, 드래그, 휠 스크롤
- 브라우저 주소창과 탭 표시줄: 탭 선택, 새 탭, 닫기, 닫은 탭 다시 열기
- Windows 파일 열기·저장 창: 파일 이름, 폴더 이동, 열기·저장·취소
- 전역 긴급 정지, 활성 창·허용 브라우저 재확인, 요청 만료·중복 거부, 최대 반복 횟수, USB 제거 대응
- Windows 프로그램 전체 자동화는 첫 범위에 넣지 않는다.

### 4. USB가 설정의 기준 원본

- USB/외장 SSD 설정이 기준 원본이다. 브라우저 저장소에는 USB가 없을 때 쓸 비민감 기본 설정과 실행 중 필요한 최소 복사본만 둔다.
- 키 배치, 떨림·머무르기 설정, 사이트 설정, 고정 번호, 문구, 입력칸 보호 설정, 일반 웹 바로가기, canvas 좌표, 자동화 단계와 이용자가 허용한 값을 USB에 저장할 수 있다.
- USB 쓰기가 실패하면 성공으로 표시하거나 브라우저 복사본만 기준 원본으로 만들지 않는다. 이용자에게 실패를 알리고 이전 USB 원본을 보존한다.
- USB가 빠지면 새 자동화를 막고 진행 중 동작을 일시정지하며 눌린 입력을 해제한다.

### 5. 이용자가 민감도를 정한다

입력칸·문구·사이트·바로가기·canvas 동작·자동화 단계마다 다음 중 하나를 정할 수 있다.

- **일반:** USB 저장·화면 표시·일반 내보내기 허용
- **보호:** USB에 암호화해 저장하고 잠금 해제 뒤에만 표시·사용하며 일반 내보내기에서는 제외
- **민감:** 기본값은 값·최근 입력·로그·동기화·내보내기 모두 금지하고 실행 때 직접 입력

모든 종류의 정보는 이용자가 항목별 위험 경고를 확인하고 명시적으로 고르면 보호 상태로 암호화 저장할 수 있다. 여기에는 비밀번호, OTP·인증번호, 보안카드, 카드 보안번호, 쿠키, 로그인 토큰, 개인 키, CAPTCHA 관련 값도 포함된다.

단, 저장 허용은 자동 실행 허용이 아니다. 로그인 완료, 인증, 금융 이체, 결제, 카드 등록, 비밀번호 변경, 계정 복구·삭제, 보안 설정 변경, 개인정보 제출은 별도 확인 없이는 자동 실행하지 않는다. 보안 키패드와 CAPTCHA를 대신 풀거나 우회하는 기능도 만들지 않는다.

### 6. 잠금과 표시

- 프로그램 시작 때 PIN 또는 암호를 한 번 입력한다.
- 성공하면 프로그램을 종료할 때까지 잠금을 유지한다. Windows 화면을 잠갔다가 다시 열어도 PIN을 다시 묻지 않는다.
- 안전 종료, 비정상 종료, USB 제거, Windows 로그아웃·종료, 이용자의 `지금 잠그기` 또는 `잠그고 중지`에서는 즉시 잠근다.
- 보호 값은 기본적으로 가리고, 실제 값 보기는 별도 동작 뒤 짧게만 허용한다.
- PIN 원문, 복호화된 임시 파일, 실제 비밀값이 든 로그를 남기지 않는다. 검증된 표준 암호화만 사용하고 구체 규격은 구현 전 보안 검토에서 확정한다.

## 기존 결정과의 관계

- “민감한 값은 저장하지 않는다”는 기존 원칙을 이 결정으로 대체한다. 새 기본값은 여전히 저장 금지지만, 이용자가 항목별로 승인하면 암호화 저장할 수 있다.
- “첫 버전은 브라우저 확장 하나”는 “브라우저 확장이 독립적으로 동작하고, 휴대형 실행기는 선택적으로 실제 입력 범위를 넓힌다”로 바꾼다.
- 서버를 운영하지 않는 원칙은 유지한다. 보호 데이터의 기준 원본은 이용자의 USB/외장 SSD다.

## OPEN

- PIN 최소 길이·허용 문자·실패 대기·복구 키 정책
- 암호화 알고리즘, 키 유도 방식, 파일·백업 형식, 손상 복구 방식
- Chrome·Edge·Whale의 임시 연결 등록 방식과 정책 차이
- 회사 PC의 USB 실행·사용자 범위 등록·코드 서명·보안 프로그램 정책

## BLOCKED

현재 차단 항목은 없다. 특정 PC 정책이 USB 실행이나 임시 연결 등록을 막으면 그 PC의 휴대형 실행기만 차단되며 확장 단독 기능은 유지한다.
