## 목표와 범위

뇌병변 장애가 있는 이용자가 손을 최대한 움직이지 않고 웹 활동을 이어간다. 필수 조작은 **스페이스바 한 번 누르고 놓기**뿐이다. 길게 누르기·더블클릭·조합키·정밀한 마우스 이동은 요구하지 않는다. 기존 마우스 자석·떨림 필터·dwell을 보존하며 한 동작은 한 번만 실행한다.

첫 완료 기준은 지원 웹페이지에서 **새 한글 검색어 작성 → 한 글자 수정 → 검색 → 결과 선택 → 본문 읽기·스크롤 → 뒤로 → 열린 다른 탭으로 이동**을 스페이스바만으로 끝내는 것이다. 취소·쉬기·재개·복구·속도 조절도 같은 조작으로 가능해야 한다. 설치·권한 부여·브라우저 실행은 준비 조건이고, 지원 페이지에 포커스가 있는 상태부터 검증한다. 모든 사이트 지원은 약속하지 않는다.

1차는 브라우저 내부 활동이다. 파일 선택창·브라우저 밖 조작·휴대용 실행기는 1차 검증 뒤 2차, 반복 업무 자동화는 그다음이다. 음성 읽기와 예측 입력은 첫 완료의 필수 조건이 아니다.

## 작업판과 순환

상위 그룹은 **찾기 → 페이지 항목 → 읽기·이동 → 글쓰기 → 조절·쉬기**로 고정한다. 강조된 그룹을 한 번 선택한 뒤 항목을 한 번 선택한다. 하위 목록에는 `상위로`와 `쉬기`가 있고, 페이지 대상은 최대 6개씩 묶어 이전·다음 묶음으로 이동한다.

초기 제안은 항목당 1.5초, 조절 범위 0.8~4초, 새 목록 첫 항목은 2배 시간이다. 재입력 보호는 기본 300ms, 범위 100~1000ms다. 2회 순환 동안 선택이 없으면 쉬고, 다음 한 번은 재개에만 소비한다. 무입력은 동의가 아니다. 실제 사용자 시험으로 값을 조정하며 자동으로 속도를 바꾸지 않는다.

그룹과 명령의 순서는 고정한다. 페이지 대상은 프레임 경로·DOM 순서의 스냅샷으로 만들고 순환 중 재정렬하지 않는다. 새 대상은 `목록 새로 읽기`에서 반영한다. 사라진 대상은 같은 자리에 사용 불가로 표시한다. keydown에서 강조 대상을 고정하고 keyup에서 한 번 선택한다. 반복·합성 키 이벤트는 실행 근거로 사용하지 않는다.

화면은 기존 `docs/design/SYSTEM.md`와 토큰을 사용한다. 큰 글자·굵은 강조 테두리·상태 글자로 구분하고 색에만 의존하지 않는다. 지속 작업판의 배경 면은 기존 ‘확인 외 사이트를 덮지 않음’ 규칙과 충돌할 수 있으므로 구현계획에서 배치·가림 범위를 디자인 결정으로 명시해야 한다.

## 공통 엔진과 실행 계약

입력 → 순수 상태 엔진 → 실행 판정 → 페이지/탭 어댑터 → 결과 이벤트 → 화면으로 흐른다. 상태는 `ready`, 그룹/항목 순환, 조합, 확인, 실행, 자동 스크롤, 쉬기, 복구를 구분한다. 타이머는 강조 이동과 허용된 스크롤만 수행하며 클릭·제출을 확정하지 않는다.

실행 요청은 `actionId`, 모드 세대, 탭·프레임·문서 세대, 대상 ID를 갖는다. 실행 직전에 대상 연결·활성 상태·의미·위험 상태를 다시 검사한다. 같은 ID는 대상 프레임에서 한 번만 수락하고 수행 중 추가 실행을 차단한다. 완료·거절·결과 불명을 구분하며 결과 불명은 자동 재전송하지 않는다.

최상위 작업판이 순환을 소유하고 프레임은 입력·대상 보고와 검증된 실행을 담당한다. worker는 송신자와 탭·프레임을 검증한다. 페이지/프레임 교체 시 옛 대상과 대기 실행을 무효화한다. 지원 불가 페이지나 비신뢰 클릭을 거절하는 사이트는 정지·지원 불가로 표시한다.

스페이스를 작업판이 소비했으면 페이지 스크롤·클릭에 전달하지 않는다. 단일 스위치 조작 중 기존 dwell 실행을 정지하고 전환 시 타이머·눌림 상태를 초기화한다. 마우스 보조 방식도 공통 실행 경계를 사용해 키·dwell 경합과 합성 클릭 재수집으로 인한 중복 실행을 막는다.

## 한글 작성과 작업 보존

작업판에서 **초성 → 중성 → 종성(없음 포함)**을 선택해 완성형 음절을 만든다. 쌍자음·겹모음·겹받침을 포함한다. 문자 공백은 `띄어쓰기` 항목이며 물리 스페이스는 선택 입력이다. OS IME 입력을 흉내 내지 않는다. 일반 키보드 모드의 composition 중 스페이스는 스캔 선택으로 해석하지 않는다.

편집은 조합 한 단계 취소, 앞/뒤 한 글자 이동, 앞 글자 삭제, 실행 취소, 저장 문구 삽입, 입력칸 적용을 제공한다. 삭제 단위는 화면에 보이는 한 글자다. 처음 지원할 입력은 일반 input/textarea와 검색칸이다. 복잡한 contenteditable·문서 편집기는 별도 검증 전까지 새 조합 입력 지원을 약속하지 않는다.

입력칸의 값과 선택 범위를 기억하고 버퍼에서 작성한다. 적용 전에 대상과 원래 값을 검사한다. 외부 변경·프레임 교체가 있으면 덮어쓰지 않고 초안을 남긴다. 취소·쉬기·모드 이동은 미완성 조합·작성문·편집 위치를 보존하며 버리기는 명시 동작이다. 페이지 이동 뒤에는 초안만 복구하고 옛 대상에 자동 적용하지 않는다.

초안은 탭별 세션 범위, 명시적으로 저장한 문구와 설정은 로컬 저장이다. 자동 동기화하지 않는다. 비밀번호·민감 입력은 초안 저장·문구 수집에서 제외한다. 브라우저 종료 뒤 임시 초안 복구는 1차 보장이 아니다.

## 취소·확인·복구

쉬기·blur·탭 숨김·탭 전환은 순환·dwell·자동 스크롤과 미완료 눌림을 정지한다. 재개 입력은 실행하지 않고 대상을 재검증한다. 자동 스크롤 중 첫 입력은 **정지에만** 소비한다. 페이지 밖 주소창·브라우저 메뉴·OS 창에서 전역 정지를 보장하지 않는다.

위험한 제출·삭제와 의미가 불명확한 버튼은 실제 동작 이름·대상을 보여 준다. 진입 키를 놓고 1초 보호 뒤 `취소 → 실제 동작명`을 순환하며 새로운 한 번 누르고 놓기로만 확정한다. dwell·시간 경과로 확정하지 않는다. 2회 무입력 순환은 확인을 취소하고 쉰다. 안전한 링크·읽기는 추가 확인 없이 실행한다. 확인 이후에도 실행 직전 위험·의미를 재검사한다.

확장 재연결·응답 유실·worker 재시작은 실행 결과 불명으로 정지한다. 초안을 보존하고 사용자 재선택 전 재시도하지 않는다. 기존 위험 휴리스틱의 한계를 인정하고 검증 사이트의 제출·삭제 계약을 별도로 확인한다.

## 검증 가능한 완료 조건

1. 준비된 연습 사이트의 전체 활동을 실제 Space down/up만으로 완주한다. 다른 키·마우스·길게 누르기 0회, 기대하지 않은 클릭·제출 0회다.
2. 저장 문구에 없는 `안녕하세요`를 작성하고 공백·중간 수정·조합 취소·문구 삽입 결과를 문자열로 비교한다.
3. 반복 키·빠른 재입력·keyup 유실·dwell 경합·확인 진입 입력에서 의도한 실행 1회 이하, 무입력 확정 0회를 검증한다.
4. DOM 삭제/삽입·프레임 이동·뒤로·탭 전환·모드 전환에서 옛 대상 실행 0회, 초안 보존, 재개 입력의 실행 0회를 검증한다. 자동 스크롤 첫 입력은 정지만 수행한다.
5. 기존 자석·떨림·dwell·입력·확인 회귀, CI 프로덕션 확장 로드, 실제 DOM 접근성과 디자인 기준을 검사한다.
6. 실제 PC에서 한글 IME 공존과 사용자 피로·오선택·속도 조절을 따로 확인한다. 클라우드 자동 검사를 실제 운동 사용성 검증으로 대체하지 않는다.
