# 단일 스위치 메뉴 정책 분리·짧은 고정 진입 설계

2026-10-04 KST · 상태: 권장 방향 B 승인 후 작성한 **구체 명세·구현 전 검토안**. 이번 지시는 명세와 구현 계획을 함께 문서화하는 범위다. 아래 세부 배치와 실행 계획까지 승인됐다는 뜻은 아니다. [구현 계획](../plans/2026-10-04-switch-menu-policy.md)을 함께 검토하고 제품 코드 변경 전에 대기한다.

## 1. 목적·근거·범위

짧은 Space 누름 하나로 브라우저 활동을 이어가면서 선택 대기를 줄인다. 실행·안전·초안 모델은 보존하고 메뉴 경로를 먼저 개선한다. 타이머만 줄이는 안은 선택 경로를 해결하지 못하고, 전체 재작성은 기존 안전 검증을 불필요하게 넓힌다. 작은 메뉴 개선으로 충분하면 더 큰 재설계를 멈춘다.

원격 대조: 제품 `62577af2db1216bc25371dee39d94b6267a80a8c`, 측정·문서 기준 `283572609b7662f78dac569ab885f03a876a89bb`, main `9394b0146f9ba169f57e47ce3274bdff57b74dfe`. PR39는 연결된 GitHub 도구로 draft/open/미병합 확인. 기존 [측정 결과](../../verification/browser-speed/RESULTS.md)와 [원본](../../verification/browser-speed/raw-results.json)이 근거다. 이전 로컬 분석의 결정을 이 명세에 옮겨 로컬 임시 파일에 의존하지 않게 한다.

기본1500ms/300ms, 각3회 합성 측정 중앙값은 클릭10.92초, 스크롤7.79초, 탭20.11초, 새탭18.72초, 고정 재사용30.85초, 문구35.83초, `가a1`86.59초다. 이는 사람·Windows IME의 속도가 아니다. `가a1`은 편집기로3회 복귀하며 ASCII75자를13그룹으로 탐색한다. 연속 키보드는 이 병목을 다루는 후속 단위이며 이번 첫 구현에 섞지 않는다.

첫 범위 B1: 순수 메뉴 정책 분리 → 기존 경로와 선택 가능한 짧은 고정 첫 메뉴 → 안전한 프로필 전환·Space 복귀 → 관련 회귀 검증. 확인 화면의 상위로 제거, 목록 내용 우선 배치, 탭4슬롯 고정, 숫자 재배치, 수동 즐겨찾기 편집, 문구-필드 결합은 후속 후보다. 이전 분석의 최종 후보 시간 모델을 축소된 B1의 예상 성능으로 인용하지 않는다.

## 2. 유지할 계약

- 실행 권한/대상 동일성/문서 세대/일반 버튼 확인/1초 확인 보호/결과 불명 자동 재시도 금지/초안 보존 유지.
- 고정 메뉴와 한 종류의 짧은 Space, 순환 중 재정렬 금지.
- 첫 비교는 순환1500ms/입력 보호300ms, 첫 항목2배 체류와 기존 확인 보호를 유지한다.
- 기존 경로 기본값과 Space 복귀, 파괴적 설정 전환 없음.
- 새 의존성·권한·서버 없음. 기존 TypeScript strict/WXT/Vitest/Playwright와 pnpm10.33.0 사용.
- 자동예측/자동배치/음성·시선/길게·더블누름 필수화는 범위 밖이다.
- merge·배포·설치 ZIP 교체는 범위 밖이다.

keydown 고정 대상→keyup1회, repeat/composition/수정키/비신뢰 입력 배제, executing·scrolling 중 첫 Space 정지, blur/pagehide 취소를 유지한다. pending/unknown을 UI 변경으로 초기화하지 않는다. 신원·값이 바뀐 입력칸에 자동 적용하지 않고 재적용 확인·오래된 초안의 revision·불명 iframe 보존을 유지한다.

## 3. B1 고정 배치와 기존 규칙 개정

[phase1 §4](2026-10-01-single-switch-phase1-design.md)의 다섯 그룹·하위 첫 상위로 규칙은 legacy 기본에 계속 적용한다. 첫 리팩터는 label/ID/순서/스택/부작용 trace를 그대로 유지한다. 새 프로필 도입 뒤 legacy 조절 메뉴 끝에 `메뉴 배치` 진입1개를 추가하는 것만 명시적 예외다. 기존 명령 간 순서는 바꾸지 않는다.

| B1 첫 메뉴 순서 | 기존 실행 ID/경로 | 의미 |
|---|---|---|
| 페이지 항목 | `group:1` | 기존 refreshTargets→pageMenu. 대상 선택·확인 그대로 |
| 입력칸 | `form-open` | 기존 openForm. 텍스트뿐 아니라 지원 폼 컨트롤 목록 |
| 고정 번호 | `pins-list` | 기존 읽기·미리보기·확인·최종 신원 검증 그대로 |
| 스크롤 | 새 로컬 `menu:scroll` | 현재 페이지 영역 초기화 후 아래/위/자동/영역 선택 |
| 탭 | `nav:tabs` | 기존 조회·목록·선택. 권한 itemId를 새 별칭으로 바꾸지 않음 |
| 더보기 | 새 로컬 `menu:more` | 기존 다섯 그룹을 그대로 제공 |
| 쉬기 | `pause` | 기존 중지·보존 |

고정 번호를 아직 문구와 합치지 않으므로 `자주쓰기`라는 넓은 이름을 쓰지 않는다. 스크롤 하위 순서는 `상위로 / 한 화면 아래 / 한 화면 위 / 자동 스크롤 / 세로 스크롤 영역 선택 / 쉬기`. 더보기는 `상위로 / 찾기 / 페이지 항목 / 읽기·이동 / 글쓰기 / 조절·쉬기 / 쉬기`. 새탭·검색·문구·복구·끄기·마우스 전환 등 기존 모든 명령은 더보기에서 접근 가능하다. 비용이 늘어나는 경로도 숨기지 않는다.

다른 하위 목록·확인·편집 메뉴는 기존 builder를 유지한다. 일반 버튼 확인은 현재 `상위로 / 취소 / 실행 / 쉬기` 그대로다. formMenu는 이미 내용 우선인 예외이며 별도로 변경하지 않는다. 대상 목록은 기존 snapshot/명시 새로읽기 계약을 유지한다. formActive일 때 root가 양식으로 돌아가는 기존 규칙도 유지한다. 양식을 나간 뒤에만 첫 메뉴로 간다.

순서·스캔 위치는 고정하며 비활성 대상 때문에 뒤 항목을 당기지 않는다. 키를 누른 동안 프로필/메뉴 전환 금지. 새 메뉴는 기존 setItems 경계를 통해 이전 선택을 무효화한다. 기존 토큰·Shadow DOM·큰 글자·색 외 강조·강조 항목 내부 스크롤을 재사용한다. 새 토큰이나 레이아웃 템플릿은 만들지 않는다.

정책에서 canonical ID를 그대로 반환하고 기존 handler로 보내야 한다. 특히 nav 요청은 pendingAction.itemId와 kind를 묶어 검증하므로 `menu:tabs` 같은 실행 별칭을 추가하지 않는다. 새 menu ID는 로컬 화면 전환만 가능하며 직접 DOM·tabs API·worker 요청을 발행하지 않는다. 스크롤 단축 경로도 기존 영역 선택·stop 코드를 우회하지 않는다. 이것은 컨트롤러 전체 분해가 아니다.

## 5. 프로필과 복귀

키 `switchInteractionProfile`, 값 `{schemaVersion:1, layout:'legacy'|'short-menu-v1'}`. pins/문구 참조나 사용 빈도는 저장하지 않는다. 없거나 잘못되거나 미래 버전이면 **현재 세션 legacy로 해석만** 하고 원본 키와 mode/interval/protection은 덮어쓰지 않는다. 읽기 실패도 legacy이며 설치 전체 설정 초기화 금지.

진입: 두 배치 모두 기존 `조절·쉬기 → 메뉴 배치`. 미리보기는 `상위로 / 기존 메뉴 / 짧은 메뉴 / 쉬기`, 선택하면 해당 고정 순서를 제목/본문으로 보여 주고 `취소 / 이 배치 사용 / 쉬기`로 확인한다. 1초 보호와 새 짧은 Space를 적용한다. 취소는 현재 배치를 유지한다.

전환 절차: 선택 키가 놓인 뒤 held 없음·외부 inFlight0·unresolved false·다른 확인/컨트롤 변경 없음을 검사 → stashField로 초안 보존 → 기존 pause와 세대 무효화 → paused/pressed null/pendingAction null 재검사 → 별도 키 저장 → 같은 전환 세대이고 여전히 안전할 때만 새 root를 구성하고 paused 유지. 다음 Space는 재개만 한다. 프로필 선택 자신의 로컬 command를 외부 실행으로 오인해 영구 차단하지 않되 다른 pending action을 지우고 통과시키지 않는다.

저장 실패는 기존 배치·초안 유지 및 실패 안내. 비동기 응답 중 문서/모드 세대가 바뀌면 새 화면을 설치하지 않는다. 외부 storage 변경은 지금 UI를 강제 전환하지 않고 다음 안전한 초기 진입에서 읽는다. 사용자 입력보다 늦게 끝난 초기 읽기도 활성 스캔을 바꾸지 않는다. 다른 탭의 진행 중 작업을 멈추거나 재시도하지 않는다. 프로필 key는 UI 선택일 뿐 실행 승인으로 쓰지 않는다.

partial Hangul/selection/history/field drafts/orphan drafts/formOrigin/formRecovery/unresolved 상태를 공통 모델에 유지한다. 결과 불명 상태에서는 전환을 거절하고 먼저 기존 복구 경로를 안내한다. 긴급 Space 정지는 항상 가능하다. root→더보기→조절·쉬기→메뉴 배치→기존 메뉴로 짧은 Space 복귀 가능해야 한다. 폼 컨트롤 미적용 변경이 있으면 양식에서 적용/취소 후 전환한다.

| 단계 | 주평가 | 반드시 공개할 회귀·손실 | 해석 제한 |
|---|---|---|---|
| B1 | 클릭·탭전환·고정 재사용·스크롤 각각20쌍, 총80쌍 | 새탭·저장문구의 기존 더보기 경로, `가a1` 직접 입력칸 경로와 더보기 글쓰기 경로를 각각3쌍. 아래 긴 한글·숫자·URL·수정은 각각1쌍 | 소표본은 도달성·큰 손실 탐지 근거이며 성능 동등/개선 합격 근거 아님 |
| K1 안정 후 | 고정한 긴 한글·숫자·URL·수정4과제 각각20쌍을 이 단계에서 한 번 수행 | `가a1` 혼합 회귀 및 첫/연속·전환·복구 비용 별도 보고 | B1의1쌍을20쌍에 섞지 않고 동일 K1 후보에서 대조 재측정. 새탭/문구는 바뀌는 B2에서 별도 사전 계획 |

B1의3쌍 경로 회귀를 먼저 수행한다. 손실/추가 누름이 채택 기준을 위반하면 후보 전체의 채택을 중단하고 나머지 성능 측정은 미실행으로 보고한다. 안전 회귀 검사는 계속 유지한다. 손실 경로만 빼고 남은 경로를 합격시키거나 측정 후 과제/표본을 교체하지 않는다. 사용자 검토로 수정된 새 후보는 변경한 범위·이유를 먼저 기록한 뒤 새 판정으로 시작한다. 심각한 실패·안전 회귀는 표본 채우기보다 즉시 중단·보존한다.

B1 경로 모델을 모든 기존 기능에 적용해 ID·선택 index·Space·대기량·복귀 경로를 기록한다. 짧은 입력칸 진입은 기존 글쓰기→양식보다 짧아질 수 있지만 더보기→글쓰기는 길어진다. 두 경로를 분리하고 빠른 경로만 대표로 고르지 않는다. 현재 명목 모델은 더보기 경유 새탭/문구/글쓰기에서 약10.5초·Space1회 증가, 스크롤 약9.09초로 기존 실측7.79초보다 불리하다. 이는 아직 실측 비교가 아니며 B1 배치를 수정해야 할 가능성을 드러내는 검토 근거다.

**실행 비용 추산:** 현재 자판의 index별 대기를 `i=0:0.3초`, `i>0:(i+1)×1.5초`로 합산하고 누름당0.03초를 더한다. 빈 양식 진입12.3초+적용10.5초, resume 포함 진입/적용5누름 기준. 한글은 매음절 진입+초/중/종성 그룹·문자7선택, ASCII는 진입+그룹·문자3선택. 계획의34자 한글948.15초/195누름, 숫자18자522.57초/59누름, URL33자724.92초/104누름: 각각20쌍(40회)을 기존 자판으로 수행하면 합계24.40시간이다. K1 후보가 빨라져도 legacy 절반만12.20시간이다. VM/IPC/읽기/오류/복구 비용은 빠진 경로 모델이며 실측·보장이 아니다.

B1은 이 세 과제 각각1쌍으로 약73.2분, 주평가80쌍은 기존 실측과 B1 모델을 합쳐 약36.5분, 짧은 경로 회귀12쌍은 약23.9분: 합계 약133.6분에 수정 과제·준비·부하/복구 비용이 더해진다. 손실로 조기 중단하지 않고 전부 수행할 때의 비용이다. 같은 조건으로 세 긴 과제를20쌍씩 반복하는 것보다 약23.2시간을 줄이며, 충분한 문자 성능 판정은 실제 자판이 바뀐 K1에 집중한다. 안전 E2E·최종 CI 비용은 별도이며 줄이지 않는다.

처음 리팩터/문서 단계에서20쌍이나 전체 장기 CI를 반복하지 않는다. 기존 타입·린트·단위·관련 프로덕션 E2E를 유지하고, 기능 통합·독립 검토 후 최종 안정 후보 전체 CI를 한 번 수행한다. 새 변경·실패가 있으면 영향 검사를 재수행한다. 실제 DOM 접근성/디자인 감사와 실행 권한 경계 검토는 구현 시 필요하다.

중복 실행·초안 손실·민감정보 노출·확인 우회는1건도 허용하지 않는다. 발견 시 후보 채택 중단, 안전하게 pause하고 미해결 작업을 지우지 않은 채 legacy로 복귀한다. 추가 누름/복구 부담 증가도 채택 중단 사유다. 코드 revert는 해당 증분만, 저장 키/초안/문구/번호 삭제 없이 수행한다. 실제 사용 전 기본값은 계속 legacy다.

## 7. 후속 단위와 검토 경계

B2(별도 명세): 내용 우선 목록/탭 묶음/고정 번호·문구 단축. B1 측정에서 남은 병목에만 적용하며 확인 계약과 필드 명시 선택을 유지한다.

K1(별도 명세·계획): 지속형 한글/영문/숫자 키보드. B1 정책 경계·프로필 복귀·안전 trace가 안정된 뒤 TextDraft/부분 조합/모든 자모·기호 도달성을 먼저 고정한다. UI 배치만 보고 바로 구현하지 않는다. 글쓰기 목표를 메뉴 개선으로 달성했다는 주장은 하지 않는다.

이번 검토 결정은 B1 배치·범위와 계획 실행 방식이다. 직접 실행을 권고하되 제품 코드 변경은 문서 검토 응답 뒤 시작한다. 독립 검토는 별도 실제 수행 결과로 남긴다. 실제 PC/사용자 평가 일정은 구현 전 차단 조건이 아니라 최종 채택 전 필요한 검증이다.
