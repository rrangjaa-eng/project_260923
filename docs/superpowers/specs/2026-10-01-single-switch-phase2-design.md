## 사용자 흐름과 화면

클라우드 시제품은 고정 시험 파일 목록을 사용한다. 실제 디스크 경로나 파일 내용은 읽지 않고 외부로 보내지 않는다. 화면 제목에 `실행기 시제품 · 실제 파일/OS 입력 없음`을 지속 표시한다.

1. 시험 페이지에서 `파일 선택`을 스위치로 고른다. 원래 탭·문서·입력 대상과 현재 초안을 보존한다.
2. 실행기 화면에는 `연결 상태 / 요청한 페이지 / 작업 상태 / 마지막 결과`를 고정 표시한다. 그룹은 `파일 / 취소 / 조절·쉬기 / 안전 종료`다. 파일 목록은 고정 순서, 6개 묶음이며 화면 변화가 선택 중 대상을 바꾸지 않는다.
3. 파일 한 개를 고르면 확인 화면에서 **파일명과 폴더, 요청한 페이지, “이 사이트는 파일을 즉시 보낼 수 있어요”**를 보여 준다. 취소가 먼저 순환한다. 1초 보호 후 새 Space down/up만 확정한다. 무입력은 선택이나 동의가 아니다.
4. 확인 후 한 번만 선택을 적용한다. 클라우드에서는 가짜 provider가 선택 결과만 반환하고 시험 페이지가 선택된 시험 파일명을 보여 준다. `setInputFiles` 호출이나 가짜 결과를 사용자가 OS 파일 창을 Space로 조작했다는 증거로 쓰지 않는다.
5. 페이지 복귀 뒤 첫 Space는 재개에만 소비한다. 후속 제출은 별도 명시 입력이다. 취소/쉬기/연결 유실은 초안을 보존하고 파일 선택 승인은 폐기한다.

초기 설치·등록은 준비 작업이다. 실제 Windows 파일 창으로 포커스가 옮겨간 동안 페이지 확장의 Space listener는 동작하지 않으므로 C# 실행기 화면이 그 입력을 맡아야 한다. 기본 브라우저 모드와 실행기 모드가 한 입력을 함께 실행하지 않도록 소유권을 명시적으로 넘긴다. 페이지 밖 전역 정지는 지금 보장하지 않는다.

## 구성과 상태 계약

| 구성 | 책임 / 재사용 |
|---|---|
| 브라우저 어댑터 | 기존 documentGeneration·modeGeneration·pendingAction ID, 대상 재검증, 초안 유지. 웹페이지가 임의 OS 명령을 전달하는 API는 제공하지 않음 |
| 실행 조정기 | `idle → selecting → confirming → executing → done/cancelled` 및 `paused/unknown`. 동시 요청 1개, 자동 재전송 0회, 입력 소유자 1개 |
| 실행기 화면 | 연결/상태/현재 항목을 유지하며 Space 그룹→항목 순환. 기존 `switch-engine.ts`의 의미와 테스트 벡터를 재사용. C#에서는 동일 계약을 검증하되 TS를 직접 실행한다고 가정하지 않음 |
| provider | 첫 구현은 순수 가짜 파일 창/전송 어댑터. 후속 Windows 어댑터는 UI Automation의 이름·역할/창 소유 관계를 검증하여 접근. 좌표를 대체 실행으로 사용하지 않음 |

요청은 버전, 세션 ID, 요청 ID, 문서/모드 세대, 명령 종류, 실행 만료시각을 포함한다. 파일 경로는 페이지가 주는 문자열이 아니라 실행기에서 사용자가 선택한 항목에 붙인 임시 토큰이다. 가짜 provider도 이 경계를 검사한다. 허용 명령은 상태 조회, 파일 목록/선택, 선택 확정/취소, 쉬기/재개, 정지/종료뿐이다. 임의 쉘·프로그램·URL·파일 실행은 없다.

실행 만료와 응답 대기 시간을 구별한다. 전송 전 거절은 `refused`; 실행 전 최종 재검증 실패도 `refused`; 전달 후 응답 유실/부분 실행은 `unknown`이다. `unknown`은 자동 재시도하지 않고 `결과를 확인하세요`로 멈춘다. 연결 재생성은 새 세션으로 시작하며 옛 승인·큐·응답을 이어 실행하지 않는다. 처리한 요청 ID는 세션 종료까지 중복 실행을 막는다.

정지/안전 종료는 입력 큐보다 우선하며 정지 상태를 latch한다. 뒤에 쌓인 명령은 거절하고 버튼/키 해제는 포커스가 바뀌어도 허용한다. 재개는 새 명시 입력이며 옛 명령을 되살리지 않는다. OS 프로세스가 강제 종료됐을 때 해제가 실행됐다고 약속하지 않는다.

## 실제 Windows 연결 전 조건

Native Messaging은 별도 `nativeMessaging` 권한과 host 등록을 요구한다. service worker가 시작한 host는 `--parent-window`가 0일 수 있어 그 값으로 파일 창 소유자를 확정할 수 없다([Chrome 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)). 후속 Windows 설계에서는 브라우저 창·프로세스·요청 세션의 연결을 독립 검증하고, 실행기 확인 화면의 포커스에서 알려진 파일 대화상자로 돌아가 실행 직전에 다시 검사한다.

접근성 트리나 창 소유 관계가 모호하면 실행을 거절한다. 파일 열기가 즉시 업로드할 수 있으므로 경로 전달/열기 전에 확인한다. 첫 범위는 파일 한 개 열기·취소다. 저장/덮어쓰기, canvas·드래그, 주소창·모든 앱, 네트워크 경로 탐색, 보호 저장·PIN·인증정보는 후속이다. Windows 접근성의 실제 패턴 지원은 현장 검증이 필요하다([Microsoft UI Automation](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-uiautomationoverview)).

C# 자체 포함 단일 exe·관리자 기본 불필요·USB 실행 위치 기준·실행 중만 연결하는 상위 결정은 유지한다. 비정상 종료 시 등록은 남을 수 있으므로 “항상 자동 제거”를 약속하지 않는다. 후속 등록 설계는 복구 가능한 소유권 journal과 기존 등록의 보존·복원, 검증된 실행 파일만 시작하는 방식을 별도 확정해야 한다. 현재는 레지스트리, OS 보안, extension 권한, 인증정보를 변경하지 않는다.

## PR13/PR14 재사용 판단

[PR13](https://github.com/rrangjaa-eng/project_260923/pull/13) `39c695b`의 깨진 sync 설정에서도 local off override로 끄는 안전 계약은 참조한다. 당시 writer 조사 뒤 PR15에서는 손상 설정에도 동작하는 local 안전 off와 지연 켜기 경합 방지를 독립 구현·검증했다(CI67 제품3ae6ad2). PR13 구현을 복사한 것이 아니다. PR13 코드 복사/병합은 하지 않았으며 네이티브 입력 활성화 전에 별도 회귀·정합성 점검 대상이다.

[PR14](https://github.com/rrangjaa-eng/project_260923/pull/14) `f69f496`은 본문에 docs-only라고 쓰였지만 `Program.cs`, `InputExecutor.cs`, `NativeHostRegistration.cs`, `portable-hand.ts`, `publish.ps1`을 실제로 포함한다. 읽기전용 대조 결과 정지는 버튼 해제만 하고 후속 큐를 거절하지 않으며, foreground 검사로 버튼 해제가 거절될 수 있고, 실행 후 transport 유실을 refused로 표현한다. 등록 제거도 연결된 host 종료를 보장하지 않는다. publish exit 확인과 실행 파일 신뢰 검증도 부족하다.

따라서 코드·권한·저장 위치 변경은 그대로 채택하지 않는다. C# 배포 방향과 허용 동작/중복/만료 경계의 아이디어만 검토 자료로 사용한다. 기존 [PR14 안전 리뷰](https://github.com/rrangjaa-eng/project_260923/pull/14#discussion_r4118922478)의 파일 선택 전 확인, 정지 latch, late response를 unknown으로 처리, 좌표 재생 금지, stale 등록/USB 설정 충돌과 보호 export 지적을 후속 인수 조건으로 보존한다. 이번 파일 시제품에는 USB 설정 기준 원본 변경·비밀 저장이 없어 그 충돌을 도입하지 않는다.

## 재개 결정 — 2026-10-02 KST

사용자의 반복된 “나머지 계속 진행해” 승인으로 이 저장된 설계의 OS 없는 시제품 범위를 이어간다. 검증된 PR15/20440e6 및 ZIP은 보존하고 `codex/phase2-file-practice`에 분리한다. 새 권한·Windows 연결·파일 전송·게시·등록은 제외한다. 기존 설계의 추가 문서 승인 대기는 최신 진행 승인으로 대체하며 새로운 전체 설계를 만들지 않는다. 다음 작은 묶음은 보류된 worker 회귀 복원, 토큰 기반 한 파일 조정기와 가짜 provider, 기존 Space 엔진/토큰을 재사용하는 독립 확장 연습 화면이다. 실제 페이지나 OS 파일 입력으로 연결하지 않는다.
