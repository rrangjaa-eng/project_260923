# 설계: 손 떨림이 있는 이용자를 위한 브라우저 도우미 (이름 미정)

작성: 2026-09-23 · 브레인스토밍(superpowers `brainstorming`)에서 사용자와 합의한 내용
상태: 사용자 검토 대기

## 1. 문제

뇌병변 장애가 있는 이용자 한 사람이 PC 웹 브라우저를 쓴다. 손 떨림과 불수의 운동 때문에 작은 버튼·이미지·입력칸을 마우스로 정확히 누르기 어렵고, 손을 거의 못 쓰는 날도 있다. 헤드 마우스 같은 보조기기는 없고, 카메라 입력은 쓰지 않는다.

가장 중요한 것은 **평소 사이트를 쓸 때의 속도**다. 그다음은 회사 웹 시스템(그룹웨어, ERP, 전자결재)에서 **반복되는 입력을 자동화**하는 것이다. 쇼핑은 하지 않는다.

## 2. 목표와 성공 기준

- 어느 사이트에서든 원하는 요소를 **키 한두 번 또는 마우스를 대충 가져가는 것만으로** 누를 수 있다.
- 긴 입력 양식을 **큰 칸이 늘어선 화면**에서 채울 수 있다.
- 반복 업무 한 건이 "틀 고르기 1번 + 바뀌는 값 2~3번 + 제출 확인 1번"으로 끝난다.
- 떨림 때문에 잘못 눌러도 **되돌리기가 키 하나**다.
- 되돌릴 수 없는 제출은 **항상 이용자 확인** 뒤에만 일어난다.

## 3. 범위

### 첫 버전: 크롬·엣지·웨일용 확장 프로그램 하나 (윈도우 PC)

| 묶음 | 기능 | AI |
|------|------|----|
| 클릭 도우미 | 자석 커서, 번호표, 자동 순서 강조, 머무르기 클릭 | 없음 |
| 이동·입력 | 키 스크롤, 명령판, 입력 줄이기, 잘못 누름 되돌리기, 양식 한 장 보기 | 없음 |
| 작업판 | 탭 카드, 자주 가는 곳 번호, 확인 대기 목록 | 없음 |
| 틀 자동화 | 기록, 실행(속도 3단계), 뒤에서 실행, 제출 전 확인, 반복 패턴 알림 | 없음 |
| 화면 정리 | 처음 보는 복잡한 화면에 1~9 번호를 골라 붙이기 | 키를 누를 때만 |
| 컨디션 모드 | "좋은 날 / 힘든 날" 설정 묶음을 한 번에 전환 | 없음 |

### 다음 버전 (이번 설계에 포함하지 않음)
- 윈도우 상주 프로그램: 커서 떨림 완화, 키 떨림 무시, 웹 밖(엑셀·한글) 머무르기 클릭과 번호표
- 엑셀·다른 사이트의 정보를 입력칸으로 옮기기, 여러 건 한꺼번에 입력
- 안드로이드 접근성 도우미 앱 (아이폰은 통신사 연결이 없어 그 뒤)
- AI 글 써 주기, AI 틀 복구

### 하지 않는 것
- 보안 키패드를 대신 누르기, 자동입력 방지 문자 풀기
- 화면을 거치지 않고 사이트에 요청을 직접 보내기 (사이트의 입력 검사를 건너뛰게 되므로)
- 비밀번호·주민번호 같은 민감한 칸의 값 저장 (이용자가 직접 푼 칸만 예외, 8장)
- 서버 운영 (모든 데이터는 이용자 PC와 브라우저 계정 동기화에만 둔다)

## 4. 구조

Manifest V3 확장 프로그램. TypeScript strict, pnpm(저장소 규칙). 빌드 도구는 구현 계획에서 정한다.

```
┌──────────── 페이지마다 ────────────┐      ┌──────── 확장 전체 ────────┐
│ content script                     │      │ service worker            │
│  ├ 요소 수집기 (누를 수 있는 요소) │◀────▶│  ├ 설정·동기화 저장소     │
│  ├ 입력 필터 (떨림 걸러내기)       │ 메시지│  ├ 틀 저장소·실행기 조정  │
│  ├ 클릭 도우미 (자석/번호/순서/머무르기) │  ├ 탭·작업판 상태        │
│  ├ 오버레이 UI (카드, 명령판, 확인) │      │  ├ 이미지·광고 차단 규칙  │
│  ├ 양식 한 장 보기                  │      │  └ AI 창구 (화면 정리만)  │
│  └ 틀 기록기·단계 실행기            │      └───────────────────────────┘
└────────────────────────────────────┘
```

- **요소 수집기**가 모든 기능의 바탕이다. 페이지에서 누를 수 있는 요소(버튼, 링크, 입력칸, 클릭 이벤트가 걸린 이미지 등)를 찾아 위치·이름·종류 목록으로 만들고, 화면이 바뀌면(MutationObserver) 갱신한다.
- **입력 필터**는 키보드·마우스 입력을 가장 먼저 받아 떨림을 걸러낸 뒤 다른 기능에 넘긴다.
- 각 부분은 요소 목록과 필터링된 입력만 주고받는다. 서로의 내부를 알 필요가 없다.
- **iframe:** content script는 모든 프레임에 들어간다(`all_frames`). 회사 시스템은 iframe 안에 본문이 있는 경우가 많기 때문이다. 마우스·키 입력은 커서나 포커스가 있는 프레임으로 들어오므로, 일을 자주 일어나는 정도에 따라 나눈다(엔지니어링 검토 1번).
  - **그 프레임에서 바로:** 자석 커서 계산과 강조 테두리, 머무르기 클릭, 입력칸 안/밖 판정. 50ms 목표 때문에 다른 프레임을 거치지 않는다.
  - **맨 위 프레임이 모아서:** 번호표 번호 매기기(모든 프레임의 요소 목록), 모드 표시, 명령판·확인 화면. 프레임끼리의 메시지는 service worker를 거친다. 부모 프레임은 `chrome.runtime.getFrameId(iframe 요소)`로 자식 프레임과 iframe 요소를 짝짓는다.
- **service worker는 언제든 잠든다(MV3):** 틀 실행 상태(어느 틀, 몇 번째 단계, 받은 값)는 단계마다 `chrome.storage.session`에 적는다. 깨어나면 그 기록에서 이어 간다. **제출 버튼을 누르기 직전에** "누름" 기록을 `chrome.storage.local`(업데이트·재시작에도 지워지지 않음)에 쓰고, 저장이 끝났다는 답을 받은 뒤에만 누른다(엔지니어링 검토 2번). 깨어났을 때 "누름" 기록만 있고 결과가 없으면 다시 누르지 않고 "확인 필요"로 둔다.
- **큰 페이지 성능:** 요소 수집기는 화면에 보이는 요소만 다루고, 위치는 격자(공간 색인)로 나눠 찾는다. 마우스 움직임 계산은 1초에 60번까지만 하고, 화면 변화(MutationObserver)는 모아서 한 번에 갱신한다. 목표: 요소 5,000개짜리 연습 페이지에서 커서를 옮긴 뒤 강조가 50ms 안에 따라온다.

## 5. 조작 방법

### 키 배치 (모두 바꿀 수 있음)

| 키 | 동작 |
|----|------|
| 스페이스바 | 자석 커서가 잡은 요소 누르기 / 자동 순서 강조에서 선택 |
| Enter | 확인 화면에서 "예"(제출 확인, 위험한 버튼 확인). 스페이스바를 1초 누르고 있어도 된다 |
| 1~9 | 번호표가 붙은 요소 누르기, 카드 고르기 |
| Alt+1~9 | 입력칸 안에서 번호 카드 고르기 (숫자는 글자로 들어가므로) |
| 0 | 명령판 열기 |
| ↑ ↓ | 한 화면씩 부드럽게 스크롤 |
| ← → | 틀 실행 중 속도 바꾸기 |
| Esc | 취소, 입력칸 빠져나오기, 방금 이동한 페이지에서 뒤로 |

**입력칸과의 충돌:** 커서가 입력칸 안에 있을 때는 숫자·스페이스바가 원래대로 글자를 입력한다. 글쓰기 편집기(`contenteditable`, 게시판·메일 편집기)도 입력칸으로 본다. Esc로 입력칸을 빠져나오면 도우미 키로 돌아간다. 이때 화면 구석에 지금 "입력 중"인지 "도우미"인지 크게 표시한다.

### 떨림 걸러내기 (키보드·마우스 공통)
- 같은 키·같은 자리 클릭이 설정한 간격(기본값은 맞춤 설정에서 정함) 안에 다시 들어오면 무시한다.
- 키를 오래 눌러도 한 번만 입력한다(자동 반복 끔).
- 더블클릭이 의도치 않게 들어오면 한 번으로 줄인다. 필요한 곳은 명령판의 "더블클릭"으로 한다.
- 끌어서 놓기는 "끌기 시작 → 놓을 곳 누르기"의 두 번 누르기로 바꿀 수 있다(버튼을 계속 누르고 있을 필요 없음).
- **확인 화면 보호:** 확인 화면(제출 확인, 위험한 버튼 확인)이 뜬 뒤 1초 동안은 모든 입력을 무시한다. 확인은 방금 누른 스페이스바가 아닌 Enter(또는 스페이스바 1초 누르기)로 한다. 떨림으로 스페이스바가 한 번 더 들어가도 되돌릴 수 없는 일이 일어나지 않게 하기 위해서다.

## 6. 기능 상세

### 6.1 자석 커서 (기본 방식)
마우스 커서에 가장 가까운 요소를 **잡아서** 굵은 테두리로 크게 강조한다. 잡는 범위는 요소 크기보다 넓다. 커서가 떨려도 다른 요소 쪽으로 충분히 옮겨 가기 전까지는 잡은 요소를 바꾸지 않는다(히스테리시스). 이 상태에서 클릭하거나 스페이스바를 누르면, 커서의 실제 위치와 상관없이 잡은 요소가 눌린다. 빈 곳이나 글자 위를 클릭했을 때(잡은 요소가 없을 때)는 다른 요소로 바꿔 누르지 않고 원래 클릭 그대로 둔다. 위험한 버튼은 끌어당기지 않는다(8장).

### 6.2 번호표
단축키(또는 명령판)로 켠다. 번호를 붙이는 순서는 다음과 같다.
1. **직접 고정한 번호:** 이용자가 이 사이트에서 특정 요소에 고정한 번호
2. **자주 누른 요소:** 이 사이트에서 누른 횟수가 많은 순서
3. **마우스 근처:** 나머지 칸은 지금 커서 주변의 요소로 채운다

한 번에 1~9만 보여 준다. 더 필요하면 0 → "다음 번호"로 넘긴다. 요소 식별 방법은 6.8의 "요소 찾기"와 같은 방식을 쓴다.

### 6.3 자동 순서 강조
번호표가 붙은 요소를 하나씩 차례로 강조하고, 아무 키나(기본 스페이스바) 누르면 강조된 요소가 선택된다. 강조 간격은 조절할 수 있다. 손이 특히 힘든 날을 위한 예비 방식이다.

### 6.4 머무르기 클릭
켜 두면, 자석 커서가 잡은 요소 위에 커서가 설정 시간(예: 0.8초) 동안 머물 때 클릭한다. 진행 중에는 요소 둘레에 원이 차오르듯 표시해서, 그 전에 커서를 치우면 취소된다. 한 번 누른 요소는 커서가 떠났다 돌아오기 전까지 다시 누르지 않는다. 위험한 버튼(8장)에는 머무르기 클릭이 동작하지 않는다.

### 6.5 키 스크롤·명령판·되돌리기
- **스크롤:** ↑↓로 한 화면의 80%씩 부드럽게 움직인다. 페이지 안에 스크롤 영역이 여러 개면 자석 커서가 있는 영역을 움직인다.
- **명령판(0):** 뒤로, 앞으로, 새로고침, 탭 닫기, 새 탭, 작업판, 틀 실행, 틀 기록, 번호 고정, 조작 방식 바꾸기, 컨디션 모드, 화면 정리(AI), 도우미 끄기(8장)를 큰 번호 카드로 보여 준다. 카드 자리는 고정이다: 첫 장 1~8에 자주 쓰는 명령을 늘 같은 자리에 두고 9는 다음 장(자리 목록은 `docs/design/SYSTEM.md`, 설정에서 바꿀 수 있음). 첫 화면에는 키 안내 카드(스페이스바·1~9·0·↑↓·Esc, 그리고 브라우저 알림 창은 Enter=확인·Esc=취소)를 둔다.
- **되돌리기:** 번호·자석 커서로 링크를 눌러 페이지가 바뀐 직후 Esc를 누르면 뒤로 간다. 입력칸에 방금 넣은 값은 명령판의 "입력 되돌리기"로 되돌린다.

### 6.6 입력 줄이기
입력칸을 누르면 그 칸의 **최근 입력 값**과 이용자가 저장한 **자주 쓰는 문구**를 번호 카드로 보여 준다. 입력칸 안에서는 숫자가 글자로 들어가므로 카드는 Alt+1~9로 고른다. 칸은 사이트 + 칸 이름으로 구분한다. 비밀번호 칸과 민감한 칸(8장)에서는 보여 주지도, 기록하지도 않는다.

### 6.7 양식 한 장 보기
명령판에서 켜면, 지금 페이지의 입력칸들을 큰 칸이 위아래로 한 줄씩 늘어선 화면으로 모아 보여 준다. 각 칸에는 원래 칸의 제목(라벨)을 크게 붙이고, 선택 목록은 번호 카드로 바꾼다. 여기서 입력한 값은 원래 칸에 바로 채워지고(입력 이벤트를 함께 발생시켜 사이트가 알아채게 함), "원래 화면으로"를 누르면 닫힌다. 제출 버튼은 이 화면에 두지 않는다. 제출은 원래 화면에서 한다.

### 6.8 틀 자동화

**기록:** 명령판 → "틀 기록"을 켜고 평소처럼 한 번 입력한다. 기록기는 누른 요소와 입력한 값을 단계 목록으로 저장한다. 끝나면 "틀 저장" 화면이 뜬다.
- 날짜·금액·전화번호처럼 모양이 뚜렷한 값은 "바뀌는 값" 후보로 자동 표시한다.
- 이용자는 각 칸을 번호로 "매번 바뀜 / 항상 같음"으로 확정하고 틀 이름을 고른다.
- 마지막으로 누른 제출 성격의 버튼(저장, 상신, 등록, 제출 등)은 **제출 단계**로 표시한다. 이용자가 바꿀 수 있다.
- 시작 페이지 주소를 함께 저장해서, 실행할 때 메뉴를 거치지 않고 곧장 이동한다.

**요소 찾기 (AI 없음):** 단계마다 요소를 여러 방식으로 기억한다(id, name, 라벨 글자, 버튼 글자, aria 속성, 페이지 안 위치 경로). 요소가 iframe 안에 있으면 그 프레임까지 가는 경로도 함께 저장한다. 실행할 때 이 순서대로 찾고, 여러 방식이 같은 요소를 가리킬수록 확실하다고 본다. 확실한 요소가 없으면 멈춘다(6.8 "막힘").

**실행:** 0 → 틀 실행 → 틀 번호. 같은 틀은 한 번에 하나만 돈다(실행 잠금). 이미 도는 틀을 다시 고르면 작업판의 진행 상황으로 안내한다. 바뀌는 값마다 최근 값과 오늘 날짜 같은 후보를 번호 카드로 보여 주고, 직접 입력도 할 수 있다. 값을 다 받으면 단계를 실행한다.
- **속도:** 천천히(단계마다 멈추고 누르는 곳을 강조) / 보통(단계 사이 짧은 쉼) / 최대(쉼 없음). 기본값은 전체 설정, 틀마다 따로 정할 수 있고, 실행 중 ←→로 바꾸며, Esc로 멈춘다.
- **최대 속도의 동작:** 페이지 전체 로딩을 기다리지 않고, 다음 단계의 요소가 나타나는 즉시 실행한다. 같은 화면에 있는 입력칸들은 한 번에 채운다.
- **이미지·광고 차단:** 틀마다 켜고 끌 수 있다. 켜면 그 틀을 실행하는 탭에서 이미지·광고 요청을 막는다.
- **뒤에서 실행:** 틀을 뒤쪽 탭에서 돌리고, 이용자는 다른 탭에서 계속 일한다. 이용자가 해야 할 일(값 고르기, 제출 확인)이 생기면 작업판의 "확인 대기"에 쌓인다.

**제출:** 제출 단계 직전에 항상 멈춘다. 입력한 값을 큰 글씨로 요약해 보여 주고, Enter(또는 스페이스바 1초 누르기)로 제출, Esc로 취소한다(5장 "확인 화면 보호"). 제출한 뒤 결과가 분명하지 않으면(성공 메시지나 페이지 이동이 없음) **다시 제출하지 않고** "확인 필요"로 표시해서 이용자가 직접 확인하게 한다.

**브라우저 알림 창 (alert·confirm):** 브라우저가 띄우는 알림 창은 페이지를 멈추게 해서 도우미가 그 위에 아무것도 띄울 수 없다. 그래서 틀 실행 중에는 페이지 쪽(main world)에서 알림 창을 가로챈다. 이 감시 장치는 모든 페이지·모든 프레임에 페이지가 열릴 때(`document_start`) 미리 넣어 두고, 틀이 돌 때만 동작한다. 상신 뒤 넘어간 다음 페이지나 나중에 생긴 iframe의 창도 놓치지 않기 위해서다(엔지니어링 검토 4번). 페이지 쪽 장치가 보내는 소식은 사이트가 흉내 낼 수 있으므로 활동 기록에만 쓰고, 제출 성공 판정이나 다음 단계 진행에는 쓰지 않는다.
- 확인한 제출 버튼을 누른 뒤 몇 초 안에 처음 뜬 "저장할까요?" 같은 확인 창: 이용자가 방금 제출을 확인했으므로 "확인"으로 답한다. **첫 창 하나만** 이렇게 한다. 그 뒤에 이어서 뜨는 창("결재선이 없습니다. 계속할까요?", "이미 상신된 문서입니다" 등)은 아래 "예상하지 못한 확인 창"으로 다룬다.
- 예상하지 못한 확인 창: "취소"로 답하고 틀을 멈춘 뒤, 창에 있던 글을 큰 글씨로 보여 준다.
- 단순 안내 창(alert): 내용을 활동 기록에 남기고 닫는다.
- 틀 밖 평소 사용에서는 가로채지 않는다. 대신 처음 설치할 때와 키 안내 카드에서 "알림 창은 Enter=확인, Esc=취소"를 알려 준다.

**막힘:** 요소를 찾지 못하거나 화면이 예상과 다르면 그 자리에서 멈추고 알린다. 이용자는 "이 단계만 다시 기록"을 골라 그 단계를 한 번 직접 하고, 확인한 뒤에만 틀에 반영한다.

**반복 패턴 알림 (AI 없음):** 같은 사이트, 같은 입력칸 묶음에 틀 없이 3번 이상 입력하면 "이걸 틀로 저장할까요?"라고 한 번 묻는다. 거절하면 그 패턴은 다시 묻지 않는다.

### 6.9 작업판
명령판 또는 단축키로 연다. 큰 번호 카드로 다음을 보여 준다.
- 열린 탭 (번호로 바로 이동, 닫기)
- 자주 가는 곳 (이용자가 고정한 사이트)
- 뒤에서 도는 틀의 진행 상황
- 확인 대기 목록 (번호로 불러와 처리)

확인 대기가 생기면 모드 표시 옆에 "확인 대기 1" 같은 숫자와 확장 아이콘 배지로 알린다. 하던 입력을 끊지 않도록 확인 창을 바로 띄우지 않는다.

### 6.10 화면 정리 (AI, 키를 누를 때만)
처음 보는 복잡한 화면에서 명령판 → "화면 정리"를 누르면, 요소 수집기가 만든 요소 목록(종류, 보이는 글자, 대략의 위치)을 AI에 보내 이 화면에서 중요한 요소 9개를 고르게 한다. 고른 요소에 1~9 번호표를 붙이고, 결과를 사이트 + 페이지 주소 형태로 저장해 같은 화면에서는 다시 AI를 부르지 않는다.
- 입력칸의 값은 보내지 않는다. 요소 글자 중 이메일·전화번호·숫자 긴 줄 같은 개인정보 모양은 가려서 보낸다.
- 작고 저렴한 Claude 모델을 쓰고, AI 호출은 모두 이 창구 한 곳을 거친다.
- 이용자가 정한 한 달 사용 한도를 넘으면 호출하지 않고 알린다.
- AI 사용 키가 없으면 이 기능만 꺼지고 나머지는 모두 동작한다.
- AI 답은 검사한다. 고른 요소가 보낸 목록에 있는 것만 받아들이고, 하나라도 맞지 않으면 그 답을 버리고 자주 누른 순서 번호표로 대신한다. AI는 번호만 붙이고 **절대 직접 누르지 않는다.**

### 6.11 컨디션 모드
"좋은 날 / 힘든 날" 두 가지 설정 묶음이다. 각 묶음에 조작 방식(자석 커서 / 번호표 / 자동 순서 강조), 떨림 간격, 머무르기 시간, 강조 속도, 번호표·테두리 크기를 저장해 두고(번호표·테두리 크기는 브라우저 확대와 상관없이 고정되고 이 설정으로만 바뀐다), 명령판에서 한 번에 바꾼다.

### 6.12 처음 설치할 때의 맞춤 설정
세 단계로 한다(디자인 검토 3번). 단계마다 "Esc 건너뛰기"가 있고, 건너뛴 단계는 기본값을 쓴다. 나중에 명령판에서 다시 할 수 있다.
1. **키 안내:** 스페이스바·1~9·0·↑↓·Esc, 그리고 "브라우저 알림 창은 Enter=확인, Esc=취소"를 큰 카드로 보여 준다.
2. **떨림 간격 재기:** 큰 버튼을 몇 번 누르게 해서 같은 키가 의도치 않게 다시 눌리는 간격을 잰다.
3. **머무르기 시간 재기:** 큰 버튼 위에 커서를 올려 두게 해서 편한 머무르기 시간을 잰다.

잰 값으로 두 컨디션 모드의 기본값을 정한다. 각 불러오기·비어 있음·실패 상태의 화면은 `docs/design/SYSTEM.md`의 상태 표를 따른다.

### 6.13 활동 기록
최근 2주 동안의 동작(무엇을 눌렀는지, 틀이 어디까지 갔는지, 알림 창 내용, 막힘·확인 필요)을 이 PC에만 남긴다. **입력한 값은 남기지 않는다.** 문제가 생겼을 때 이용자가 명령판에서 "기록 내보내기"를 누르면, 내보낼 내용을 먼저 보여 주고 확인한 뒤 파일로 저장한다.

기록에서 주간 진행 통계도 만든다: 되돌리기 횟수, 틀 한 번에 누른 횟수. 기본값을 조정하고 도우미가 실제로 나아지고 있는지 보는 데 쓴다.

## 7. 저장과 동기화

| 데이터 | 저장 위치 | 이유 |
|--------|-----------|------|
| 조작 설정, 컨디션 모드, 고정 번호, 자주 가는 곳, 자주 쓰는 문구, 민감한 칸 설정 | 브라우저 계정 동기화 (`chrome.storage.sync`) | 다른 PC에서도 같은 조작 |
| 자주 누른 기록, 최근 입력 값, 화면 정리 결과, AI 사용량, 활동 기록(2주) | 이 PC만 (`chrome.storage.local`) | 양이 많거나 개인 기록이라서 |
| 틀 실행 상태 | 이 브라우저 실행 동안만 (`chrome.storage.session`) | service worker가 잠들었다 깨어나도 이어 가려고 |
| AI 사용 키 | 이 PC만 | 동기화하지 않는다 |
| 틀 | 이 PC만 + 파일로 내보내기·가져오기 | 동기화 용량(약 100KB)을 넘을 수 있어서 |

- 설치는 크롬 웹스토어 비공개 링크로 한다. 같은 브라우저 계정으로 로그인한 다른 PC에는 자동으로 설치된다.
- 동기화는 **같은 브라우저끼리만** 된다. 크롬↔크롬, 엣지↔엣지는 되지만 크롬과 엣지·웨일 사이에는 설정이 넘어가지 않는다. 다른 브라우저로 옮길 때는 설정 파일 내보내기·가져오기를 쓴다.
- 동기화 용량을 넘을 것 같으면 넘기 전에 알리고, 자주 쓰는 문구부터 파일 내보내기를 안내한다.
- **저장은 한 곳에서만**(엔지니어링 검토 6번): 모든 저장은 service worker 하나가 순서대로 한다. 탭·프레임은 저장을 부탁만 한다. 동기화 항목은 사이트별로 나눠 한 항목 8KB·분당 쓰기 횟수 제한을 넘지 않게 하고, 활동 기록은 하루 단위로 나눠 저장한다. AI 사용 키는 사이트 쪽 코드(content script)에 절대 넘기지 않는다.
- 틀을 파일로 내보낼 때는 "이 파일에는 틀에 저장된 고정 값이 들어 있습니다"라고 먼저 알린다.
- 저장하는 모든 데이터에는 형식 버전을 붙인다. 새 버전으로 바꾸다 실패하면 원래 데이터를 그대로 두고 알린다.

## 8. 안전장치와 보안

- 제출 성격의 단계는 항상 이용자 확인 뒤에만 실행하고, 절대 다시 시도하지 않는다.
- **민감한 칸**은 값 기록, 최근 입력, 틀 저장, AI 전송에서 모두 뺀다. 이런 칸이 틀 안에 있으면 실행 때마다 이용자가 직접 입력하게 멈춘다. 판별은 다음과 같다.
  - `type=password` 칸, 이름·라벨에 비밀번호·비번·PW·인증번호·OTP·보안카드가 들어간 칸: 기본으로 민감하다.
  - 이름·라벨에 주민·계좌·카드가 들어간 칸: **입력된 값이 주민번호·계좌번호·카드번호 모양일 때만** 민감하다. "법인카드 구분", "지급계좌 선택" 같은 업무 칸이 막히지 않게 하기 위해서다.
  - **이용자가 직접 정하기:** 명령판에서 칸을 골라 "이 칸은 민감함 / 민감하지 않음"으로 사이트마다 정할 수 있다. 비밀번호 칸을 포함한 모든 민감칸을 풀 수 있고, 풀 때는 한 번 더 확인한다. 비밀번호 칸을 풀 때의 확인 화면에는 "이 칸의 값이 이 PC와 틀 파일에 암호화 없이 저장됩니다"라고 적는다. 판별 단어 목록도 설정에서 더하고 뺄 수 있다. 이 설정은 계정 동기화로 다른 PC에도 적용된다.
- 보안 키패드, 자동입력 방지 문자, 결제 화면을 만나면 자동으로 누르지 않고 멈춘다.
- **위험한 버튼:** 글자에 삭제·취소·반려·로그아웃·결재 취소 같은 말이 들어간 버튼(목록은 사이트마다 고칠 수 있음)은 떨림으로 잘못 눌리면 되돌리기 어렵다. 그래서
  - 자석 커서가 끌어당기지 않는다. 커서가 버튼 위에 정확히 있을 때만 잡힌다.
  - 머무르기 클릭이 동작하지 않는다.
  - 번호표나 자동 순서 강조로 고르면 빨간 테두리와 함께 "정말 누를까요? Enter = 예"를 한 번 더 묻는다(5장 "확인 화면 보호").
- **도우미 끄기:** 명령판과 확장 프로그램 아이콘에서 도우미 전체, 또는 지금 사이트에서만 끌 수 있다. 어떤 사이트에서 도우미가 방해되면 바로 끄고 일을 계속할 수 있어야 한다.
- **자동 업데이트 대비**(엔지니어링 검토 3번): 틀이 도는 동안에는 업데이트 적용을 미루고(`runtime.onUpdateAvailable`), 틀이 끝나면 적용한다. 업데이트·재시작으로 연결이 끊긴 옛 도우미는 스스로 모든 키 감시와 화면 표시를 걷어 내서 키를 가로채지 않는다. 업데이트 직후 열린 탭에 새 도우미를 넣는다(`onInstalled`).
- **되돌릴 수 있는 배포:** 웹스토어 링크로 설치한 확장은 웹스토어에서 자동으로 업데이트되므로, 옛 설치 파일을 직접 밀어 넣어 되돌릴 수 없다. 새 버전에 문제가 있으면 웹스토어의 되돌리기(이전 버전으로 롤백)를 쓰고, 안 되면 이전 코드를 더 높은 버전 번호로 다시 올린다(심사를 기다릴 수 있음). 그 사이에는 "도우미 끄기"로 버틴다. 새 버전은 연습 사이트 시험을 모두 통과한 뒤 올리고, 심사를 통과해도 바로 공개하지 않고 확인 후 공개(지연 게시)한다.
- **사이트가 만든 가짜 입력은 무시한다**(엔지니어링 검토 4번): 도우미는 브라우저가 "사람이 누름"(`isTrusted`)으로 표시한 키·마우스 입력에만 반응한다. 사이트가 만든 가짜 Enter로 확인 화면이 넘어가지 않는다. 도우미 부분끼리의 메시지(프레임 사이 포함)는 사이트가 닿지 않는 확장 내부 통로(service worker)로만 주고받는다.
- 확장 프로그램은 클릭 도우미 때문에 모든 사이트 접근 권한이 필요하다. 설치 화면에서 이 점을 알린다.
- 데이터는 서버로 보내지 않는다. 밖으로 나가는 것은 이용자가 "화면 정리"를 눌렀을 때 AI로 가는 요소 목록뿐이다.

## 9. 오류 처리

| 상황 | 처리 |
|------|------|
| 틀의 요소를 못 찾음 | 멈추고 "이 단계만 다시 기록" 제안 |
| 제출 결과가 불분명함 | 다시 제출하지 않고 "확인 필요" |
| 뒤에서 도는 탭이 닫힘·로그아웃됨 | 그 틀을 멈추고 작업판에 이유 표시 |
| 확장 프로그램이 동작하지 않는 페이지(브라우저 설정 화면, 웹스토어 등) | 페이지 위에는 아무것도 띄울 수 없으므로, 확장 프로그램 아이콘에 "도울 수 없음" 표시 |
| AI 호출 실패·한도 초과 | 화면 정리만 건너뛰고 자주 누른 순서 번호표로 대신 |
| AI 답이 목록에 없는 요소를 고름 | 답을 버리고 자주 누른 순서 번호표로 대신 |
| 동기화 용량 초과 | 알리고 파일 내보내기 안내 |
| 틀 실행 중 예상하지 못한 알림 창 | "취소"로 답하고 멈춘 뒤 창의 글을 보여 줌 |
| 틀 실행 중 service worker가 잠듦 | 저장된 실행 상태에서 이어 감. 제출 단계에 "누름" 기록만 있고 결과가 없으면 "확인 필요" |
| 같은 틀을 두 번 실행 | 두 번째는 시작하지 않고 진행 중인 틀로 안내 |
| 저장 데이터 형식 변환 실패 | 원래 데이터를 그대로 두고 알림 |
| 도우미가 특정 사이트를 방해함 | 이용자가 그 사이트에서만 도우미를 끔 |

## 10. 시험 방법

- **연습용 가짜 사이트:** 아주 작은 버튼과 이미지 링크, 긴 입력 양식, 늦게 나타나는 입력칸, 모양이 바뀌는 페이지(틀 막힘 재현), 결과가 불분명한 제출 버튼, iframe 안의 양식, 알림 창(alert·confirm)을 띄우는 버튼, 위험한 버튼, 요소 5,000개짜리 큰 페이지를 갖춘 로컬 사이트를 만든다. 모든 기능은 이 사이트에서 먼저 시험하고, 실제 회사 시스템에서는 시험하지 않는다. **예외 하나**(엔지니어링 검토 7번): 11장의 확인을 위해, 이용자가 회사 시스템에서 **제출 없이** 누르기·입력만 해 보는 읽기 전용 확인 목록을 직접 돌린다.
- **자동 시험 범위:** CI는 크롬(Chromium)으로만 돈다. 엣지·웨일은 출시마다 짧은 수동 확인 목록으로, 웹스토어 설치·계정 동기화·다른 PC는 수동으로 확인한다.
- **단위 시험:** 떨림 필터(간격 안의 재입력 무시), 자석 커서 히스테리시스, 번호표 우선순위, 요소 찾기 점수, 바뀌는 값 자동 표시, 민감한 칸 판별, 위험한 버튼 판별, 반복 패턴 세기, AI 답 검사, 저장 형식 변환.
- **확장 프로그램을 띄운 브라우저 시험:** 확장 프로그램을 설치한 크롬으로 연습 사이트에서 틀 기록 → 실행 → 제출 확인 → 막힘 → 다시 기록까지 흐름 전체를 자동으로 돌린다. iframe 안 양식, 알림 창 처리, 실행 중 service worker를 강제로 재운 뒤 이어 가기, 큰 페이지의 강조 반응 시간(50ms)도 함께 시험한다.
- **이용자 시험:** 실제 이용자가 연습 사이트에서 정해진 과제(작은 버튼 10개 누르기, 양식 하나 채우기)를 확장 프로그램 없이 할 때와 있을 때의 시간과 잘못 누른 횟수를 비교한다.
- **중간 이용자 시험:** 클릭 도우미(자석 커서·번호표)와 떨림 걸러내기를 먼저 만들고, 나머지를 만들기 전에 실제 이용자가 연습 사이트에서 써 본다. 여기서 떨림 간격, 잡는 범위, 머무르기 시간 같은 기본값을 맞추고, 결과에 따라 이후 순서를 조정한다.

## 11. 확인이 필요한 점 (구현 전에 짧게 시험)

1. **대신 누른 클릭을 받지 않는 사이트:** 확장 프로그램이 발생시킨 클릭은 사람이 누른 클릭과 구분될 수 있다. 이용자가 쓰는 회사 시스템에서 번호표 클릭과 틀 입력이 먹히는지 먼저 확인한다.
2. **회사 PC 정책:** 회사 PC가 확장 프로그램 설치를 막는지 확인한다.
3. **뒤쪽 탭 속도 제한:** 브라우저가 뒤쪽 탭의 타이머를 늦추기 때문에, 뒤에서 도는 틀이 얼마나 느려지는지 확인한다.
5. **대신 누른 클릭의 한계**(엔지니어링 검토 5번): 머무르기 클릭과 틀 실행은 사람이 직접 누른 것이 아니라서, 브라우저가 새 창(결재 팝업), 선택 목록, 파일 선택 창을 막을 수 있다. 1단계 첫 시험에 이 경우들을 넣는다. 누르기는 마우스 누름·뗌·클릭과 포커스를 차례로 보내는 방식으로 하고, 선택 목록은 이용자의 실제 키 입력에서 연다. 새 창은 이용자가 고정한 회사 사이트만 허용한다(팝업 권한 `contentSettings`는 새 권한이라 만들 때 승인받는다). 개발자 도구(debugger) 방식은 쓰지 않는다.
4. **사이트 단축키와의 충돌:** 숫자·스페이스바를 자체 단축키로 쓰는 사이트에서 도우미 키가 우선하도록 가로챌 수 있는지 확인한다.
