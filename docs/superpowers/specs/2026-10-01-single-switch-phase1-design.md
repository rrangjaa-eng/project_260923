# 스페이스바 단일 스위치 웹 활동 — 1차 설계 검토안

작성: 2026-10-01 KST · 상태: 사용자 설계 승인 전달됨. 구현계획 작성·검토 단계

## 1. 목표와 첫 완료 기준

뇌병변 장애가 있는 이용자가 손을 최대한 움직이지 않고 브라우저 활동을 이어간다. 필수 입력은 **스페이스바 한 번 누르고 놓기**다. 길게 누르기, 더블클릭, 조합키, 숫자키, 정밀한 마우스 이동을 요구하지 않는다. 기존 자석·떨림 필터·dwell은 보존한다.

첫 완료 시나리오는 준비된 지원 웹페이지에서 **새 한글 검색어 작성 → 한 글자 수정 → 검색 → 결과 선택 → 본문 읽기/스크롤 → 뒤로 → 열린 다른 탭으로 이동**이다. 시작과 종료, 잘못 고른 항목 취소, 쉬었다 재개하기도 스페이스바로 한다. 설치·최초 권한 부여·브라우저 실행은 준비 조건이며 1차의 단독 조작 보장에 포함하지 않는다. 지원 페이지에 포커스가 있고 단일 스위치 모드가 설정된 상태부터 검증한다.

모든 사이트 지원을 약속하지 않는다. 먼저 로컬 연습 사이트에서 전 과정을 자동 검증하고, 사용자가 실제 쓸 검색/읽기 사이트 한 곳에서 별도 사용성 검증을 한다. 파일 선택창·브라우저 밖 조작·휴대용 실행기는 2차, 반복 업무 자동화는 그다음이다. 이번 문서는 설계까지만 다룬다.

## 4. 작업판과 순환 규칙

상위 그룹은 **찾기 → 페이지 항목 → 읽기·이동 → 글쓰기 → 조절·쉬기** 순서로 고정한다. 스페이스 한 번으로 강조된 그룹에 들어가고, 다시 한 번으로 강조된 항목을 선택한다. 모든 하위 목록의 첫 항목은 `상위로`, 마지막은 `쉬기`다. 페이지 항목은 한 묶음 최대 6개와 `이전 묶음/다음 묶음`으로 나눈다. 그 외 필수 동작에도 Enter/Esc를 요구하지 않는다.

- 읽기·이동: 한 화면 아래/위, 자동 스크롤 시작, 뒤로, 열린 탭 목록. 읽기는 우선 본문을 보며 읽는 흐름이며 음성 읽기는 1차 필수가 아니다.
- 글쓰기: 새 문장, 수정, 저장 문구. 찾기는 같은 글쓰기 버퍼를 사용하고 `검색` 선택 때만 실행한다.
- 조절·쉬기: 순환 속도, 입력 간격 보호, 쉬기, 조작 방식 전환. 기존 방식으로 바꾸면 단일 스위치만으로 가능한 범위가 줄어듦을 표시하고 전환을 명시적으로 선택하게 한다.
- 초안 기본값: 항목당 1.5초, 범위 0.8~4초, 새 목록의 첫 항목은 2배 시간. 재입력 보호는 기본 300ms, 100~1000ms 범위. 최종값은 사용자 시험으로 결정하며 몰래 속도를 조절하지 않는다.
- 그룹/명령 위치는 고정. 페이지 대상은 수집 당시 프레임 순서와 DOM 순서로 스냅샷을 만들고, 순환 중 재정렬하지 않는다. 새 대상은 명시적 `목록 새로 읽기`에서 반영한다. 사라진 대상은 그 자리에서 사용 불가로 표시하고 실행하지 않는다.
- 키를 누르는 순간 현재 강조 대상을 고정하고, 놓았을 때 그 대상을 한 번만 선택한다. 누른 채 시간이 지나도 다음 항목 선택이나 실행으로 바뀌지 않는다. 키 반복은 무시한다.
- 2회 완주 동안 선택이 없으면 `쉬는 중`으로 전환한다. 이는 동의가 아니다. 다음 한 번은 재개에만 쓰고 첫 항목부터 충분한 시간을 준다.

표현은 `docs/design/SYSTEM.md`와 기존 토큰을 따른다. 큰 글자·굵은 선택 테두리·현재 상태를 표시하고 색만으로 구분하지 않는다. 기존 Enter/Esc 키 안내와 명령판 배치의 단일 스위치용 변경은 승인 후 디자인 결정 문서에 반영한다. 이번에 기존 디자인 기준을 수정하지 않는다.

## 5. 공통 엔진과 실행 경계

입력 어댑터 → 상태 엔진 → 실행 권한 판정 → 페이지/탭 어댑터 → 결과 이벤트 → 작업판의 단방향 흐름으로 한다. 순수 상태 엔진은 DOM·브라우저 API를 직접 호출하지 않고 시간과 이벤트를 받아 새 상태 및 실행 요청을 반환한다.

| 경계 | 책임/주요 계약 |
|---|---|
| 입력 | 신뢰된 물리 키의 down/up를 한 cycle로 정규화. `repeat`, 조합키, composition 중의 이벤트는 선택으로 해석하지 않음. blur/숨김/모드 변경 시 미완료 cycle 폐기 |
| 상태 | `ready / groupScan / itemScan / composing / confirming / executing / scrolling / paused / recovering` 및 복귀 위치·버퍼 소유. 타이머는 강조 이동만 수행 |
| 실행 | 요청마다 `actionId`, 모드 세대, 탭·프레임·문서 세대, 대상 ID를 검증. 수행 중 추가 실행 차단. 완료/거절/결과 불명을 구분 |
| 페이지 | 기존 collector, fingerprint, 클릭·위험 판정을 재사용. 대상 연결·활성·문서 세대와 위험 상태를 실행 직전에 다시 확인 |
| 탭/프레임 | 최상위 작업판이 순환을 소유하고 해당 프레임은 입력/대상 보고 및 검증된 실행만 담당. 백그라운드는 송신자·탭·프레임을 검증해 중계 |
| 화면/보존 | 상태만 렌더링. 설정과 명시적으로 저장한 문구는 기존 저장 계층 사용. 작성 중인 문장은 탭별 세션 범위에 보존하고 자동 동기화하지 않음 |

단일 스위치 모드에서는 스페이스가 작업판의 선택 입력이고 페이지의 기본 스크롤·버튼 클릭으로 동시에 전달되지 않는다. 마우스 보조 모드에서는 기존 자석·떨림 필터·dwell을 유지한다. 전환 시 dwell 타이머와 눌림 상태를 초기화한다. 작업판·확인·입력·자동 스크롤 중에는 페이지 dwell 실행을 정지한다. 마우스 클릭도 같은 실행 경계를 통과시키며 물리 입력 묶음과 엔진이 발생시킨 클릭을 재수집하지 않는다.

동일 `actionId`는 대상 프레임에서 한 번만 수락한다. 키 선택과 dwell이 경쟁하면 엔진이 먼저 수락한 실행 하나만 수행하고 나머지는 폐기한다. 응답 유실·worker 재시작으로 결과가 불명확하면 자동 재전송하지 않는다. 사이트가 비신뢰 클릭을 거절하면 지원 불가로 표시하며 권한 우회나 OS 입력 합성을 추가하지 않는다.

## 6. 한글 새 문장·수정·입력 모드

단일 스위치 글쓰기는 OS 한글 IME 키 입력을 흉내 내지 않는다. 작업판 안에서 **초성 → 중성 → 선택 종성(없음 포함)**을 그룹/항목으로 고르고 음절을 조합한다. 쌍자음·겹모음·겹받침도 선택지에 포함한다. 초안은 완성형 음절을 명시적으로 만드는 방식이며 예측 입력은 필수가 아니다. 문장 사이 공백은 `띄어쓰기` 항목으로 넣는다. 물리 스페이스는 항상 선택이고 문자 공백과 구분한다.

편집 항목은 조합 한 단계 취소, 앞/뒤 한 글자 이동, 앞 글자 삭제, 실행 취소, 문구 삽입, 입력칸에 적용이다. 삭제 단위는 화면에 보이는 한 글자이며 조합 중에는 직전 조합 단계만 되돌린다. 기존 일반 키보드 입력 모드는 별도로 유지하며, OS composition 중의 스페이스와 완료 이벤트는 스캔 선택으로 소비하지 않는다. 단일 스위치 이용자에게 OS 입력 모드를 필수로 거치게 하지 않는다.

사이트 입력칸을 선택하면 대상과 현재 값/선택 범위를 기억하고 작업판 버퍼에서 작성한다. `적용` 때 대상 및 원래 값을 다시 확인한다. 사이트가 값을 바꾸었거나 프레임이 교체되었으면 덮어쓰지 않고 버퍼를 남겨 재선택한다. 첫 지원 계약은 일반 input/textarea와 검색 입력이다. 복잡한 contenteditable·문서 편집기는 기존 보호를 보존하되 새 한글 삽입 지원을 별도 검증 전까지 약속하지 않는다. 비밀번호·민감칸은 문구 수집과 초안 영속 저장에서 제외한다.

취소/쉬기/그룹 이동은 미완성 조합과 작성문을 보존한다. 원래 입력칸으로 돌아가기는 유효한 대상에서만 포커스·선택을 복원한다. 버퍼 버리기는 별도 명시 동작이다. 페이지 이동 뒤 버퍼는 복구 가능하지만 옛 대상에 자동 적용하지 않는다. 브라우저 종료 뒤 임시 초안 복구는 1차 보장이 아니며, 저장 문구만 유지한다.

## 7. 취소·쉬기·확인·복구

| 상황 | 동작 |
|---|---|
| 잘못 고른 그룹/항목 | `상위로`를 순환 선택. 입력 초안은 유지. 안전한 내부 편집은 실행 취소 가능 |
| 쉬기 | 모든 스캔·dwell·스크롤 타이머 정지. 다음 한 번은 재개에만 소비. 대상은 재검증 |
| 자동 스크롤 | 지원 페이지에서 받은 첫 선택 입력은 **정지에만** 소비하고 클릭/선택으로 재사용하지 않음. blur/숨김도 자동 스크롤 정지 |
| 위험한 제출/삭제 등 | 실제 동작 이름·대상 요약을 표시. 시작 키를 완전히 놓고 1초 보호 후 `취소 → 실제 동작명`을 순환. 새로운 한 번 누르고 놓기로만 확정. dwell 확인 금지 |
| 확인 중 무입력 | 선택하지 않음. 2회 순환 뒤 취소하고 쉬기. 시간이 흘렀다는 이유로 확정하지 않음 |
| 페이지/프레임 교체, 대상 삭제 | 문서 세대 무효화, 미완료 눌림과 대기 실행 폐기. 초안만 보존하고 재개 때 새 대상 선택 |
| 탭 이동·포커스 이탈 | 현재 작업을 정지/보존. 지원 탭에서 새 입력 한 번으로 작업판 재개. 이전 탭의 클릭·확인 이어 실행 금지 |
| 확장 재연결/결과 불명 | 쉬는 상태로 복구, 실행 여부 표시. 사용자 재선택 전 자동 실행·재시도 금지 |

페이지 밖(주소창·브라우저 메뉴·OS 대화상자)에서 전역 스페이스 정지를 보장하지 않는다. 비지원 페이지에는 실행 대상을 만들지 않는다. 자동화가 복구할 수 없는 상태는 정지하고 한 줄로 이유를 표시한다. 위험 판정은 기존 휴리스틱을 재사용하지만 완전하지 않다. 검증 대상 사이트의 제출/삭제 계약을 확인하며, 동작 의미가 불명확한 페이지 버튼은 단일 스위치 모드에서 확인 대상으로 취급한다. 링크 이동·읽기 등 알려진 안전 동작은 추가 확인을 요구하지 않는다.

## 8. 승인 후 검증할 수용 조건

1. 지원 페이지에서 준비 상태의 첫 스페이스로 시작해 §1의 전체 활동을 **스페이스 down/up만으로** 끝낸다. 마우스·다른 키·길게 누르기 사용 0회, 기대하지 않은 사이트 클릭/제출 0회다.
2. `안녕하세요`처럼 저장 문구에 없는 문장을 만들고 공백 삽입, 중간 한 글자 수정, 조합 취소, 문구 삽입을 수행한다. 각 결과 문자열을 비교한다.
3. 키 반복, 빠른 떨림, keyup 유실, dwell과 키의 경합, 확인 진입 직전 입력에서 실행 횟수는 의도한 1회 이하이며 무입력 확정은 0회다.
4. 순환 중 DOM 삽입·삭제, 프레임 탐색, 뒤로 가기, 탭 이동을 발생시켜 옛 대상 실행 0회와 초안 보존을 확인한다. 자동 스크롤 중 첫 입력의 부작용은 정지만이다.
5. 기존 자석·떨림·dwell·확인·입력 모드 회귀를 검증하고 CI 프로덕션 빌드를 실제 로드한다. 새 상태 엔진은 가상 시각 단위 검사, 통합은 실제 키 입력 E2E로 나눈다.
6. 작업판은 기존 토큰과 DOM 접근성 검사로 검증한다. 실제 PC에서 한글 IME 공존과 이용자의 피로·오선택·속도 조절을 별도 확인한다. 클라우드 자동 검사는 실제 운동 사용성을 대체하지 않는다.
