# 단일 스위치 양식 탐색: 승인된 후속 범위

2026-10-02 KST. 기준 PR18/6fce6f5. 기존 INPT-03, 1차 단일 스위치 설계의 입력·상태 엔진과 최신 사용자 진행 승인을 연결한 작은 작업이다. 새 개인 데이터 수집이 필요한 INPT-01 최근값 카드는 별도 승인 대상으로 남긴다.

글쓰기 → **양식 한 장 보기** → 입력칸 이름 선택 → 한글·수정·문구 → 이전/다음 칸 → **입력칸에 적용** → **원래 화면으로**를 스페이스바 한 번 누르고 놓기로 조작한다. 목록은 기존 프레임/DOM 순서의 이름만 6칸씩 보여 주고, 순서는 사용자가 목록을 새로 읽기 전 유지한다. 값은 선택한 칸만 읽는다. 첫 범위는 선택값 4000자 이하의 지원되는 input/textarea이며 민감 입력, readonly/disabled, select·파일 등은 제외한다.

기존 작업판과 토큰을 재사용한다. 편집 중에는 양식 내 위치·칸 이름을 표시한다. 칸 이동은 입력을 적용하지 않고 각 칸의 문장·커서/선택·undo·미완성 한글을 메모리에 보존한다. 원래 화면으로 돌아오면 진입 전 작성 문장과 메뉴 맥락을 복원한다. 새로고침·문서 교체 뒤 대상은 자동 재연결하지 않는다.

쉬기는 확인 승인을 폐기하고 문장을 보존한다. 양식 안의 확인 취소/쉬기 뒤에는 양식 목록으로 돌아간다. 프레임·연결·도우미 상태 무효화 때 원래 작업을 복원하고 현재 양식 문장은 **양식 작성 문장 복구**로 대상 없이 열 수 있다. 복구 자체로 페이지에 적용하지 않는다. 메모리 버퍼는 페이지/controller가 살아 있는 동안의 복구이며, 페이지 종료 후 영구 복구를 약속하지 않는다.

적용 전 기존 문서 세대·필드 identity·민감 상태·기존 값을 다시 확인한다. 사이트가 값을 바꿨으면 덮어쓰지 않는다. 대기 중 쉬기나 무효화가 발생한 뒤 옛 응답은 현재 작업 공간을 바꾸지 못한다. 자동 저장·최근값 수집·외부 전송·자동 제출·새 권한은 추가하지 않는다. 문구 저장은 기존 명시적 사용자 선택 계약을 따른다.

완료 조건은 실제 확장의 Space-only 흐름에서 목록의 값 비노출, 필드별 작업 보존, 명시적 적용 1회/input·change 이벤트, 제출 0회, 원래 작업 복귀, 민감 제외, 대상 변경 거절, 늦은 응답 폐기를 확인하는 것이다. 360/768/1280px 실제 DOM에서 기존 최소 표적 56px·글자18px·제목/상태의 뷰포트 경계를 확인한다. 실제 PC IME·운동 사용성·실사이트는 별도 검증이다.

INPT-03 전체(선택/체크 등 모든 양식 위젯, 사이트 유효성 오류 읽기, 모든 사이트 지원)는 이번 부분 구현을 근거로 완료 처리하지 않는다. 다음 결정은 선택/체크 위젯과 검증 오류 읽기의 구체적인 단일 스위치 조작 범위다. 사이트가 값을 바꾼 칸에서 기존 초안과 변경값을 비교해 다시 적용하는 확인 UI도 후속으로 남긴다. 현재 cache의 기존값 검사는 같은 칸 재선택만으로 해제하지 않는다. 최근값/실제OS/배포는 각각 별도 승인 경계다.
