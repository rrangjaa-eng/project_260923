# NAV-04 현재 입력칸의 마지막 적용 되돌리기

## 승인과 최소 범위

사용자는 기존 설계/요구사항에 충분히 정해진 안전한 NAV-04 범위를 구현·독립 검토·검증·commit/push·draft PR·최종 CI까지 진행하도록 요청했다. 기준은 PR33 `cc95a59d19766104ff419f36627eee66e9afceea`, 브랜치 `codex-switch-applied-undo`. PR31–33·main HEAD와 기존 ZIP을 보존하며 새 main 병합·배포·ZIP 교체는 하지 않는다.

원 요구사항 NAV-04와 원 설계6.5는 “입력칸에 방금 넣은 값”의 되돌리기다. 기존 `edit:undo`는 초안만 바꾸고 실제 입력칸은 되돌리지 않는다. 이번 최소 범위는 **현재 선택한 지원 input/textarea의 마지막 성공한 명시 적용 또는 비교 후 재적용 1회**다. 검색 제출·선택 컨트롤·contenteditable·전체 기록·다단계 undo/redo로 확대하지 않는다.

## 동작 계약

- “적용한 값 되돌리기”는 초안의 “입력 되돌리기”와 별도 메뉴다. 현재값/되돌릴 값 미리보기, 취소 우선, 1초 보호 뒤 명시 확인을 사용한다.
- 적용 후 작성 중인 다른 초안·미완성 한글, pending/unknown이 있으면 되돌리지 않는다. 칸 이동·양식 진입/이탈·쉬기·문서/프레임 변경에서 controller의 되돌리기 권리를 폐기한다. 취소는 필드·초안·권리를 그대로 보존한다.
- 원래 값·선택 범위·실제 DOM 노드·조상 집합은 해당 content 문서 메모리에만 보관한다. 각 collector의 마지막 한 건만 보관하며 새 적용/실행·쉬기/종료에서 폐기한다. worker/storage에 undo 이력을 저장하지 않는다. 현재 초안 저장은 기존 경로를 유지한다.
- 미리보기와 최종 적용 모두 기존 문서/프레임 세대·가시성·승인 검사를 통과해야 한다. 페이지 실행기는 현재 DOM 노드·identity·민감성·쓰기 가능 여부·현재값·1회용 토큰을 다시 검사한다. 같은 노드가 제거됐다 재삽입돼도 제거 이력으로 거절한다.
- undo 토큰은 사이트 이벤트를 발생시키기 전에 소비한다. 성공하면 필드값·원래 선택과 해당 초안을 함께 복원한다. 이벤트 중 값/노드 변경 또는 결과 불명은 unknown이며 자동 재실행하지 않는다. 늦은 응답은 세대가 바뀐 초안을 덮지 않는다.
- 새 권한·의존성·데이터 수집·영속 저장·외부 전송 경로를 추가하지 않는다. 토큰과 스냅샷은 사용자 파일/ZIP에 포함하지 않는다.

## 실패 재현과 검증

최초 단위 검사는 메뉴가 없어서1RED였다. 기본 구현 후 취소/복원/원래 backward 선택/중복 실행 거절이 통과했다. 독립 검토에서 같은 노드 remove→재삽입 및 부모 제거 후 노드 구출의 P2를 찾아2RED로 재현했다. 기존 radio/multiple 패턴의 bounded MutationObserver·조상 집합·takeRecords로 보완했다. 감시는 최초 적용 전부터 시작해 적용 이벤트 중 제거가 있었으면 undo 토큰을 만들지 않고, undo 이벤트 중 제거가 있으면 토큰 소비 후 unknown으로 처리한다.
