# NAV-02: 승인된 Space 탭 작업

기준 PR29 `04373f8` + 검증 기록 `d0da218`, 브랜치 `codex-switch-nav02`. 사용자 승인: 새 탭은 Space 도우미 시작 화면, 미적용/진행 작업이 있으면 reload/close 차단, 같은 창의 마지막 탭 닫기 금지 및 돌아갈 탭 미리보기·명시 확인. 기존 PR27–29는 미병합이다.

## 동작과 경계
- 읽기·이동의 새 탭은 현재 창에 정확한 확장 `start.html`을 한 번 연다. 원래 탭은 보존한다.
- 시작 화면에서 기존 Space engine/controller와 한글 편집을 재사용한다. 이 화면에만 영문·숫자·주소 기호 그룹을 추가했다. 검색어/주소를 입력칸에 적용한 뒤 명시 검색 또는 버튼 확인으로 이동한다. Google 검색 목적지를 화면에 표시하며 입력 중 전송하지 않는다. 주소는 사용자 입력 HTTP(S), 사용자명/비밀번호 없는 URL만 허용한다.
- 시작 탭 통신은 exact URL·확장 ID·Chrome이 준 tab.id/frame0/documentId의 Port만 받는다. 일반 runtime 방송을 controller가 직접 구독하지 않는다. 양방향 RPC로 중첩 승인을 처리하며 연결 교체/끊김/탭 loading 시 취소한다. 요청 본문의 임의 tabId로 연결하지 않는다.
- 끊어진 연결은 새로운 신뢰된 Space 누름으로만 다시 연결한다. 이전 controller의 문장과 unknown 상태를 보존하며 실행을 재생하지 않는다. 설정·안전 상태가 확인되기 전 조작을 허용하지 않는다. 손상된 설정, 늦은 초기 응답, 안전 끄기 경합도 차단한다.
- 새로고침·닫기는 취소가 먼저 나오는 확인 화면과 1초 보호 이후 새 누름을 요구한다. 미완성 한글·현재 문장·다른 양식 칸/복구 문장·제안된 선택·진행 중 요청·결과 불명 상태가 있으면 막는다. unknown은 정지 후 재개한 이전 세대 요청이라도 기록하고 자동 재시도하지 않는다.
- 같은 창에 지원되는 돌아갈 탭이 없거나 마지막 탭이면 닫지 않는다. 돌아갈 후보는 같은 창의 지원 탭 중 탭 순서상 첫 번째다. 미리보기 토큰을 한 번만 소비하고 문서·URL·제목·창·창 이동 세대를 재검사한다. source 제거 전에 돌아갈 탭의 정지 응답 done도 필요하다.
- source 삭제 뒤 돌아갈 탭을 재확인·활성화한다. 돌아갈 탭은 정지 상태이며 이전 닫기 결과를 확인한 뒤 새 Space로 재개하도록 안내한다. source 삭제 뒤 실패는 unknown이며 다른 탭 대체·복원·재시도를 하지 않는다.

## 확인한 실패와 수정
1. 늦은 unknown/timeout이 정지→재개 뒤 보호에서 빠짐: controller 2RED → 요청 경계의 세대 독립 기록으로 GREEN.
2. 돌아갈 탭 pause unknown/refused를 무시함: worker 2RED → done만 허용, remove/activate0으로 GREEN.
3. 최종 승인 대기 중 돌아갈 탭이 다른 창으로 이동하면 source 창의 마지막 탭 삭제: 1RED → onDetached 세대 비교로 GREEN.
4. 시작 화면의 늦은 초기 안전 응답이 끄기를 되돌림: 실제 Chromium RED → 버전 비교로 GREEN.
5. 손상된 sync 설정에서 시작 화면 활성 유지, Port 끊김 후 Space 복구 불가: 각각 실제 Chromium RED → 설정 버전/유효성 차단과 명시 재연결로 GREEN.

## 남는 한계
실제 Windows 한글 IME·운동 사용성·실사이트·브라우저 native beforeunload/주소창/설치 UI는 미검증이다. 원 NAV-02의0키/Enter/Esc 명령판을 구현한 것으로 확대하지 않는다. Chromium 탭 API는 다중 프로세스 원자적 트랜잭션이 아니며 검사 직후의 모든 외부 창 변경을 완전히 보장하지 않는다.

기존 “문장 버리기”는 빈 초안으로 만들며 원래 입력값이 있으면 아직 미적용 차이로 취급할 수 있다. 양식 캐시는 재선택 때도 초안을 복구하므로 재선택만으로 항상 취소된다고 안내하지 않는다. 이 작업에서 기존 discard 의미나 영속 저장 구조를 바꾸지 않았다. 결과 불명 차단도 페이지의 기존 요청을 자동 재시도하거나 자동 승인해 풀지 않는다.

권한·의존성·수집/영속 저장·native 설치 확장 없음. 회사 시스템에 접근하지 않았고 검사는 허용된 합성 고정물/가로챈 검색 응답만 쓴다. merge/deploy/ZIP교체 없음.
