## 계약과 변경 이유

읽기·이동에 `앞으로`를 추가하고 기존 뒤로와 같은 초안 저장 경계를 사용한다. Chrome의 기존 tabs API `goForward`를 호출하며 새 권한이나 방문기록 수집을 추가하지 않는다. API 거절은 이동 불가 안내로 처리하고 현재 화면을 유지한다. 응답 불명은 기존 recovering·결과 확인·자동 재시도 금지로 남는다. [Chrome Tabs 공식 API](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-goForward)의 Promise 형태에 맞춰 저장소의 수동 타입 선언도 보완했다.

이동 요청은 현재 문서 세대·모드 세대·pendingActionId를 포함한다. worker가 첫 요청을 받을 때, 탭 조회 뒤, 대상 ping과 쉬기 응답 뒤 현재 명령을 확인한다. controller는 일반 실행 승인 외에 `뒤로/앞으로/열린 탭/특정 탭`의 현재 itemId까지 비교한다. 따라서 다른 종류의 현재 명령으로 옛 이동 요청을 승인하지 않는다. Space 정지·모드 변경·탭 제거·다른 문서 보고는 기존 취소 세대/문서 비교로 거절한다.

첫 승인 직후 문서별 승인 키를 동기적으로 소비해 동시 중복/완료 후 재수신이 같은 이동을 반복하지 못하게 한다. 단순 보고 갱신은 키를 지우지 않는다. 새 문서에서 승인된 첫 이동은 새 키 집합을 사용하고 탭 제거 시 정리한다. 탭 활성화는 요청 전에 source를 쉬게 하던 순서를 바꿔, 실행 대기 중 Space로 계속 정지할 수 있게 한다. 성공 뒤에는 기존 focus/visibility/활성 탭 이벤트와 완료 처리가 쉬기를 유지한다.

이미 Chrome API에 전달된 효과를 되돌리는 기능은 아니다. 승인 응답과 브라우저 실행 사이의 분산된 시스템을 원자적 트랜잭션으로 보장한다고 주장하지 않는다. worker 재시작 전체 계약, OS/native·실사이트·운동 사용성은 별도다.
