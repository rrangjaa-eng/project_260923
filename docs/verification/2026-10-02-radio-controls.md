# 일반 라디오 선택 — 계약과 검증

기준: 사용자 승인으로 병합한 PR26/main `a0738fb832bd04abdb5397c09bbef3f38279e86c`. 후속 브랜치 `codex-switch-radio-controls`이며 제품 배포나 과거 설치 ZIP 교체는 아니다. 원래 INPT-03 양식 후속의 일반 radio만 추가한다. 열린 PR8–14의 별도 계획/native 구현을 가져오지 않았다.

## 동작 계약

- 양식 목록 또는 페이지 항목에서 일반 HTML 라디오를 선택한다. 현재 상태와 같은 그룹의 다른 선택 해제를 안내하고 `이 항목 선택`으로 변경안을 만든 뒤 `선택 적용`에서 적용한다. 항목 진입·변경안 작성만으로 값은 바뀌지 않는다.
- 이미 선택된 항목에는 선택 해제와 반복 적용을 제시하지 않는다. 수신 측도 false 제안을 거절하고 이미 선택된 상태는 이벤트 없는 no-op으로 처리한다.
- 같은 Document/tree, 실제 `.form`, 비어 있지 않은 `.name`으로 그룹을 찾는다. 외부 `form=` 연결도 포함하며 다른 폼의 같은 이름은 구분한다. Shadow DOM 내부와 이름 없는 radio는 이 기능에서 제외한다.
- 최대100개 그룹이며 값4000자·라벨300자 한도를 둔다. 멤버 중 민감 판별에 걸리거나 disabled/disabled-fieldset/hidden/inert/aria-hidden/숨김 스타일이 있으면 그룹을 보수적으로 거절한다. 기존 PRIV-01 전체가 구현됐다는 뜻은 아니다.
- 멤버·폼 정체성, 값·라벨·선택 상태·필수 여부·form 속성의 snapshot을 문서 내부 메모리에만 둔다. 메시지에는 현재 항목의 상태와128-bit 불투명 토큰만 보낸다. 문서당 현재 capture 하나만 보유하고 해당 문서의 쉬기·종료·다음 capture에서 폐기한다. 새 local/session 영속 저장·외부 전송은 없다.
- HTTP에서도 동작하는 `crypto.getRandomValues`를 사용한다. 토큰을 유효 적용 직전에 동기 소비하며 사이트 이벤트가 선택을 원복해도 같은 토큰을 재사용하지 못한다.
- 제거 기록과 이전 조상 집합을 검사해 같은 멤버/폼의 제거→재삽입도 거절한다. 적용 직전 `takeRecords`를 처리한다. 적용 뒤 전체 그룹 구성이 그대로이고 대상만 선택됐는지 다시 확인한다. 사이트가 바꾸면 성공으로 보고하거나 자동 재시도하지 않는다.
- native checked setter 뒤 input/change 각1회만 전달한다. 일반 press의 radio 클릭 우회도 차단한다. 도우미가 click/requestSubmit을 호출하지 않는다는 계약이며 사이트 자신의 이벤트 처리 부작용을 되돌리는 기능은 아니다.
- 명시 쉬기·자동 쉼은 변경안과 capture를 버리고 양식 목록으로 돌아간다. 새 Space는 재개만 하며 필드를 다시 골라야 새 변경안을 만들 수 있다. unknown 응답은 기존 불확실성 안내와 정지를 유지한다. 원래 글쓰기 초안은 보존한다.

## 실패 재현과 수정

초기 기능 부재7RED(기존3pass), 추가 경계 검사8RED를 확인했다. 그룹 form 속성 변경은 DOM 라이브러리의 `.form` 해석 차이를 포함해 실제 속성 snapshot도 비교했고 외부 form 연결은 실제 Chromium에서도 검사한다. 제거된 조상에서 같은 input을 구출한 경계1RED, 쉬기 후 새 선택2RED, HTTP randomUUID 미지원1RED, 미지원 metadata·disabled fieldset2RED를 각각 확인해 보완했다. 단언·retry 정책은 완화하지 않았다.

독립 검토에서 HTTP randomUUID P2를 수정했고 재검토의 추가P1/P2는 없었다. 수신 경계·폼 그룹 정체성·민감 형제·클릭 우회·승인 재사용을 security review 범위로 삼았다. 전제품 보안 인증이나 사이트 전체 지원을 뜻하지 않는다.

## 실행 결과

최종 로컬 type/lint/production build, unit331/331(37파일), 새radio4+재적용2=6/6(2.4분), 자동UI101/101(4.0분,0fail/skip/flaky)이 통과했다. 360/768/1280px의 변경안 미리보기와 버튼 치수도 새radio 검사에 포함됐다. 새 라디오의 실브라우저 검사는 최상위 HTTP 문서이며 프레임 안 라디오는 별도 미검증이다. CI92의 전체358건36.3분에 새4건을 더하므로 E2E45분/job50분 한도로 실행 여유만 늘렸고 검사·단언·retry정책은 유지했다.

최종 실행 수치·소스 해시·CI는 `radio-controls-results.json` 및 WORK-STATUS에 기록한다. 선행 부분검사와 최종 소스를 구분한다. 자동 화면 검토는 기존 토큰·크기·서체·포커스 검사와 새 흐름360/768/1280px DOM 치수를 사용하며 실제 손 움직임의 편안함을 측정하지 않는다.

실제 Windows 한국어 IME·운동 사용성·실사이트, custom/multiple 위젯·임의 사이트 오류 원문·최근값 자동수집·native 파일 전달은 미완료다. 배포·설치본 교체는 별도 승인 대상이다.
