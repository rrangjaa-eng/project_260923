# NAV-02 남은 범위와 구현 전 결정

이 문서는 iframe 검증 이정표 당시의 범위 판단이다. 이후 사용자가 세 추천 정책에 “네가 추천하는대로 해”라고 답했고 구현을 명시적으로 위임했다. 현재 후속은 [NAV-02 구현·검증 기록](2026-10-03-nav02.md)을 따른다. 병합·배포 승인은 포함하지 않는다. 아래 표와 미착수 문장은 당시 기록이다.

## 현재 코드와 원 요구

`.planning/REQUIREMENTS.md` NAV-02는 0키 명령판의 뒤로·앞으로·새로고침·탭 닫기·새 탭, 큰 번호 카드, 첫 화면의 키 안내(알림 Enter/Esc 포함)를 요구한다. 현재 승인된 단일 스위치 방식은 Space 순환 선택이다.

| 항목 | 현재 상태 |
|---|---|
| 뒤로·앞으로 | Space 읽기·이동에서 구현. 승인/취소·중복 실행 방지 포함 |
| 열린 탭 목록·전환 | 지원하는 HTTP(S) 탭의 목록과 활성화 구현 |
| 새로고침 | Navigation schema·worker·Space 메뉴에 없음 |
| 새 탭 생성 | Navigation schema·worker·Space 메뉴에 없음. 열린 탭 전환과 구분 |
| 탭 닫기 | Navigation schema·worker·Space 메뉴에 없음 |
| 첫 화면 키 안내 | 현재 Space 시작·선택·정지·재개 상태 안내가 있음. 원 요구의0키 명령판·Enter/Esc 안내 전체가 구현됐다는 뜻은 아님 |

근거는 `src/shared/switch-messages.ts` Navigation(`tabs/back/forward/activate`), `src/worker/switch-relay.ts`, `src/page/input/switch-controller.ts` 읽기·이동 메뉴, `src/page/overlay/switch-panel.ts` 상태 안내다. 원 `.planning` 체크박스는 유지한다. 더블클릭·고정 번호 등 다른 NAV 요구를 NAV-02 완료 조건으로 추가하지 않는다.

## 사용자에게 필요한 제품 결정

1. **새 탭의 시작점:** 도우미가 조작 가능한 시작 화면을 새로 마련할지, 정해진 검색/홈 페이지를 열지 정해야 한다. 브라우저 자체 새 탭/주소창을 열었다고 그 화면을 Space만으로 조작할 수 있다고 할 수 없다. 주소 입력을 포함한다면 입력·허용 URL 범위를 별도 증분으로 정의한다.
2. **새로고침·닫기 때 초안 처리:** 도우미에 미적용 초안이나 미확정 실행이 있으면 우선 실행을 막는 정책을 권장한다. 버리기/복구까지 원한다면 무엇을 얼마나 유지할지 먼저 결정해야 한다. 이번 권한을 새 사이트 값 수집이나 영속 저장 확대에 사용하지 않는다.
3. **마지막 탭 닫기:** 마지막 탭은 닫지 않는 정책을 권장한다. 여러 탭 중 하나를 닫은 뒤 돌아갈 지원 탭을 어떻게 고를지도 명시한다. 마지막 탭을 닫아 브라우저가 끝나는 동작은 묵시적으로 채택하지 않는다.

기존 Space 취소 우선·보호 후 새 누름으로 명시 확인·문서/모드/실행ID 재검증·unknown 자동 재시도 금지는 유지하는 구현 원칙이다. 이를 새 승인 질문으로 되돌리지 않는다. 원0키/Enter/Esc 명령판 전체를 별도로 구현할지는 현재 Space 우선 범위와 구분한다.

## 클라우드와 실제 기기의 경계

위 결정 후에는 합성 탭·페이지에서 정상/취소/초안/탭 이동·닫힘 경합을 자동검사하는 작은 증분으로 진행할 수 있다. 브라우저 native beforeunload·주소창·창 종료와 실제 Windows 프로필의 입력/초점 안내는 별도 검증 대상이다. 새 권한이나 큰 구조 변경이 필요해지면 구현을 확대하기 전에 결정을 요청한다.

아직 NAV-02의 위 미구현 기능은 착수하지 않았다. 현재 이정표는 iframe 안 기존 양식 기능의 검증과 재현 결함 수정이다.
