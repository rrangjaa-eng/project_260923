# NAV-05 현재 문서의 명시적 번호 고정 설정

## 범위와 기준

사용자의 계속 진행 지시에 따라 PR34 `3454494ac6a532a1b82b1c83b07383726a2b862a`에서 `codex-switch-pin-settings`를 분기했다. 원 설계6.2·6.8·7장의 사이트별 고정 번호·확실한 요소 찾기·기존 동기화 설정을 연결한다. PR31–34/main/기존 ZIP을 보존하며 merge/deploy/ZIP 교체는 하지 않는다.

이번 최소 범위는 최상위 HTTP(S) 문서의 비민감 일반 native `button[type=button]`·HTTP(S) 링크를 Space로 고정/교체/해제하는1–9 슬롯이다. 입력칸·제출/초기화 버튼·위험 대상·편집 가능한 복합 요소/외부 라벨·iframe·custom 위젯은 새 고정 대상에서 제외한다. 고정 목록에서 항목을 선택하면 기존 `chooseTarget` 승인·취소·press 경로로 실행한다. 고정 설정 중 사이트 클릭은 발생하지 않는다.

## 승인·저장 계약

- 읽기·이동 → 번호 고정 설정 → 번호 → 대상 선택 → 현재/새 이름 전체 페이지 미리보기 → 취소 우선·1초 보호 → 명시 확인. 번호당 하나, 대상당 하나이며 다른 번호의 고정을 조용히 이동하지 않는다. 먼저 해제한 뒤 새 번호에 고정한다.
- `site:<origin>.pins`·기존 Fingerprint 형식·`chrome.storage.sync`와 단일 storage writer만 사용한다. 입력값·최근값·undo 이력·새 권한·새 의존성을 추가하지 않는다. 대상 이름/위치를 사이트 고정 설정에 저장한다는 안내를 제공한다. 새 descriptor는 각 문자열1000자·전체6KB 안으로 제한하며 최종 site 항목8KB 한도도 검사한다.
- worker가 sender의 최상위 사이트·문서·취소 세대를 확인하고, 현재 `pin-commit` 명령과 정확히 같은 제안인지 content에 재확인한다. quota 대기 뒤 최신 설정을 재읽어 expected pins와 비교한다. 작업 중 관찰한 sync 변경은 마지막 승인 뒤에도 거절한다. disabled와 손상 원본을 자동 복구/덮어쓰지 않는다. 여러 PC 사이 원자적 compare-and-swap을 보장한다고 주장하지 않는다.
- 대상 capture는 실제 DOM 노드·identity·일반 요소 조건·제거 이력을 묶는다. 같은 노드 제거/재삽입도 무효다. DOM identity/유일성/eligible 변경과 scroll·resize로 인한 화면 밖 이동은 기존 취소 세대로 전달해, 이미 처리됐지만 지연된 최종 승인 응답으로 저장되지 않게 한다. 쉬기/종료·늦은 승인·unknown은 자동 저장 재실행으로 이어지지 않는다. 쓰기 응답이 불명확하면 unknown이며 저장 결과를 확인하도록 한다.
- 고정 항목을 실행할 때도 설정 snapshot과 DOM capture를 확인하며, 확인 화면/최종 승인 대기 중 sync 변경은 실행 capability를 무효화한다. 변경된 일반 요소로 대체 실행하지 않는다.
- 기존 번호표와 Space 고정 목록 모두 공통 resolver를 사용한다. 알려진 id/name 충돌을 거절하고, 둘 다 없으면 같은 DOM 경로를 요구하며 기존 복수 식별 점수와 유일성도 확인한다. Space 고정 목록의 없는/모호한 번호를 다른 일반 요소로 채우지 않는다. 기존 일반 번호표의 미고정 번호 채우기·9개씩 넘기기 정책은 유지한다.

## 실패 재현과 검사 진행

새 설정 변경 동작1RED, 기존 번호표의 모호한 첫 후보 선택1RED, storage 구현3RED, worker 메시지 연결1RED, controller 메뉴1RED를 확인했다. 독립 검토의4개 P2(마지막 승인 대기 중 sync 덮어쓰기, 고정 실행 확인 중 설정 변경, 강한 식별자 충돌, 긴 이름 끝부분 숨김)를 각각 실패로 재현하고 보완했다. 관련74/74·전체unit465/465(47파일)·type/lint 통과 후 quota/disabled 검사를 추가했다.

첫 Chromium6건은5pass/1fail이었다. 실패는 테스트가1초 확인 보호 안에서 취소를 눌러 무시된 뒤 없는 다음 화면을 기다린 것이며, 제품 보호는 유지하고 테스트에1100ms의 명시 대기를 넣었다. 전체 이름 페이지·설정 변경 후 고정 실행 거절을 포함한 후속8건은8/8(4.0분) 통과했다. 추가 리뷰의 최종 승인 응답 후 동일 노드 제거/재삽입1건은 실제 Chromium RED→GREEN(24.4초)으로 확인했다. scroll/resize 무효화2unit RED와 외부 편집 라벨의 값 혼입2unit RED도 보완했다. 이들을 포함한 최종14건과 회귀·UI를 순차 실행한다. 최종 전체 unit·브라우저·UI·독립 재검토·CI 결과는 종료 후 추가한다.

## 남은 항목

이번 범위를 NAV-05 전체 명령판/플랫폼 기능 완료로 확대하지 않는다. iframe 고정, custom/native 복합 컨트롤 고정, 명시적 더블클릭 NAV-06은 후속이다. 더블클릭을 추정하거나 일반 클릭을 두 번 실행하지 않는다. 실제 Windows 한국어 IME·운동 사용성·실사이트·native UI 및 실제 두 PC 동기화는 미검증이다. INPT-01/PRIV-01 전체·최근값 수집·native/C# 연결은 별도 계약 없이 확대하지 않는다.

## 독립 최종 읽기 검토

최종 DOM 무효화·scroll/resize listener 정리·외부 편집 라벨 제외까지 읽기 재검토했고 추가 actionable P1/P2가 없었다. 이는 실제 브라우저 검사 결과와 구분한다. 대상 capture는 제안/실행 중에만 유지하며 종료·취소·dispose 때 observer와 viewport listener를 해제한다.
