# 미완성 한글의 적용·검색·문구 저장 보호

## 범위와 완료 기준

기준은 draft PR32 `97a9a96c630834ae408d21bb0131cee8f31357a2`다. PR31·32의 제품 HEAD를 유지하고 `codex-switch-compose-commit`에서 분리한다. 사용자는 다음 실제 미구현 기능 또는 재현되는 결함의 구현·독립 검토·검증·commit/push·draft PR·전체 CI를 계속하도록 요청했다. 새 main 병합·배포·ZIP 교체는 승인되지 않았다.

최신 완료 기준과 코드를 대조했다. native 단일/multiple select·checkbox·radio, generic validity, 변경값 재적용 확인, 프레임 컨트롤, 탭 작업, 일반 영문·숫자 입력은 이미 구현됐다. 기존 조합 보호는 ASCII·초안 편집 및 비교/문구 교체에는 있지만 적용·검색·새 문구 저장에는 없었다. 이 세 경로는 화면의 미완성 한글을 제외한 draft.text만 외부 효과에 사용했다. 완료된 앞부분을 잘못 적용·검색·저장할 수 있는 기존 결함으로 범위를 한정한다.

- 미완성 초성 또는 중성이 있으면 적용·검색·새 문구 저장 요청을 보내지 않고 “한글 조합을 마치거나 취소하세요”로 안내한다.
- 초안·조합·선택 위치·기존 필드·문구 목록을 보존한다. 자동 확정·자동 취소하지 않는다.
- 조합 완료 또는 명시 취소 뒤 사용자의 새 선택으로 기존 적용·검색·저장이 정상 실행된다.
- 기존 공통 guard에 명령 세 개만 추가한다. 새 권한·외부 수집·영속 저장 정책·메시지 schema·UI 토큰은 바꾸지 않는다.
- 완료 기준: 실제 실패 재현, 위 부정/긍정 동작 검사, 독립 검토, type/lint/unit·관련 Chromium·기존 편집기·자동 UI 및 최종 HEAD 전체 CI 통과.

## 다음 잔여 범위

NAV-04의 적용 후 실제 필드 되돌리기는 현재 초안 undo와 다르며 미구현이다. 구현 전 되돌릴 스냅샷의 수명, 사이트가 값을 다시 바꿨을 때 거절, 양식/프레임 경계를 별도 범위로 정해야 한다. 기존 “문장 버리기”가 원래 값으로 되돌리는 동작이라는 뜻은 아니다.
