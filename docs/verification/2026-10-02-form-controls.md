# 선택 목록·체크 항목·입력 오류 안내 후속

기준: PR #19 head `930ab0fafe7a446ac1d0c296d8e5b72c035e7638`. 후속 로컬 브랜치 `codex/form-controls-errors`, 보존 원격 브랜치 `codex-form-controls-errors`. 기존 PR #19를 수정하거나 중복 생성하지 않는다. 사용자 ‘작업 이어가’와 이전 선택·체크·오류 안내 개발 지시를 이어 수행한다.

## 구현 범위

기존 양식 한 장 보기와 페이지 항목에서 일반 native 단일 select와 checkbox를 선택한다. 목록 보고는 칸 이름과 지원 여부만 전송하며, 선택한 칸에서만 현재 상태와 선택 항목을 읽는다. select는 1~100개 선택 항목, 항목 이름 300자 이하, 비교 스냅샷 64000자 이하를 지원한다. checkbox는 제출값 4000자 이하와 확정된 체크 상태만 지원한다. 민감·비활성 칸, multiple select, 빈/100개 초과 목록, indeterminate checkbox는 적용을 지원하지 않는다. radio와 custom widget은 이번 양식 확장 범위 밖이다.

사용자가 변경안을 선택해도 원래 칸은 바뀌지 않는다. **선택값 적용** 또는 **체크 상태 적용**만 DOM 상태를 변경하며 input/change를 한 번씩 발생시킨다. 변경 없는 적용은 이벤트를 발생시키지 않는다. 클릭·자동 제출을 호출하지 않으며 checkbox의 일반 press fallback도 막는다. 실제 사이트가 input/change 처리에서 일으키는 부작용까지 보장하지는 않는다.

적용 전에 기존 문서/프레임/요소 identity와 현재 상태를 검사한다. select의 항목 값·이름·disabled/optgroup disabled와 선택 위치, checkbox의 제출값과 checked가 capture 이후 바뀌면 거절한다. 적용 중 사이트 핸들러가 의미를 바꾼 경우도 성공으로 알리지 않는다. 자동 쉬기·명시 쉬기 때 미적용 변경안과 적용 카드를 폐기한다. 결과 불명 응답은 목록으로 돌아와 쉬고 결과 확인을 안내하며 자동 재시도하지 않는다. 늦은 capture는 모드 세대 검사로 현재 화면을 바꾸지 않는다.

텍스트 칸의 초안·커서·한글 보존과 진입 전 화면 복귀는 기존 버퍼를 재사용한다. select/checkbox 변경안은 메모리에만 두며 칸을 떠나면 폐기한다. **입력 오류 읽기**는 선택한 지원 칸의 validity/aria-invalid를 조회한다. checkValidity/reportValidity/requestSubmit은 호출하지 않는다. 사이트의 임의 validationMessage나 aria 설명 본문에는 값이 포함될 수 있으므로 일반적인 한국어 상태와 원래 화면 확인 안내를 사용한다. 사이트별 오류 문장을 그대로 읽는 기능은 구현하지 않았다.

## 테스트와 검토

- 새 페이지 행동 단위 8개: 선택 metadata 비노출·명시 capture, 선택 적용/input/change/click0/submit0, stale/disabled/unsupported 거절, checkbox 상태, validity/invalid0/임의 메시지 비노출, stale checkbox 제출값·지원 대상 제한, checkbox press 차단, 적용 중 checkbox 의미 변경.
- 새 실제 controller 단위 3개: 자동 쉬기 뒤 변경안 폐기, unknown 적용 뒤 결과 안내·쉬기, 긴 현재값·변경안 전체 읽기. 화면/Chrome 전송만 대체하고 실제 controller/DOM/행동 코드를 실행한다.
- 실제 확장 Space E2E 6개: 명시 적용·오류 읽기, stale/쉬기·복귀·storage 비노출, 페이지 항목 진입·쪽 이동·3 viewport, 자동 쉬기 취소, 실행 후 응답 유실·재실행0, 늦은 선택 응답 폐기.
- 독립 검토: gpt-6.1-sol/high. 자동 쉬기 변경안 잔류와 unknown 안내 누락을 RED2로 재현 후 GREEN2 확인. checkbox signature/press fallback/적용 중 의미 변경도 확인했다. 최신 소스로 확인된 미해결 P1/P2 없음. 독립 /tmp 경계 검사 10/10은 저장소 단위8과 겹치므로 추가 제품 시험 수로 합산하지 않는다.

현재 선택과 변경안은 각각 24 grapheme 단위 읽기쪽으로 표시하고 Space로 이전/다음 쪽을 고른다. 긴 항목 선택 카드는 원래 항목 번호와 짧은 이름을 표시하며, 원문은 미리보기에서 끝까지 읽는다. 360px에서 공백 없는 영문이 카드를 넓히는 문제를 RED로 재현하고 min-width/줄바꿈 보완 뒤 실제 브라우저 경계 검사를 통과했다.

검증은 단계별로 기록한다. 전체 단위 262/262, 최종 타입·린트·생산 빌드 통과. 전체 브라우저 341/341(29.7분, 실패·스킵·불안정 0)은 읽기쪽·줄바꿈 최종 보완 **전** 빌드를 검사했다. 보완 후 최신 빌드의 기본 화면 101/101(3.2분, 실패·스킵·불안정 0)을 다시 검사했다. 같은 최신 생산 빌드의 최종 선택 흐름 6/6(3.8분, 실패·스킵·불안정 0)도 통과했다. 360/768/1280px 화면과 긴 원문 전체 읽기를 검사하고 실제 360px 이미지에서 마지막 읽기쪽을 확인했다. 따라서 전체 341개를 최종 소스의 전체 재검사로 표현하지 않는다. 단계별 source SHA-256·통계는 [구조화 결과](form-controls-results.json)에 보존한다.

CI는 측정된 전체 실행 29.7분에 맞춰 E2E 30→35분, job 35→40분으로 조정했다. 시험을 생략하거나 권한을 늘리지 않았으며 YAML 구문 검사 통과. 원격 CI 실행 여부는 로컬 검증과 구분한다.

실제 Windows IME·손 떨림 사용성·실제 사이트·모든 브라우저 설치는 미검증이다. 전체 INPT-03/PRIV-01 또는 프로젝트 페이즈를 완료 처리하지 않는다. 최근값 자동수집·외부 전송·새 권한·OS 연결·merge/deploy를 추가하지 않았다. 기존 downloads ZIP을 보존한다.
