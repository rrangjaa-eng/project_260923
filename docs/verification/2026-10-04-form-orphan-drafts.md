# 연결할 입력칸이 없어진 초안

PR30 후속 [리뷰](https://github.com/rrangjaa-eng/project_260923/pull/30#discussion_r4170786719)의 P2를 수정한다. 필드 제거 또는 identity 변경 후 새 목록을 읽으면 `FormDrafts`에는 미적용 초안이 남지만 화면에서 접근할 수 없어 새로고침·탭 닫기가 계속 막혔다. 기존 CI109에는 이 경계 시험이 없었다.

## 변경 계약

- 보관된 미적용 초안 중 현재 양식 목록의 정확한 문서·프레임·항목·identity와 연결되지 않는 문장을 `보관 문장`에서 읽는다. 지원 필드가 0개여도 접근할 수 있다.
- 문장·미완성 한글을 기존 페이지형 미리보기로 표시한다. 보관 문장을 읽기만 해서는 편집 workspace에 복사하거나 사이트에 적용하지 않는다.
- `이 보관 문장 버리기` → 취소 우선 확인 → 1초 보호 → 명시 확인으로 선택 항목 하나만 버린다. 자동 삭제·자동 재연결·새 영구 저장은 없다.
- 최종 확인에서 현재 목록을 다시 읽는다. 항목 revision, 확인 상태, 모드 세대와 접근 불가능 상태를 다시 검사한다. 최종 확인 전에 관측한 입력칸 재등장·초안 변경·쉬기·늦은 응답에는 삭제하지 않는다. 아직 전달되지 않은 iframe 알림까지 포함한 분산 DOM 원자성을 보장하지 않는다.
- 삭제 뒤 원래 workspace로 복귀한다. 양식 목록에 남아 있던 마지막 필드 복사본을 연결 해제 시 복구 초안으로 다시 만드는 것을 방지한다. 다른 보관 초안과 원래 workspace·독립 복구 초안은 남는다. 따라서 한 항목을 버렸다는 이유만으로 모든 이동이 허용되지는 않는다.
- 기존 일반 `문장 버리기` 의미와 적용/되돌리기 계약은 바꾸지 않는다. 보관 문장의 다른 칸으로 전송·복사·영구 보존은 이번 범위에 없다.

## 독립 검토 후 추가 경계

- 최종 목록 응답을 지연시킨 사이 원래 필드가 돌아오는 경우를 별도 RED로 확인했다. 현재 프레임에서는 report metadata signature가 바뀐 세대를 비교하고, 마지막에 collector를 동기 refresh하여 다음 애니메이션 프레임까지 기다리는 DOM 변화도 확인한다. 단순 화면 렌더 횟수는 변경으로 세지 않는다.
- 다른 iframe의 실제 report 변경은 기존 `switch/refresh` 알림의 선택적 boolean `changed`로 전달한다. relay의 document/path/items가 같은 반복 보고는 false, 실제 변경은 true다. 알림 자체와 기존 refreshAvailability는 유지하고, true일 때 보관 삭제 확인의 변경 세대만 무효화한다.
- top 지연 목록 1RED, 원격 변경 알림 1RED, relay 변경 구분 5RED/기존·발신자 대조13GREEN을 확인했다. 구현 후 관련 core/controller/relay 77/77 통과. 원래 제품 테스트 assertion 삭제·완화는 없다. 새 재등장 시험은 보존 문장·원래 사이트 값 단언을 유지하고 거절 후 명시 목록 새로읽기 경로만 추가했다.
- 보안 검토 범위는 메모리 초안, extension 메시지 발신자와 relay 보고 입력, 명시 삭제 권한이다. 기존 runtime.id 검사와 메시지 schema를 유지하며 changed는 boolean만 허용한다. 위조 발신자의 보고는 알림·저장된 report를 변경하지 않는 부정 시험을 포함한다. 새 권한·사이트 쓰기·외부 전송은 없다. 전체 제품 보안 또는 모든 분산 메시지 전달의 원자성을 인증하지 않는다.


독립 최종 검토: 새 삭제 권한은 항목 revision·확인 상태·현재 모드·실제 보고 변경 세대에 묶이고, 성공 exitForm은 마지막 필드 복사본의 재복구를 막는다. relay의 changed boolean은 거절 범위만 넓히며 기존 발신자 검증과 알림 전송을 유지한다. 현재 변경 범위에서 추가 actionable P1/P2는 발견하지 않았다. 이는 알려진 모든 프로젝트 결함이 없다는 뜻이 아니며 실제 브라우저 결과·CI는 별도 확인한다.

## PR39 추가 검토: 목록 조회 불명과 부재 구분

원격 HEAD `fd66053`의 독립 검토 후보를 실제 Chromium에서 RED로 재현했다. 자식 iframe의 입력칸 identity를 먼저 복구하고 changed 알림 전달까지 마친 뒤, 최종 frame-check만 unknown으로 응답하게 하면 relay가 프레임을 목록에서 조용히 제외하여 보관 초안이 삭제됐다. 이전의 변경 세대 보호만으로는 최종 조회 자체의 불명을 구분하지 못했다.

후속 수정은 `switch/list`에 `uncertainFrames`를 함께 전달한다. 가시성 unknown/비정상 응답·예외, 부모 보고 부재, 조회 도중 report 일관성 상실은 해당 프레임을 불명으로 기록한다. 명시적 숨김 거절과 구분하며 기존 가시성/실행 승인의 boolean 결과는 바꾸지 않는다. controller는 선택 초안 프레임이 불명이거나 이 신뢰도 필드 자체가 빠지거나 손상되면 초안을 보존한다. 관련 없는 다른 프레임의 불명은 선택 초안의 명시 삭제를 막지 않는다.

이 결함 때문에 CI112의 이전 HEAD 결과를 후속 수정 검증으로 재사용하지 않는다. 기존 제품 테스트 단언을 약화하지 않았고, 기존 목록 응답 단언에는 새 불명 프레임 배열의 기대값만 추가했다. 새 Chromium 부정 시험은 실패했던 초안 표시·보존 안내·사이트 원값 단언을 그대로 유지한다. 후속 최종 결과는 아래에 추가한다.
