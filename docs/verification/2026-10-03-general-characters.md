# 일반 입력칸의 Space 영문·숫자 작성

## 선택 이유와 범위

기준 main `9394b0146f9ba169f57e47ce3274bdff57b74dfe`, 병합 후 CI99 unit397/browser403 성공. PR27–30은 이미 merged다. 기존 잔여 양식·탐색 문서의 iframe/NAV-02 작업은 PR29/30으로 진행됐으므로 그대로 다시 수행하지 않는다.

다음 작은 기능은 일반 입력칸과 양식에서 영문·숫자·주소 기호를 직접 작성하는 것이다. text/search/email/tel/url 및 textarea를 이미 지원하지만 ASCII 선택은 시작 화면에만 있어 일반 칸에서는 해당 문자를 Space로 직접 만들 수 없었다. 열린 PR16–25는 기존 스택이며 이 후속과 겹치는 새 PR은 없다. PR8–14 및 다른 브랜치는 건드리지 않는다.

사용자가 남은 구현·검토·commit/push/draft PR·최종 CI를 이어가도록 위임했다. 기존 문자 선택을 일반 editor에 연결하는 bounded 변경이며 새 제품 정책이나 권한/수집/저장 구조를 만들지 않는다. brainstorming의 짧은 설계를 보고하고 해당 실행 승인 범위에서 진행한다. 새 PR 병합·배포·ZIP 교체는 승인에 포함되지 않는다.

## 동작 계약

- 일반 글쓰기/양식의 “영문·숫자 쓰기”에서 기존 6개씩 문자 묶음을 Space로 선택한다. 시작 화면의 기존 “영문·주소 쓰기”는 유지한다.
- 문자 선택은 초안의 선택 범위를 교체한다. 기존 커서·되돌리기·명시 적용 경로를 사용하며 선택만으로 DOM 값을 바꾸거나 제출하지 않는다.
- 양식의 다른 칸으로 이동해도 각 초안이 남고 명시 적용한 칸만 바뀐다.
- 미완성 한글이 있으면 ASCII 메뉴/삽입을 거절하고 “한글 조합을 마치거나 취소하세요”로 안내한다. 조합·커서를 자동 확정/취소하지 않는다. 한글을 마친 뒤 다음 문자를 고른다. 공용 시작 화면도 같은 경계를 적용한다.
- 민감칸 분류와 적용 시 재검증은 그대로다. 새 값 수집·보호 저장·외부 전송·권한·native 연결은 추가하지 않는다. 문자 draft는 기존 탭 세션 경로, 양식 draft는 기존 메모리 경로다.

## 디자인·보안 검토 범위

기존 switch-panel과 토큰을 사용하며 새 시각 토큰/컴포넌트는 없다. 일반 메뉴 이름만 용도에 맞추고, 360/768/1280px 문자 목록의 패널 경계·표적56px·글자18px을 DOM으로 검사한다. 자동UI 결과와 실제 운동 사용성은 구분한다.

변경은 고정 문자 선택→기존 draft 편집 경로다. 외부 입력 파서·sender 승인·민감칸 capture/apply·영속 저장 구조·권한 설정은 변경하지 않는다. DOM 렌더링은 기존 textContent 경로다. 합성 민감 값이 타입 변경 후 화면/저장에 들어가지 않고 input/change/submit0인지 브라우저에서 검사한다. 전체 사이트 개인정보 판별을 보장한다는 의미는 아니다.

실제 Windows IME·운동 사용성·실사이트·contenteditable 직접 삽입·OS/native UI는 이 작업의 검증 범위 밖이다. 기존 문장 버리기 의미나 NAV-04의 적용 후 실제 필드 되돌리기는 변경하지 않는다.
