# Space로 스크롤 영역 선택

기준은 PR24 `461d431c3a7dffee3b0dd8c13d546380453e6bfc`이며 CI90의 단위296/E2E352 success를 먼저 확인했다. 원격과 작업트리에서 중복 작업이 없음을 확인하고 `codex-switch-scroll-regions`를 만들었다. 기존 CI 결과 기록 `be8cc5a`는 문서만 cherry-pick해 보존했다. PR24와 설치 ZIP은 변경하지 않는다.

## 최소 동작 계약

기존 읽기·이동과 공통 Space 상태 엔진을 확장한다. 진입 시 제목에 `페이지 전체`를 명시한다. `세로 스크롤 영역 선택`은 현재 화면에 걸쳐 있는 최상위 문서의 일반 세로 overflow 영역과 페이지 전체를 수집한다. 선택 자체는 스크롤하지 않는다. 이름·번호·기존 강조 테두리로 대상을 확인하고, 취소가 첫 항목이며 5개씩 이전/다음 영역으로 이동한다. 영역 새로 읽기도 명시적 선택이다. 이름은 aria-label에서 최대80자만 사용하고 본문·입력값·프레임 내부는 읽거나 저장하지 않는다. input/textarea/select/contenteditable 안쪽과 도우미 자신의 화면은 스크롤 영역 후보에서 제외한다.

선택 뒤 제목과 강조 테두리를 유지하며 한 화면 아래/위는 선택 영역 높이의80%, 자동 이동은 기존2px/30ms를 선택 영역에만 적용한다. 기존 페이지 전체는 화면 높이80%다. `scrollTo`의 instant 동작으로 사이트의 smooth CSS에 남은 이동이 Space 정지 후 이어지지 않도록 한다. 끝이나 실제 위치 변화가 없으면 자동 이동을 종료한다. 영역 스크롤을 조상이나 페이지로 대신 넘기지 않는다.

자동 이동 중 신뢰할 수 있는 새 Space keydown은 입력 보호 간격과 관계없이 즉시 정지에만 쓴다. 같은 keyup은 선택·재개·클릭에 쓰지 않는다. 반복·조합·수정키는 기존 입력 정책을 유지한다. 정지 후 첫 항목은 상위로이며 읽기 메뉴에서 루트로 나갈 수 있다. 선택 목록 취소는 기존 선택을 보존하고, 읽기를 나갔다 새로 들어오면 제목이 명시된 페이지 전체로 시작한다.

DOM 참조·문서/body·URL·이름/역할·제거 세대를 검사한다. 제거 뒤 같은 노드를 다시 삽입해도 옛 선택을 거절한다. 교체·숨김·inert·aria-hidden·overflow 해제·문서 변화는 실행 전에 거절하고 자동 이동 중에도 매 단계 확인한다. 문서 전체도 body/root의 가시성과 스크롤 잠금을 검사한다. 무효 대상은 페이지 전체로 대체하지 않고 다시 선택하도록 안내한다. 쉬기·blur·탭 숨김·pagehide·기존 프레임 변경·도우미 끄기·해제는 타이머를 멈추며 재개 한 번은 자동 이동을 다시 시작하지 않는다.

- 최초 단위3RED: 영역 선택 부재2건, 자동 이동 시작 직후 입력 보호 안의 Space 정지 실패1건. 구현 뒤3GREEN.
- 경계 확대: 기존12GREEN/페이지 스크롤 잠금1RED(0기대614.4이동). body/root 잠금·가시성 검사 추가 뒤13GREEN.
- 독립 검토가 발견한 opacity0/visibility collapse2RED와 실제 이동 없음의 자동 반복1RED. 검사·이동 결과 확인 추가 후 새 단위17/17.
- 단위는 선택 영역만 이동, 선택 시 이동0, 제거·같은 노드 재삽입·교체, 숨김·overflow 변경·이름 변경, Space 정지·keyup 무동작·반복/조합/수정키, 쉬기·pagehide·재개, 끝·불가, 취소·복귀, 목록 페이지, 미지원 후보 제외를 검사한다.
- 첫 실제 브라우저6개는5pass/1fail(1.9분). 360px 긴 공백 없는 이름에서 panel scrollWidth846 > clientWidth322를 확인했다. 기존 제목 스타일에 overflow-wrap:anywhere만 추가하고 새 색·토큰·레이아웃은 도입하지 않았다. 해당 단언은 유지하고 선택 항목의 목록 내부 위치 단언도 추가했다.
- gpt-6.1-sol/high 독립 읽기 검토: 가시성·실제 이동 없음·긴 제목 P2 수정 후 지원 범위 안의 추가 P1/P2 없음. 검토자는 시험을 실행하지 않았다.

최종 실제 실행 수치와 소스 해시는 [구조화 결과](scroll-regions-results.json)에 기록한다. 첫 브라우저 결과를 최종 소스 전체 통과로 합산하지 않는다. 기본 자동 UI 검사와 전체 CI도 각각 실제 완료 결과로 구분한다.
